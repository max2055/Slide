AI 工作空间与监控配置输入负担排查

日期：2026-10-22。范围：AI 工作空间首版故障排查与恢复闭环，以及相邻监控配置原型。依据为当前源码、V2 原型和设计稿静态核查；本轮未运行浏览器业务验收、未修改产品代码。以下调整属于拟建设要求。

V4 范围更新（用户已确认）：遵循当前版本项目范围，只做中文浅色桌面，1440×900 为主，1366×768/1920×1080 检查；不投入移动/平板、深色、听读顺序、完整无障碍及其他范围排除专项。保留基础标签、键盘、焦点和错误状态。纳管对象无 Agent，人工建设原生模板，不做 Zabbix 兼容；AI Agent 运行时保持现状。事件中心移除重复规则配置，证据引用当时规则快照。

1. 已确认的设计原则

用户要求：避免过多手工输入，能选择/筛选就选择/筛选，系统能够生成的内容不要求用户输入。

处理顺序为：已有上下文自动带入 → 从权威记录自动读取 → 提供默认值或可复核草案 → 搜索/筛选/选择 → 只对确实缺失的内容要求补充。不能把所有文本框机械换成下拉框，也不能用没有依据的自动填充隐藏不确定性。

系统自动生成标识、标题、时间线、版本引用和报告结构；用户确认范围、判断与操作意图。自动填充不意味着自动发起模型分析、扩大范围、批准变更或宣告恢复。

补充：现有资源名称选择、类型/状态筛选、计划列表、审批发现、验证参数与执行记录列表均应复用。不是从零重做，也不把已经自动完成的内容列为待开发。

3. 建议的最少输入路径

从事件进入

事件“连接使用率过高” → 自动带入标题、事实目标、资源、事件引用和窗口 → 用户核对上下文 → 点击“开始只读排查”。

目标：来源信息完整时，启动前必须填写的自由文本为 0 项。用户仍能编辑目标、对象和时间；确认不会立即执行变更。

从资源直接进入

已有资源 → 选择“响应慢 / 连接异常 / 容量不足 / 其他问题”等适配该资源的场景 → 默认可见的时间预设 → 开始排查。场景只提供有实现支持的检查，无法支持时说明限制。

目标：常见场景必须填写的自由文本为 0 项；“其他问题”允许输入一段问题描述，不再重复填写标题。场景集合支持按类型筛选和搜索，避免用几十个固定按钮增加选择负担。

从工作空间自主发起

搜索选择对象 → 选择常见问题，或输入一段描述 → 核对系统生成的目标与窗口 → 开始。自然语言解析仅是可选辅助，选择路径无需先调用模型生成标题或猜测资源。

从结果继续

推荐下一步 → 查看检查范围与意图 → 一次提交形成新一轮执行。补充信息采用对应控件；已经提供的内容不重复提问。不能确定时选择“不清楚/暂时跳过”，保留缺口而非堵住整个调查。

从结果进入行动及验证

选择有能力支持的受控动作 → 带入精确结果、目标、前置条件及验证方案 → 人工核对草案 → 提交审批 → 独立批准与显式执行 → 系统汇总实际观测。填写编号和复制证据链接不应成为中间步骤。

行动是否有效由实际观测和明确标准判断，不能用“用户点了已恢复”替代。需要人工确认业务症状时提供“已恢复/仍异常/无法确认”并允许补充证据，状态更新仍遵循原权限与恢复规则。

4. 相邻监控配置原型排查

项目 要求
模板选择与版本 保留全部授权模板搜索、兼容筛选和多选；新绑定可推荐兼容稳定发布版，已有版本保持固定，不自动升级或替用户绑定
连接与凭据 从资源配置读取地址、端口、引擎和凭据引用；缺项才补。凭据从有权限的凭据库选择，不反复输入密码，也不回显秘密
参数覆盖 默认继承模板、展示来源；只有点击覆盖才编辑。阈值等数值保留带单位的数字输入，可提供常用值，不能为了选择化限制合理取值
监控项 优先从现有指标/采集输出选择或复制；名称、单位、类型由所选定义带入。新自定义指标的稳定标识可由确定性规则生成、查重并允许专业人员在发布前编辑；发布后不能随展示名变动
触发器 监控项、函数、运算符、周期、严重度和依赖用结构化选择；名称由规则生成可编辑；高级表达式保留，且不能在模式切换时丢失语义
测试采集/规则 自动使用当前对象与有效参数；支持选授权真实样本、历史窗口或边界预设，模拟数据明确标记。正常测试不要求用户另写 SQL、复制 ID 或先输入模拟数值
历史数据 带入当前资源与监控项，提供时间预设、对比周期和图表缩放，图形/数值切换不重填条件
确认事件 操作者、时间和事件引用自动记录；常用备注可选、自定义备注可补。确认不是恢复，更不是批准变更

5. 交互与数据约束

  • 自动带入的数据用可读摘要或标签显示，并提供局部“修改”，不铺满禁用输入框。
  • 默认值注明来源；预填不等于事实核验。无数据保留未知，不能为减少输入编造连接池上限、业务影响或根因。
  • 数据库、服务器等重名对象同时显示地址、类型及可用的环境标签，搜索结果可辨认；选项只来自当前授权范围。
  • 选项多时使用服务端搜索与分页；不得把未加载误报为不存在。已选项在翻页和筛选后保持，重新提交时校验权限与存在性。
  • 更换主对象、事件或窗口时，仅清理失效关联并说明原因，保留仍有效的用户补充；有未提交内容时避免静默丢弃。
  • 自动读取与复用事实默认不调用模型；需要额外模型生成草案时说明操作含义，刷新或打开表单不产生隐式分析任务。
  • 审批、拒绝、范围扩展和执行决定仍由有权限的人明确表达。常用理由只是便利输入，不能替审批人默认同意或伪造理由。
  • 前后端契约中若仍要求 title/goal/reason 等字段，由结构化上下文生成有效内容并保留来源；不能只在前端隐藏字段后提交空值或通用占位句。涉及审批理由策略的修改需另行核验后端约束。
  • 键盘可完成搜索、选择、移除和提交；控件有名称与加载/失败说明。少打字不能以嵌套弹窗和过多点击为代价。

6. 下一版原型验收要求

  1. 事件信息完整时，从事件到发起只读排查，必填自由文本为 0 项。
  2. 资源已有配置时，常见问题按场景和时间选择即可发起；自定义问题最多要求一段描述，不再要求独立标题。
  3. 标准闭环中不要求手工输入资源/调查/计划/审批 ID、结果版本、报告版本或复制证据引用。
  4. 同一资源与时间从事件到调查、行动、验证连续带入；有意变更时显示差异，不静默重置或扩大范围。
  5. 能点选有依据的下一项检查；无法确定的信息可标记未知。选择不会自动执行变更或代替审批。
  6. 大规模资源、重名、搜索无结果、读取失败、权限变化、过期版本、缺配置均有可用路径。
  7. 报告和交接从已有记录生成可复核草案，保留证据、缺口和人工补充来源。

以上为设计验收要求，本轮仅完成静态排查，尚未验证这些目标已经实现。

V4 原生模板少输入补充

新增监控项先选择已注册的可采集指标，自动带入名称、稳定标识、单位与映射；只调整名称、周期或允许参数。不要求手写内部 ID、SQL、命令或输出字段。无采集实现时明确提示并阻止加入可发布模板；测试沿原始字段→变换→指标展示结果。当前原型仅提供代表指标样例，不接真实采集。
