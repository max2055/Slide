# Slide 监控与运维闭环优化方案

日期：2026-10-22｜初始核查基线：main / 45fe437b｜状态：V4，按已确认范围更新设计与独立原型；不代表生产能力已实现

V4 补充：当前版本范围以[项目范围](../../slide/requirements/current-version-scope.md)为准：中文、浅色桌面浏览器，1440×900 为主，1366×768 与 1920×1080 复核；不做移动/平板、深色、听读顺序及完整无障碍专项。无 Agent 采集，人工维护 Slide 原生模板；不做 Zabbix 导入或运行兼容，事件中心取消重复的“规则与策略”。

V3 延续：资源概览保留综合态势、数据库、服务器、网络设备四子标签及既有模块；AI 工作空间按[体验设计](2026-10-22-ai-workspace-experience-review.md)和[输入负担排查](2026-10-22-input-burden-audit.md)更新。首版以故障排查与恢复闭环为主，资源/平台共用调查框架，优先自动带入、选择与筛选。

## 1. 决策与边界

采用 **Slide 原生完善 + 向 Zabbix 成熟领域机制对齐**。以模板统一监控项、触发器、参数、发现与图形，在资源上形成有来源的有效配置，以历史证据贯通问题判定、处理和运维验证。优先复用现有采集器、凭据引用、不可变版本、权限、告警事件与通知服务。

本次交付完整产品方案和可点击原型；不修改生产路由、业务配置、数据库或既有任务，不把原型演示作为后端验收。方案中的新增能力均为拟建设能力。AI 仅保留统一证据的接入点，不在本次重构模型配置或 Agent。

Slide 的定位是智能基础设施运维平台。除 AI 外，应以数据库等专业场景的“观测 → 诊断 → 操作 → 验证 → 审计”建立价值。Zabbix 也有数据库模板、资产、动作、脚本与远程命令，不能用“它只有监控”作差异化判断。监控底座应对齐成熟做法，把产品投入留给专业运维闭环。

### 已确认实现路线与排除项

本版唯一主线为 Slide 原生监控领域完善，参考 Zabbix 的成熟机制与指标经验。人工创建 Linux、MySQL、PostgreSQL、Oracle、达梦、华为交换机等原生模板，逐项连接真实采集实现并验收。内置模板可复制和编辑；绑定时从全部授权模板选择，不把某类资源的模板写死。

本版不做 Zabbix 文件解析/导入、表达式语法兼容、转换报告、兼容矩阵、上游同步、Agent/Proxy 协议或 Zabbix 后端集成；不为这些能力预建框架。此前可选后端与导入兼容讨论不作为实施依赖。参考机制不自动复用代码或模板文件，若未来实际复用再核验具体来源与许可。

纳管对象不安装监控 Agent；复用 SQL、SSH、SNMP 及已有注册的 HTTP 等采集实现。AI Agent、Agent 沙箱、模型执行不属于“目标侧监控 Agent”，沿用现有边界。

## 2. 依据：已有基础与真实缺口

依据：[Slide 初步分析](../../../outputs/monitoring-model-discussion-20261021/ANALYSIS.md)、[Zabbix 实机报告](../../../outputs/zabbix-lab-20261021/REPORT.md)。Zabbix 研究为 7.0.21 LTS 独立环境，14 项证据检查通过；含真实 Agent 数据及明确标识的 Sender 场景数据。研究未验证真实通知到达、生产容量和长期趋势清理。

| 现状（源码核查） | 方案要求 |
|---|---|
| 指标目录 / 采集包 / 采集策略分散在设置；资源另有采集模板及启用入口 | 用户看到监控模板、资源监控配置、最新数据、事件中心，内部技术对象继续可复用 |

| `metrics/packages/model.ts` 有不可变版本、digest、共享采集输出和凭据引用 | 作为模板编译与执行基础，不按每个监控项新建连接 |
| `metrics/consumers/evaluation.ts` 有阈值、持续时间、恢复阈值、质量校验；另有 compiled-rule / event / silence / notification | 汇入同一条有效触发规则 → 评估 → 事件 → 通知路径，不新增平行引擎 |

| 已有全局 raw/history/attempt 保留策略，不等于完整逐项趋势体系 | 首期保留策略清晰展示，后续再做按类型趋势和容量治理 |

以上为接线与能力基础，不等于 Zabbix 等价能力已经存在。实施首项需输出实际调用链清单，选择唯一事件写入路径。

## 3. 向 Zabbix 对齐与 Slide 适配

| 机制 | 决定 | Slide 具体做法 / 边界 |
|---|---|---|
| 模板包含监控项和触发器 | 直接对齐 | 两者为并列主页签，不把触发器隐藏在另一套告警配置中 |
| 资源绑定模板，模板可组合 | 对齐 | 支持多模板、固定发布版本、有效配置和来源；冲突阻止应用，不静默覆盖 |
| 宏与资源覆盖 | 对齐并简化 | 名称显示“参数”，高级界面保留宏标识；展示默认、覆盖、最终值和来源；秘密值只引用凭据库 |
| 继承与来源链 | 对齐但控制复杂度 | 首期一个模板版本可有一个基础模板版本，继承深度上限 3，禁止环；资源可组合多个模板；以后按需要扩展多父 |
| 单项测试与立即执行 | 对齐 | 测试不写正式历史、不发事件；立即采集走正式调度，返回任务及样本关联标识 |
| 预处理与依赖监控项 | 对齐并复用 | 一次采集产出多个规范化指标；有限转换类型白名单，不任意执行用户 JS |
| 触发/恢复表达式 | 对齐语义、分批实现 | 结构化编辑优先；高级有界 AST，首批 last/avg/min/max 与显式 nodata；不直接 eval，不承诺语法兼容 |
| 问题去重、确认与恢复 | 对齐 | 业务状态、评估质量和处理状态独立；单事件模式优先，恢复需满足明确条件 |
| 依赖、维护、通知升级 | 对齐 | 复用告警/静默/通知服务，明确依赖阻止新下游问题、维护抑制通知；不等于根因或恢复 |
| 最新数据、历史数值/图形 | 直接对齐 | 同一个资源、监控项、维度、时间窗上下文，历史保留配置版本 |
| 低层发现与两类原型 | 对齐，后续阶段 | 用文件系统、接口、库表实例化监控项及触发器；带失联保留和退役策略 |
| Zabbix 文件 / Agent / Proxy 兼容 | 本版排除 | 仅借鉴领域机制与指标经验，人工维护原生模板；不导入、转换或自动同步 |
| 界面与 AI 工作空间 | Slide 原生体验 | 保持蓝色主题、三类资源和专业运维入口；单页编辑，避免多层弹窗 |

## 4. 用户心智和信息架构

保持现有导航体系。资源管理严格保留原四个菜单及顺序：资源概览、网络设备、服务器、数据库。监控模板和最新数据纳入现有运维管理；事件处理完善现有事件中心，不新增事件真相源或独立问题中心。发现规则属于监控模板，与监控项原型、触发器原型共同版本化，不作为独立菜单。

不新增运维工作台。取消独立跨资源诊断菜单，其资源关系、观测证据、时间范围和分析过程合并到 AI 工作空间。取消独立关注事项菜单，原待处理聚合事件视图收敛到事件中心；工作空间首页“需要你处理”仅投影等待补充信息、待审批、待验证等原记录，不维护第二套状态。工作空间使用“资源诊断 / Slide 平台诊断”用户语言，证据查看无需调用模型。

平台状态保留现有统一入口，包含运行观测、平台自检、Agent 沙箱。平台异常放在事件中心，平台调查放在 AI 工作空间。其他既有菜单保持其原职责；原型中未展开的菜单标明未参与本轮交互。

资源详情以当前 Slide 各类资源完整详情为基线，融合概览、监控项、触发器、历史、监控配置和操作记录；这些是需要覆盖的信息职责，不要求替换既有全部标签结构。模板详情包含“监控项、触发器、参数、发现、图形、关联资源、版本”。常用对象可收藏，但不重复产生另一套配置来源。

| 旧概念 | 新入口与责任 |
|---|---|
| 指标目录 | 监控项的指标选择器与高级“指标定义”；保留语义、单位和维度规范 |
| 采集包 | 编译后的版本化执行制品；用户通过模板管理，不再要求普通用户先理解包 |
| 采集策略 | 资源监控配置里的周期、超时、并发等高级参数；保留调度责任 |
| 采集模板 | 统一为“监控模板”，必须包括监控项和触发器 |
| 启用此对象采集 / 检查并启用 | 统一流程：“绑定模板 → 检查配置 → 测试采集 → 应用并启用”；可保存配置暂不启用 |

资源八列遵从用户要求，单行多列：

- 数据库：序号、实例、地址、版本、观测健康、采集状态、最近采集时间、操作。
- 网络设备：序号、设备、地址、型号、观测健康、采集状态、最近采集时间、操作。
- 服务器：序号、主机名称、地址、系统版本、观测健康、采集状态、最近采集时间、操作。

四个操作按钮完整展示，不放进“更多”。原型采用详情、监控配置、测试连接、编辑四个示意动作；上线时保留当前业务已有的四项语义并按权限校验，不能以原型示意删掉已有动作。桌面保持一行，较小桌面窗口在表格容器内横向滚动，提供明确提示；不让整个页面溢出。

### 4.1 全模板选择与原生模板建设

资源上的“管理模板”读取当前主体有权访问的全部模板，不按数据库或服务器写死模板名称。按资源类型、数据库引擎、设备厂商、协议及 capability registry 推荐兼容的已发布版本；全部视图保留不兼容模板并展示明确原因。草稿、缺少采集适配器和能力不满足的版本不可应用。支持搜索、筛选、多选、固定版本、取消不生效、解除保留历史；确认选择后重新测试，不能默默更换正在生效的配置。无模板时不能测试和启用。

内置模板按实际已注册能力人工建设。Linux 采用 SSH；MySQL、PostgreSQL、Oracle、达梦采用各自只读数据库查询；华为交换机采用 SNMP。可参考 Zabbix 对应模板的指标选择、阈值、恢复逻辑和发现思路，但直接写成 Slide 原生定义，不建立上游导入/转换关系。Redis 等既有资源只按当前真实 capability registry 开放，类型声明和原型条目不等于已支持。

每份内置模板交付清单包含：适用系统/数据库/设备版本、采集实现、最低权限、指标语义/单位/维度、监控项与触发器、默认/覆盖参数、已验证对象及未支持项。没有采集实现的候选保留草稿且禁止应用；不能发布空壳模板。模板建设按数据库代表、Linux、华为 SNMP 的纵向闭环推进，其余引擎按实际能力逐项扩充；不承诺先填满指标数量再补实现。

### 4.2 事件中心的配置边界

取消“规则与策略”标签，不在事件中心重复编辑模板触发器。保留活动告警、聚合事件、通知投递、平台异常；聚合仅为原事件的关联/处理视图，不创建第二套事实或状态。

事件详情展示事件发生时的规则快照：监控项身份、命中值/时间、问题与恢复条件、有效阈值、模板版本、资源覆盖与配置 revision、依赖和抑制原因。后续修改模板或资源参数不改写历史快照；可跳转当时模板版本及当前有效配置，明确二者区别。

通知投递展示发送时间、渠道、接收对象引用、结果、失败原因与回执；通知路由/升级复用已有统一配置入口，不把本页变成第二个通知编辑器。维护/静默可从资源或事件就近进入并显示范围、期限、影响，不改变业务恢复判定。跨事件关联规则等未来确需配置时独立评估，当前不新增空壳“事件处理策略中心”。

### 4.3 资源详情的保留基线与设计前置

2026-10-25 澄清：数据库、服务器、网络设备列表中的“详情”进入现有 Slide 完整资源详情，并在保留各类专业能力的基础上优化；不能将 V4 的简化 `resource-detail` 弹窗当成最终详情页设计或开发验收标准。

- “详情”负责完整资源观测与专业信息，“监控配置”直接进入模板绑定、有效参数、测试与启用；两者复用相同资源上下文，不各维护一套配置。
- 共享资源身份、状态/数据时间、导航、监控与事件/AI 联动框架，但不将数据库、服务器、网络设备的专业内容压成同一个通用页面。
- 详细实施前，逐类盘点当前页面、标签、按钮、数据来源、权限和深链接，形成“保留 / 优化 / 新增”的差异表；现有能力是否可用以当时真实版本核查为准，不把历史源码核查当作现状证明。
- 补充三类完整详情原型，覆盖正常、无数据、加载失败、部分失败及无权限状态，并建立现有功能回归清单后，再进入相应页面开发。
- V4 已完成的列表、监控配置、模板、历史与事件关键交互可继续参考；当前简化详情弹窗只说明入口和资源上下文。本方案不宣称完整详情原型已补齐。

## 5. 领域模型与一致性

### 5.1 定义、版本、实例和历史身份

- Template：稳定 template_id、资源类型/能力要求、所有权、内置/自定义、标签。
- TemplateVersion：不可变 version_id/digest，包含监控项、触发器、参数、发现原型、图形、基础模板引用；草稿可改，发布新版本不可覆盖旧版。
- ItemDefinition：稳定 definition_id、key、显示名、单位、值类型、维度、采集器与输出映射、预处理、周期/超时、保留策略。可见名更改不改变历史身份。
- ResourceTemplateBinding：resource_id + template_id + pinned_version + enabled + overrides + revision；生效配置包含来源链、编译版本和应用回执。
- EffectiveItem：resource_id + definition_id + canonical_dimensions 形成稳定序列身份；series_id 与 template_version 分离。指标含义/单位不兼容时创建新 identity，旧历史可查，不拼接成连续曲线。
- TriggerDefinition/EffectiveTrigger：稳定规则身份、引用的指标身份、有效参数、问题/恢复条件、窗口/覆盖率、依赖、严重度、规则版本。
- ProblemEvent：effective_trigger_id + episode_id；开闭事件、证据窗口、规则版本及参数快照、确认记录、抑制原因、通知回执分别记录。

**组合冲突**：相同 canonical metric key 且相同含义可在编译时去重执行；若来源配置不同，展示冲突并要求选定一个提供者或修改命名空间。不同 key 但相同采集查询按采集器 output group 复用。不能“后绑定的赢”。资源覆盖优先于所选模板值；参数来源完整展示；恢复继承需预览变化。

**解绑**：默认“解除关联，保留历史”，展示将停止的项/规则和未恢复问题。无后续提供者的规则停止评估，未恢复问题标记“规则已停用/终止评估”，保留事件而不伪造恢复。重绑同一稳定定义可继续同一序列；不兼容新定义另建序列。历史删除为独立受限操作。

### 5.2 生效与调度

保存草稿不影响运行；发布不自动升级所有资源。升级先比较新增/删除/单位/阈值/负载影响，选资源灰度，按版本及 revision 应用。应用状态 pending/applied/failed 与发布状态分开显示。幂等应用键包括资源、目标 revision 和 digest；失败保留上一份生效配置，支持重试和回退，避免半更新。

周期与并发经服务器校验；同资源同采集分组复用连接、查询和输出，分发给多个监控项。采集不支持、无权限、凭据失败和样本无效都有分类错误，不能呈现为 0 或“健康”。测试、正式执行分开标识 trace_id。调度拥有者租约/锁和幂等样本标识防止多实例重复执行。

### 5.3 权限、凭据和表达式安全

区分查看历史、查看/编辑模板、发布、绑定、测试、立即采集、处理问题和执行运维权限，按资源范围实时校验。模板草稿和测试同样需授权，不能借表达式或绑定越权读其他资源。秘密参数只保存 credential_ref，日志/导出/测试返回均脱敏。SQL/SSH/SNMP 等采集限制查询范围、耗时、结果行数和目标地址；只读监控与变更操作权限分离。

表达式使用受限语法解析为 AST：限定函数、窗口、递归深度、输入序列数和评估耗时，发布时校验单位与值类型；无 eval、任意 SQL 或任意脚本解释器。高级编辑与结构化编辑必须等价转换；不能转换的合法高级表达式以只读摘要显示，避免静默丢失逻辑。


### 5.4 无 Agent 采集与显式映射

**执行链：资源绑定/权限与凭据 → 有效采集计划 → 注册采集实现 → 原始输出 → 类型/单位/维度与转换 → 指标观测 → 监控项序列 → 触发评估/历史/AI 证据。** 图中的环节为后端责任，普通用户只面对模板、指标选择和测试结果，不必维护采集包。

沿用现有 `metrics/packages/model.ts`、`runner.ts` 的 `implementation_ref`、`raw_field`、`metric.id/semantic_version`、单位及 `transform_version`，不另造基于显示名称的绑定系统。数据库适配参照 `metrics/database/catalog.ts` / `collector.ts`，主机参照 `metrics/packages/adapters.ts`，网络参照 `metrics/snmp/collector.ts`。这些是代码基础，不是全部拟建模板已经可运行的证明；实施前按 P0 核实实际执行路径。

#### 5.4.1 四种身份与匹配规则

| 层 | 身份与责任 |
|---|---|
| 原始输出 | 采集实现固定版本 + 输出字段名，包含观测时间、类型、源单位、维度与质量 |
| 指标定义 | 稳定 metric_id + semantic_version，描述含义、最终单位、gauge/counter/state、维度与变换；一个字段可参与多个派生项 |
| 模板监控项 | 稳定 definition_id，显式引用指标定义和采集映射/依赖；显示名只是标签 |
| 资源实例/序列 | 资源、监控项稳定身份与规范化维度关联到 series_id；记录 binding/revision 和采集 attempt，不随模板发布或显示名变化换历史身份 |

触发器保存对监控项/指标的明确引用，编译到有效实例；不得按中文名、展示顺序或字符串相似度匹配。等义的已有 canonical metric 复用；同名但口径不同创建独立定义。跨模板共享读取不等于无条件合并历史。来源或含义不兼容变化需要新身份和明确迁移，不能静默续接。

#### 5.4.2 原生模板采集示例（拟建设验收样例）

| 对象/监控项 | 原始来源 | 映射/转换 | 重要边界 |
|---|---|---|---|
| MySQL 连接使用率 | `SHOW GLOBAL STATUS` 的 Threads_connected 与 `@@GLOBAL.max_connections` | 两个来源完整后 current/limit×100，单位 % | 包含监控连接；不能静默替换为权限范围不同的 PROCESSLIST 行数；零上限/缺字段为未知 |
| MySQL 失败连接速率 | Aborted_connects 累计计数与启动/重置证据 | 相邻有效样本差/实际秒数，单位次/秒 | 首样本、重启、回退或连续性不明时未知；变换只做一次 |
| Linux 可用内存比例 | SSH 读取 /proc/meminfo 的 MemAvailable、MemTotal | 统一 kB 到字节后 available/total×100 | 缺 MemAvailable 不改用未经说明的 MemFree；服务器凭据独立 |
| Linux CPU 利用率 | SSH 两次读取 /proc/stat，或有连续性证据的周期差分 | 固定公式与采样窗口，iowait 口径明确 | 不是瞬时值，不能冒充 Zabbix Agent 的 avg1；重启/采样不足为未知 |
| 华为接口入流量 | SNMP IF-MIB 的 ifHCInOctets、uptime、接口身份/连续性 | uint64 差值/秒×8，单位 bit/s，绑定接口维度 | ifIndex 复用、设备重启、计数中断不跨越计算；缺首样本不补 0 |

上述字段与指标需先登记到现有实现注册表，经真实测试后对用户开放，不因写入文档或原型而成为已实现能力。SNMP 状态若从原始 1/2 转成不同状态值，指标定义与触发器同时按明确字典转换。

#### 5.4.3 配置与模板编辑体验

新增监控项先搜索/筛选“已注册可采集指标”，按资源类型、引擎、协议和权限推荐；自动带入显示名、系统生成稳定标识、单位、输出映射和默认周期。名称可改，周期与允许的参数可调；普通用户不手输 raw_field、SQL、SSH 命令或指标内部 ID。高级定义维护仅向有权限的维护者开放，仍需受控注册和发布；不增加任意脚本执行器。

缺能力项保留“尚无采集实现”的说明，不能测试/加入可发布模板；新增名称不会自动赋予采集能力。派生项选择已存在输入和允许的公式，验证类型、单位、依赖环与执行顺序。发现从 SNMP 表或 SSH 枚举生成带稳定维度的监控项/触发器实例，仍属于当前模板。

提供“采集映射”只读详情：来源协议与实现、输出字段/时间/单位、变换、最终值、监控项和序列身份；测试时逐项沿链展示成功或失败阶段，生产数据和演示/测试数据清楚区分。

#### 5.4.4 调度、批量与生命周期

复用现有唯一调度路径。同资源相同实现/版本、目标、凭据范围、参数及兼容周期可共享连接和输出；不同权限/参数不得为省查询而混用。到期项组成一次有界读取，结果分发给多个监控项，重型容量/发现任务独立较低频率。具体周期、并发及超时由 P0 实测容量基线决定。

绑定/参数/版本改变后重新编译并测试，失败保持上一有效计划。执行保留计划 revision 和原始观测时间；复用结果只在同次或明确新鲜度内发生，不能把缓存旧值当本轮采集。超时分类、退避、连接复用和单项失败隔离沿用现有基础，连续失败不显示健康。

累计量保留精确 uint64 和连续性证据；率计算集中在指定变换层，避免采集器与监控项预处理重复求差。首次样本、重启、计数器重置、异常时间间隔和接口身份变化进入未知/预热；后续连续有效样本才恢复速率评估。派生值记录输入时间与窗口，窗口不一致不强行拼接。

数据库指标若依赖主机观测，必须选择有来源的数据库—服务器关系和该服务器授权凭据；不能从数据库地址猜测 SSH 目标，不能借数据库权限访问服务器。

#### 5.4.5 逐模板完成门槛

每种模板独立完成“真实采集 → 原始字段映射 → 标准指标 → 最新/历史 → 触发/保持/恢复”并保存证据。人工创建模板是一次性可复用定义，新增资源只选择模板、确认参数和凭据，不逐资源手工映射。普通编辑入口只能选择已交付能力；未覆盖项明确留作候选，不以指标计数或页面存在宣称完成。

## 6. 核心流程与状态语义

### 6.1 配置与测试

1. 从资源进入监控配置，选择适配能力的已发布模板，看到监控项/触发器数量与版本。
2. 展示合并后的监控项、参数及来源；冲突和缺凭据直接阻止应用。
3. 测试采集返回成功、失败、不支持、未采样数量，逐项显示值、单位、耗时、读取/预处理阶段与错误。测试不写正式历史、不触发问题或通知。
4. 正式启用前列出计划、负载估计、失败项和影响；必要项失败或未完成测试时阻止启用。可选项可显式排除，不能“一键忽略所有失败”。
5. 应用并启用后先显示“配置已生效，等待首样本”；首样本落地后才显示正常采集。部分失败显示异常数量并可直达原因。
6. “立即采集”返回执行任务，再关联真实样本。点击被接受≠采集成功。

### 6.2 触发器：问题、质量、处理三个维度

| 维度 | 值 | 交互含义 |
|---|---|---|
| 业务判定 | 正常 / 问题 / 初始未判定 | 描述业务条件；初次没有有效数据不得默认为正常 |
| 评估质量 | 有效 / 未知（缺测、过期、单位不符等） | 问题期间缺测保留问题，附“当前无法评估”，不能自动恢复 |
| 处理状态 | 未确认 / 已确认；未抑制 / 已抑制 | 确认有人处理与维护抑制通知，不改变业务判定 |

示例：资源 CPU 高阈值覆盖为 90，恢复阈值继承 70。问题 last >90；恢复需问题条件为假且 last <70。95 触发，85 保持，60 恢复，恰好 90 不触发，恰好 70 不恢复。窗口规则必须说明 min/avg/max 的含义及最低覆盖率，不能用“持续五分钟”替代不同统计逻辑。

首期支持 last/avg/min/max、比较、AND/OR、宏参数、独立恢复与 nodata；默认单事件，同一问题持续不重复建单。显式 nodata 通过调度时钟评估，不能等新样本才检测无数据；未知数据不等于 0。依赖阻止新下游问题，已有问题不因上游异常自动恢复；依赖仅是配置抑制关系。维护默认继续采集、记录问题、抑制通知；离开维护重新评估和执行通知策略，避免补发风暴。

规则发布、重复评估、进程重启、延迟/乱序样本均需幂等：问题状态持久化，事件开闭转换事务化，通知用 outbox 与幂等键。过迟样本可进历史，是否重评当前状态按明确 watermark 策略，不能把旧样本当当前恢复；首期不追补历史通知。

### 6.3 最新数据与历史

最新数据展示当前采集状态、最近成功值、值时间、最后尝试时间、单位和模板来源。当前错误和旧成功值并列；旧值灰化附时间，不冒充实时健康。

历史详情保持资源、监控项、维度、时区与时间窗；提供图形/数值表、6h/24h/7d/自定义时间，图形显示单位、缺口、阈值、问题/维护区段。数值表显示实际时间、值、质量和配置版本。图形降采样必须保留异常峰值，输出 count/min/max/avg 与桶范围；原始值分页可查。状态/文本项以事件表展示，不强制折线。

24h、1分钟周期1440槽首期必须完整检索，不能先裁1000点再聚合；分页/流式读取的 API 明确 cursor、时序、时区和 total/hasMore。历史判定相对当时的采样和查询窗口，不能因“距离现在太旧”消失。停用/解绑后历史依然按资源权限可查。后续趋势分层聚合，按值类型设置保留期，删除有容量预测和审计。

### 6.4 问题 → 专业运维

问题详情先展示命中数据、表达式、有效阈值、依赖/抑制原因和发生/确认/恢复时间线，链接到同一证据窗口。第一步接已有只读诊断入口；后续通过“诊断包、预检查、变更、验证、回滚和审计”形成专业运维任务。

例如数据库连接数高：查看连接数与上限 → 同时段活动会话/锁等待只读诊断 → 操作者选择受控动作 → 按现有权限和风险审批 → 复测指标与业务探针 → 记录前后证据。确认问题不启动操作，执行完成也不自动宣告恢复。破坏性动作、AI 自主修复、全套数据库工具不属于首批监控改造。

### 6.5 Slide 自身观测与平台诊断

复用现有平台观测、持久异常和 System 调查实现，完善串联而非新建平台诊断系统：平台状态 → 事件中心「平台异常」→ AI 工作空间「Slide 平台诊断」→ 复测恢复 → 审计。

平台状态展示异常采集与自动分析两个独立开关的有效状态、组件信号覆盖、数据新鲜度、API错误、Agent运行、WebSocket连接、采集延迟、队列积压及部署版本证据。自检仅说明一致性/准备度；无信号、采集关闭、读取失败均明确显示未知，不能显示健康或零错误。生产启用和有效配置需单独验证，原型不修改配置。

异常事实先持久化，自动调查受现有开关、服务身份、权限、去重/冷却及预算约束；查看页面不启动模型。平台诊断按组件、版本和时间窗口读取异常事实、脱敏日志与经核验的部署源码。缺少对应部署版本时保留缺口，禁止回退最新 main 充当故障版本。模型不可用时事实与证据仍可查看；不默认自动修复。

故障状态、调查执行状态与处理状态分开。调查完成不等于故障恢复，恢复需后续有效观测或明确复测证据；从原异常进入调查后能返回验证，保留原始异常及分析记录。平台整体不可用的发现还需要独立外部探针，本轮原型不模拟全宕机下的自我报告能力。

## 7. 页面与美观设计契约

沿用 Lit、Slide 蓝色主题、共享组件与 token，不另建设计系统。主要内容为可扫描的紧凑表格，数字等宽，语义色只用于状态和少量重点。页面标题、说明、主操作保持固定层级，避免卡片堆叠和每行整块强色。

减少输入负担：已有资源、时间、连接、凭据引用和版本自动带入；优先采用搜索、筛选、结构化选择与模板继承，确需自定义才补文字或数值。系统生成标题、标识、时间线与报告草案，保留可复核来源；不自动批准、扩大范围或宣告恢复。具体源码/原型排查和验收要求见[输入负担排查](2026-10-22-input-burden-audit.md)。AI 工作空间应提供问题场景选择，不能要求用户必须编写提示词才能排查。

- 模板库：类型筛选、搜索、版本/关联数、监控项/触发器计数；点击进入并列页签。
- 模板编辑：主编辑区 + 右侧生效摘要。基础项默认展开，高级规则逐步展开；触发器独立页面，不嵌套多层对话框。
- 资源监控配置：模板组合、来源/覆盖、测试结果、底部应用；未测/失败/等待首样本均有明确状态。
- 最新数据与历史：状态及时间不混淆，曲线和表格共享上下文，未知有文字解释。
- 事件中心：发生状态和处理状态分列；确认弹窗明确“不改变恢复判定”；详情给证据与时间线。
- 发现：在模板内展示规则、实例、监控项原型、触发器原型与失联生命周期。
- AI 工作空间：统一调查列表，资源/平台为对象筛选；首页提醒引用原记录。以场景选择、上下文确认、只读检查、人工补充、证据/结果版本、行动与复测为主线；不要求手工输入内部 ID 和版本。平台取证边界独立，不混用资源工具权限。
- 平台状态：采集开关、信号覆盖、新鲜度与部署缺口显式展示，自检与运行观测分开。
- 桌面范围：1440×900 为主，1366×768 与 1920×1080 检查；浅色中文，当前稳定 Chrome/Edge。表格局部滚动，主操作和固定区不遮内容；保留基本键盘和弹窗焦点。不做手机/平板、深色、听读顺序、完整 WCAG、多主题、国际化、PWA、装饰动效和穷举视觉矩阵；完整边界见项目范围。
- 不只验收默认页：还要覆盖无模板、无数据、部分失败、不支持、无权限、应用失败和待首样本。

## 8. 迁移与回退

1. 盘点指标目录、采集包版本、策略绑定、旧模板、告警规则和历史身份，导出映射与计数，先不改运行数据。
2. 幂等迁移把旧 package pin 映射成一个监控模板发布版，旧绑定映射成一条资源关联，旧阈值规则关联为触发器。保持原始 source_id、series_id、凭据引用、revision 和更新时间。
3. dry-run 输出未映射、重复、冲突、单位变更及受影响资源；阻断项清零后才对代表资源灰度。迁移绝不靠 UI 名称匹配。
4. 切换采用 feature flag 和资源级路由。先影子编译与只读比较，不启第二个事件/通知写入者；指定唯一调度和事件负责人。
5. 校验有效计划一致、历史计数和抽样、样本频率、问题去重、权限、配置来源和负载；分别灰度数据库/服务器/网络设备。
6. 回退至旧配置版本及执行路径，保留新历史与事件审计；新模型新增的多模板组合先冻结编辑，不强行压回单模板造成丢失。保留旧结构至回退窗口结束后再独立清理。

## 9. 分阶段实施包

本方案是完整蓝图，按依赖拆成独立实施包，不能将所有能力塞入一张开发任务。工期在调用链盘点和数据量基线完成后按实际工作量估算，本次不编造人日。

| 阶段 | 交付与依赖 | 完成门槛 |
|---|---|---|
| P0：契约和迁移准备 | 调用链、历史身份、唯一引擎、模板/绑定/触发器契约、迁移 dry-run；明确容量基线 | 模型映射无静默冲突、可回退；现有数据与权限不丢失 |

| P4：专业运维联动 | AI 工作空间统一资源/跨资源及平台调查，串联现有平台状态和事件中心；证据窗口、只读诊断、受控动作、操作后验证及审计；可在P1后先接已有只读入口 | 问题→诊断→审批/执行→验证全链可追溯；不扩大操作授权 |

P1 可以按“先固定一个模板跑通，再打开组合编辑”内部拆分，但对用户发布时不可把触发器和可查询历史留成空壳。所有阶段同时交付对应 UI、错误状态与浏览器验收。
