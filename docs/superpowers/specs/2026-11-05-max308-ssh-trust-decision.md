### 实际字段映射与剩余具体歧义

当前代码只有以下两种登录认证，没有第三个“凭据认证”模式：

| 字段值 | 实际传给 ssh2 | UI 名称 | 新迁移范围 |
| --- | --- | --- | --- |
| password | username + password | 密码 | 明确排除；含已配指纹的混合对象 |
| key | username + privateKey | SSH 密钥 | 待确认“凭据认证”是否就是此模式，特别是无指纹的 key 对象 |

依据：`server-database-service.ts` 的 testConnection、`ssh-session-pool.ts` 的 _connect 和 `network-devices/config-backup-service.ts` 的 transport 均按 password 分支设置 password，否则设置 privateKey；`resources/network-device-types.ts` 与公开契约只接受 password/key；`app-ssh-auth-selector.ts` 明确显示密码/SSH 密钥。主机指纹独立传给 hostVerifier，不能作为登录方式判断依据。

建议具体映射：key 私钥认证属于本次范围（不论是否已有 pin）；password 一律排除新迁移。需要仅确认这个字段映射，不能仅从“凭据”一词自行断定。没有该确认时，不写入数据库迁移或在 key 无指纹连接前新增拒绝逻辑。

## 方案比较

| 方案 | 兼容性与安全语义 | 结论 |
| --- | --- | --- |
| 固定指纹 + 显式兼容 + 待确认迁移 | 复用已有 SHA256 pin；新配置无策略拒绝；旧 pin 保留，旧空值待确认；需接受未确认对象暂停 SSH | 推荐，改动最小，符合现有架构 |
| 保持旧连接运行的限期过渡 | 需要单独记录 legacy 状态、明确期限和风险接受主体；不得把它当成逐对象显式兼容或声称已消除风险 | 需产品明确批准过渡例外后才能采用 |
| known_hosts 或 TOFU | 增加目标映射、首次确认、并发首次写入及密钥轮换；未经可信渠道确认的首次密钥仍可能来自冒充者 | 本任务无需新增第二套信任机制 |

## 推荐方案的具体行为（待决策，不实施默认值）

信任状态为 `pinned`、`insecure`、`pending`。后两者不能通过一个空指纹隐式表示。

- `pinned`：提供严格校验的 SHA256 指纹；支持通过受信任渠道核验后手工录入。首次连接匹配才认证，错配在发送密码前拒绝。不得自动学习或覆盖错配的密钥。
- `insecure`：用户在管理界面或 API 明确选择，UI 在测试、保存和运行前展示“未验证服务器身份，密码可能发送给冒充者，运维结果可能伪造”。只接受明确模式值，不由缺省、空白或测试成功推断。
- `pending`：已存在但没有有效指纹及显式选择的对象；不发送认证凭据，显示待确认原因和修正入口。这个行为须先获本文件的升级决定确认。
- 缺省与空白：新建和无状态测试缺省策略返回需要选择；字符串空串/纯空白视为输入错误。更新省略策略保持原策略；显式清空不能意外降级到 insecure。历史 DB null 与 API 误填空白分别处理。
- 模式与指纹冲突、未知模式、非字符串、错误 pin 均拒绝，不能退回兼容模式。已有合法 pin 可按已有有效验证能力迁移到 pinned，不需要重新接受风险。

## 存储、API 与审计

- 在服务器及网络设备 SSH 凭据旁新增专用信任状态字段，保持原指纹与密文不变；只使用前向、幂等迁移，不修改历史 migration checksum。
- 显式选择记录 actor、资源、模式、时间和请求关联；审计不得包含密码、私钥、完整请求体或解密后的凭据。策略更新与审计持久化须具备一致性，不能审计失败仍悄悄允许 insecure。
- 为网络设备提供独立更新 SSH 信任策略的路径，避免仅更新策略却被迫重输或回传已有凭据；读取 DTO 只暴露信任状态和公开指纹。
- 列表、详情和编辑器暴露同一状态；未配置 SSH 的网络设备标为未配置，不误报为待确认连接。
- 无状态测试也执行同一策略解析；不能把 SSH 登录成功返回的 `verified` 误解为服务器身份已经验证，响应应区分登录成功与信任模式。
- 更新 OpenAPI 与生成客户端，并运行 `pnpm contracts:check`。

## 所有连接入口及一致性

| 入口 | 必须处理 |
| --- | --- |
| 服务器无状态测试 | 策略验证先于 connect；保留 MAX-309 握手失败及时完成 |
| 服务器采集、诊断和 Linux evidence | 读取同一资源快照的策略、pin 与凭据，统一连接池验证 |
| metrics/config/access | 将策略加入已验证快照和身份比较；变化即拒绝旧能力，不在快照验证后另取新目标 |
| ssh-session-pool | 策略进入会话身份；变更策略不能复用旧连接；保留用户名/凭据指纹隔离、撤销和在途容量预留 |
| 网络设备 SSH 测试、手工/定时备份、SSH 命令 | transport 强制执行同一策略；业务返回明确的拒绝原因 |
| 已强制 pin 的行动执行器 | 继续强制 pin，不通过本任务兼容模式放宽 |

策略变更需使对应旧会话与能力证据失效；保留凭据迁移 CAS，不为更新模式改写凭据。更改 host/port 不能沿用对旧目标的兼容确认或信任证据；需重新选择或核验。
