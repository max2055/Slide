# 平台数据库重启后的进程内自动恢复

日期：2026-10-21。状态：待用户审阅的设计草案，尚未实施。

## 目标与验收边界

平台 MySQL 暂时不可达或重启后，前端开发服务和后端 Node 进程保持原 PID；数据库恢复后，API、已登录页面和符合条件的后台任务自动恢复，无需人工重启、刷新页面或重新登录。真正过期、撤销或禁用的会话仍执行现有认证规则。部署本功能时允许一次正常加载新版服务；后续数据库故障演练不得通过重启应用完成恢复。

本次仅处理平台数据库依赖，不将纳管 PostgreSQL、达梦等目标不可达混入平台故障。不升级依赖、不新增守护进程、不调用产品 LLM、不变更 Provider 或自动调查开关，不改写已确认结果未知的任务。

## 当前证据

- `apps/db-ops-api/src/lifecycle/worker-startup.ts`：租约续期异常立即中止启动代次并调用关闭回调，AbortController 不可复用。
- `apps/db-ops-api/server.ts`：该回调关闭后台任务、HTTP 服务和平台连接池；当前停机流程只有整进程关闭语义，没有依赖恢复语义。
- `apps/db-ops-api/src/db-connection.ts`：mysql2 连接池可建立新连接，但连接池被主动关闭后，现有引用无法自行恢复。
- `apps/db-ops-api/src/auth-middleware.ts` 和 `src/auth/actor-context.ts`：依赖读取异常被包装为认证失败，HTTP 中间件统一返回 401。
- `frontend/src/api/index.ts`：刷新令牌请求只要返回非成功响应就清理登录状态，包括暂时性的服务故障。
- `frontend/src/app/ui/views/dashboard.ts`：数据加载失败后只提供手动重试；`app-settings.ts` 的连接恢复刷新分支跳过 dashboard 等独立页面。
- 2026-10-21 本地故障：MySQL 容器 08:52 重启；后端记录 `WORKER_LEASE_FAILED` 后退出，Vite 仍监听但代理持续报连接拒绝及 HTTP 500。恢复证据见 `outputs/frontend-recovery-20261021/receipt.json`（本地产物，不作为跨环境前置依赖）。

## 方案比较与选择

| 方案 | 行为 | 取舍 |
| --- | --- | --- |
| A：进程内降级与安全恢复（推荐） | HTTP 保活，暂停后台任务，恢复依赖并重新确认租约后重建任务代次，页面自动重新读取 | 满足应用进程不重启，需要拆分现有最终关闭与可恢复暂停 |
| B：守护进程自动重启后端 | 数据库恢复后自动启动新的 Node 进程 | 实现较少，但后端 PID 改变，不满足进程不重启的目标 |
| C：仅连接池重连与延长续租等待 | 容忍部分短暂断连 | 无法覆盖租约过期、会话误清除或页面不刷新的问题，不能作为完整交付 |

本草案选择 A。不能把数据库错误直接忽略、延长已过期租约，或将自动重启称为进程内恢复。

## 后端生命周期与任务安全

将最终退出和依赖中断分开。运行状态为 ready → degraded → recovering → ready；收到 SIGTERM/SIGINT 进入最终 stopping，不得触发恢复。HTTP 路由只注册一次，恢复时不重复注册 Fastify 插件。

断库或无法证明租约有效时立即撤销 ready、新任务派发及写操作资格，并中止当前后台任务代次。存活探针保持可达，就绪探针返回 503。平台业务接口采用稳定的服务暂不可用响应，保留真实的未授权、权限不足和业务冲突语义，不返回伪造的空列表或成功结果。

平台连接池继续使用稳定引用；只丢弃驱动确认失效的连接。后台工作代次独立持有 AbortController、定时器、任务注册表、Agent 运行资源和关闭结果，不复用已终止 signal。暂停时取消或排空旧代次；API 所需资源保持可用，或者以明确状态等待依赖恢复。检查 `get-agent-engine.ts` 的单例处置语义，保证恢复时不会取得已 dispose 的运行资源。

恢复协调器单实例运行，使用有上限的指数退避与抖动，探测超时，禁止并发恢复循环和探针堆积。恢复后检查数据库访问及迁移账本兼容性，不反复执行迁移；真正 schema 不兼容、无效配置等错误保持不可用并报告，不能伪装为网络瞬断。

重新获取租约后才能建立新工作代次；租约、工作任务自身 fencing 和现有权限检查均继续生效。旧代次未确认停止时不得开始新代次，不允许通过超时后直接放弃旧资源而并发执行。不能安全取消或确认停止的外部操作维持不可用并留下诊断；不承诺其自动继续。

其他实例已持有租约时保持 API-only standby，不抢占有效租约。本次只让曾正常运行的实例在依赖中断后尝试重新取得执行资格，不扩大原有 standby 自动接管语义。恢复未完成时始终不 ready。

结果未知的 SQL、行动、通知、模型调用和其他外部副作用沿用现有 unknown、幂等和人工核对规则；不因重连重新执行。已持久化队列工作按原有任务状态与 fencing 恢复，不绕过审批、不新增立即补跑策略。

## 认证与前端恢复

对平台依赖不可用建立明确的内部错误类型，将其映射为 503，而不是 401；身份验证和实时授权无法读取时仍拒绝业务访问，不能沿用过期权限缓存放行。HTTP 与 Agent WebSocket 的认证入口采用一致分类，避免临时依赖故障触发永久 auth_failed。

前端只在确认的令牌过期、撤销或身份无效时清除登录状态。刷新令牌遇到网络错误或 5xx 保留现有状态并显示暂不可用；真正认证错误继续退出。刷新令牌请求不因结果未知盲目重复轮换，先按现有令牌轮换和重用检测契约处理，不能将连接重试变成新会话创建。

复用现有主题和通知/空状态组件展示连接中断及恢复。统一的连接状态协调器在失败后有界频率探测恢复，不在每个组件各建轮询；健康时停止恢复轮询，组件卸载时清理监听。页面重新可见时可重启探测，避免后台长时间节流后无法恢复。

恢复时通知当前页面重新读取必要的只读数据，包括资源概览；不强制整页重载，保留筛选、分页、输入草稿及滚动位置。WebSocket 自动重连仍受真实认证失败和主动断开控制，不在重试次数耗尽后永久卡住临时故障。只读请求允许重新获取；保存、删除、执行等失败写请求不自动重放。

## 验证与交付

1. 先增加并执行回归测试，证明旧实现断库关闭服务、把依赖故障当 401、刷新失败清除会话以及页面不能自动恢复等问题。再逐项修复并运行同一测试确认转绿。
2. 后端测试覆盖瞬断、超过租约 TTL 的中断、并发续租失败、恢复后另有持有者、旧代次关闭阻塞、最终退出、连接超时和反复重启；验证单个恢复循环、单代次任务和未授权不放行。
3. 前端测试覆盖 503 保留登录、真实 401 退出、只读数据自动刷新、组件卸载清理、请求合并与退避，以及未知写结果不重放。
4. 真实故障演练优先使用隔离 MySQL 与同版候选应用，禁用产品模型调用和新增外部副作用。演练前核对 PID→端口→cwd→命令→Commit→日志，保存隔离对象及回退点；不为验证本功能重启其他项目共享数据库。
5. 同一浏览器页面保持打开，记录前后端 PID、HTTP 存活/就绪状态、有效登录、资源概览及后台任务状态；执行真实 MySQL 停止/启动，覆盖短暂与超过 30 秒两种中断，再重复一轮。数据库确认可用且旧代次排空后，以 60 秒内恢复就绪及页面读取为验收上限；等待有效他方租约或无法排空的任务明确列为不满足自动恢复的安全阻塞。
6. 数据库中断时 HTTP 存活可达、业务及就绪返回 503；数据库恢复后应用原 PID 不变、页面无需手动刷新或重新登录、无重复后台任务和外部操作。真实会话到期不计作保留登录失败，但需单独验证正常过期行为。
7. 按变更运行后端/前端 focused checks；最终候选完成受影响模块测试、双方 typecheck、前端 build/CSP、公开契约检查与触达认证/授权的安全测试。必要真实业务验收不能由健康探针代替。当前文档不代表这些测试已通过。

## 停止条件与授权

旧代次无法安全结束、发现未知外部执行结果、隔离环境不可用且只能重启其他项目共享数据库，或需要改变既有审批/权限边界时，仅暂停受影响操作并保留证据。其余独立工作继续。产品 LLM 调用为零；若后续验收确有必要，先继承适用的既有批次模型与计量规则，不自行重置预算。

本草案同时供设计与书面方案审阅；批准后按同一范围进入实施计划和 TDD，不重复请求相同版本设计批准。
