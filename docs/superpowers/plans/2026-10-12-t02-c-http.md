# T02-C Investigation HTTP Implementation Plan

> **Execution:** 在已批准 V1.1 / 调度 v1.2 与 T02-C dispatch 内执行。无子代理、生产变更或模型调用。

**Goal:** 交付真实 JWT 调查 CRUD/admission HTTP，幂等恢复同一调查、原子消息与队列。

**Architecture:** Fastify 窄路由复用 ActorContext 与 T03 SessionBridge.create/admit。T02 store 在同一事务预留创建命令键并恢复原调查；正式增量迁移保存键/hash及冻结 subject/window。一个 admission/queue owner。

**Tech Stack:** Fastify、TypeBox、MySQL 8.4、Vitest、pnpm。

### 1. HTTP 与输入契约
- 新增 investigations/http-contracts.ts / routes.ts / routes.test.ts，严格拒绝客户端 actor/权限/Profile内容。
- POST create 要求 Idempotency-Key，服务器固定 Profile 版本；校验 subject/resourceRefs 和有限窗口；桥接创建及首请求返回202稳定ID。
- list 使用授权后 count/limit，cursor绑定过滤条件；detail读取已持久化元数据；PATCH乐观版本；runs复用桥接；消息按内容scope读取。
- cancel仅持久取消意图，队列尚未领取时事务取消job；运行中不伪造Run终态，后续T04执行器消费意图。
- 注册 apps/db-ops-api/server.ts；将HTTP schema与OpenAPI接入现有生成器，生成前端类型仅契约产物。

### 2. 有界 store 增量
- 新迁移113：creation key/hash/investigation关联和冻结context；不修改历史迁移。
- createInTransaction先锁actor/key，重试实时授权后比较原命令hash并返回原创建版本供桥接首request去重；任何失败回滚全部。
- PATCH活动请求禁止更改goal；无证据的resolved拒绝，恢复验证留T11。
- cancel实时operator/all-scope授权；事务更新request取消意图与未领取job；不操作DirectAdapter。

### 3. 真实验收
- routes.test.ts采用Fastify真实注册、签名JWT、隔离MySQL正式迁移，验证100同键create/runs、payload409、单Session活动请求、CRUD重开连接持久读取、分页/授权、viewer/read-share负例、同JWT撤权与全部三类scope、System config/service登录、原Chat转换/活动Run、版本竞争。
- 注入Session/调查/request/message/job/outbox失败，503且表内无孤儿，移除故障后同键恢复。
- focused测试先失败，再实施；真实suite接入现有CI qualification脚本；module、typecheck、lint、contracts、触达安全gate。
