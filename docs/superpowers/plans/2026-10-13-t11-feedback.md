# T11 反馈领域实施计划

> **Execution:** Follow this plan within existing authorization and repository rules; track acceptance evidence. No delegation.

**Goal:** 保存实际结果版本绑定的人工反馈、外部处理记录、根因确认与恢复验证，拒绝无证据 resolved。

**Architecture:** 复用 InvestigationObservationDatabase 的 Session→Investigation 事务锁与 InvestigationAuthorization。反馈独立追加，不改写机器结果、不发布可信知识；状态修改、审计记录和 stream change 同事务提交。共享生产装配由父协调移交。

**Tech Stack:** Fastify / TypeBox / MySQL / Lit / Vitest / Playwright。

## 1. 专属契约与持久化

- 新建 `apps/db-ops-api/src/investigations/feedback-contracts.ts`：严格判别联合，rating、handling、root_cause、recovery、close，携带 resultId/resultVersion/expectedVersion，禁止客户端确认人字段。
- 新建 `feedback.ts`：复用事务与授权；只允许用户 operator 写，viewer 可读；绑定最新实际 result，检查 exact request/run evidence、过期和全部 scopes。确认人/时间由服务器记录。恢复验证窗口须被观测证据覆盖。相同 actor/key 重试返回同一记录，异载荷/版本冲突拒绝。
- 新建唯一 `120_investigation_feedback.sql`，正式 runner 自动发现；不可变 JSON 审计记录与 FK，不修改迁移 runner 或共享注册。
- `feedback-routes.ts` 局部注册 authenticated/no-store GET/POST；严格 body/header/query，错误不泄漏 SQL。server 注册等待父授权。

## 2. 安全与真实 SQL 验证

- `feedback.test.ts` 校验伪造身份、空证据、非法日期、无依据 resolved、根因与恢复分离。
- `feedback.mysql.test.ts` 用专属隔离 MySQL、正式迁移、真实 ActorContext/JWT/HTTP；并发同键、restart、rollback、版本冲突、旧结果、跨 Run 引用、撤权、成员过期、viewer/service 写拒绝、过期引用、恢复窗口及持久 stream/audit。
- 执行 `pnpm --filter slide-api exec vitest run src/investigations/feedback.test.ts src/investigations/feedback.mysql.test.ts`（配置 T11_TEST_MYSQL_PORT），要求零 skip。

## 3. 反馈专属 UI

- `frontend/src/app/ui/components/investigation-feedback.ts` 独立组件，复用表单/卡片/按钮 token，结果版本显式展示；局部 API 契约直接类型导入，公共生成文件待共享移交。
- 专属直接测试与 Playwright 夹具：真实 JWT/HTTP/SQL，组件提交与历史显示，冲突保留草稿，权限变化清空，明确人工确认不等于恢复。
- workspace 主容器挂载等待文件释放，不伪报生产接入。

## 4. 交付与停止条件

- 保留 40 样本/版本历史；复用已核验 runner，不调用 Provider，模型评分仍 unscored。
- 执行受影响模块检查、前后端 typecheck/build、契约检查。创建独立干净 PR，仅携带本任务文件，保留托管分支起始提交/用户修改。
- 当前 head CI 通过后交父独立 Review；共享装配/生产链路/40例模型评分缺口列明，部分交付 in_review，不宣称完整 T11 或 done。
- 无新 Issue、子代理、生产部署或外部模型请求。实际 token/费用遥测不可用。
