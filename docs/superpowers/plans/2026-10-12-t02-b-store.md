# T02-B 正式调查 schema/store 实施计划

> **Execution:** 遵循 MAX-143 已批准的 V1.1 方案及 v1.2 分阶段调度；不委派。

**Goal:** 将 #146 隔离事务内核转为可供 T03-B 消费的正式持久化模块。

**Architecture:** 沿用 SQL migration runner 自动注册 112；调查固定绑定现有 numeric-owner Session，外键禁止独立删除。事务内的可信授权端口接收完整资源集合；任何入口缺少授权端口均失败关闭。列表先逐项授权，再 count/分页。HTTP、Profile/服务主体、消息追加仍由后续阶段负责。

**Tech Stack:** TypeScript、mysql2、现有 OutboxService、Vitest、隔离 MySQL 8.4。

### 1. 迁移与真实夹具
- `apps/db-ops-api/sql/migrations/112_investigations.sql`：调查、资源、成员、请求、幂等键；Session 唯一/FK RESTRICT，用户 numeric ID；不复制 Chat 消息或 Run 状态。
- `apps/db-ops-api/src/investigations/store.mysql.test.ts`：使用完整 MigrationRunner 创建真实 schema，重复 run 不改 ledger；验证旧会话消息原 ID、100 同键、不同 payload 409、Session 活动请求唯一、SQL 故障回滚。
- 验证空 schema 升级和无破坏回退：无数据测试库可反向删除新增表；已有调查时旧版应用回退保留新增表和 Session FK，不执行生产 down。

### 2. CRUD 与授权查询端口
- `apps/db-ops-api/src/investigations/store.ts`：新增 create/detail/list/patch、资源及 owner 快照类型，保留 admission 返回值。
- create 在单事务创建或关联 owner Session、拒绝只读分享转换/已有 running Run/重复绑定；授权后写调查及资源。授权失败回滚新 Session。
- detail/read 和 list 按服务器端端口核验全部 scope；不可见 404，列表只过滤 404，不吞异常；过滤先于 count/limit，稳定 updated_at/id 排序。
- patch 锁调查，授权先于 expectedVersion 校验，标题/目标/生命周期白名单；活动请求禁止生命周期改动；不开放 resolved 声明。
- admission 保留 actor/key -> investigation 行锁和固定 hash；实时授权含所有资源，重试不免授权；创建 request/job/outbox 原子提交，不创建 Run/消息。

### 3. Chat 守护与验证
- `apps/db-ops-api/src/chat-database-service.ts`：仅 maintenance 清理排除被引用 Session；现有 deleteSession 事务由 FK 拒绝且回滚消息删除。
- 真 MySQL 测试证明 Session FK 删除拒绝、归档保留消息、版本竞争仅一个成功、资源部分授权不可见、撤权重试拒绝、授权异常不形成孤儿。
- `bash scripts/qualification/run-report-recovery.sh`：新增/既有 MySQL 测试 0 skip。
- `pnpm --filter slide-api typecheck`、focused lint、契约检查；更新 `docs/slide/ai-native-operations/t02-store-validation.md` 和 Review 对应条目，明确 T03-B 端口接法与未完成 HTTP。
