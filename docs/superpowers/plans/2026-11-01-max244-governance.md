# MAX244 模板治理完整流程实施计划

> **Execution:** 在既有授权及指定分支追加实施；禁止子代理。Chief 独立复核。

**Goal:** 固定单父继承→差异→灰度逐资源应用→失败保留旧版→重试/回退。

**Architecture:** 复用237模板发布与238配置应用服务。继承在发布时展开为不可变快照，保留固定基础版本及来源；绑定继续使用既有多模板冲突、参数覆盖和受限触发器校验。治理批次保存逐资源意图及稳定操作键，逐项执行既有probe/trial/apply，查询真实pending/applied/failed，回退也经同一试采与应用路径。

**Tech Stack:** Lit、Fastify、JWT、MySQL、现有metrics模板/绑定服务。

1. 核实237/238/239/240确切源码差异，仅整合237 authoring接口、schema、操作表和模板库入口；保留维护已接受源码，不覆盖240/241。
2. 扩展模板service/schema：单父最多3条继承边，按模板身份禁环；发布合并基础已发布快照与本地项/参数/触发器，显式同名覆盖，移除本地覆盖恢复继承。参数类型冲突拒绝。新增来源及版本差异，比较增删/语义单位/阈值/负载，投影授权影响资源。
3. 新治理service/routes：真实授权资源选择、不可变批次意图、逐资源基准revision、原键重放与未知恢复、部分失败；复用唯一binding服务和真实应用回执，不写fake applied。回退到批次保存的前版且检查当前revision，不实际解绑。
4. Lit入口：基础版本选择、来源/恢复、版本比较、影响/灰度选择、逐项回执/错误/重试/回退。主体/迟到响应隔离、确认、存储恢复与键盘焦点。
5. focused→模块→最终必要gate。真实Lit/Fastify/JWT及独占非3306MySQL；受控传输和fixture内正式采集仅声明对应边界。记录nonce/ID/PID/cwd/schema，验证清理。交源码SHA/安全发布SHA/对象审计/一次CI事实及剩余范围。
