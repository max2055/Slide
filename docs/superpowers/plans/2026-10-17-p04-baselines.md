# P04 语义行为基线实施计划

> **Execution:** 在已批准的 implementation-1.2 / B06 范围内执行，不派子代理；父任务独立审查后才允许合并。

**Goal:** 只消费正式 metrics 观测，生成可解释、可失效的日内/周基线版本。

**Architecture:** source-adapter 复用正式 store、catalog 和 aggregate，保留 source/version/epoch。calculator 实现 UTC 小时槽位、14/28 天窗口及最后 7 天时间外验证。store 使用 P01 schema，按当前身份/配置/rollout fence 校验缓存并保留历史；routes 仅导出 P10 注册入口。

**Tech Stack:** TypeScript、Fastify、MySQL、Vitest。

1. 新增 `operations/baselines/calculator.ts` 及测试：14/28 天、90% 覆盖、每小时至少 7 日期/3 周期、无插值、时间外独立、严重漂移与静态阈值并行。数据不足或无标注不声明改善。
2. 新增 `source-adapter.ts` 及测试：只读 `MysqlFormalMetricStore.queryWindow`，分块避免 1000 样本限制，复用 `aggregate` 的 gauge/rate；拒绝来源/单位/版本/epoch 混用、坏质量、未来时间、迟采和不安全整数。不修改 scheduler、告警或开关。
3. 新增 `store.ts`、`routes.ts` 及 SQL/HTTP 测试：P01 实时授权、资源范围、最终发送检查、配置/rollout/目标变化、过期和保留式撤入口。保存不可变版本与完整训练/验证元数据；不增加正式迁移或 server 注册。
4. 验证 focused tests → operations/metrics 受影响回归 → API typecheck / lint / contracts 必要 gate；真实 MySQL 固定只读状态查询经过既有正式采集/验真链再进入本适配器与 JWT/HTTP。合成 14/28 天边界与短时真实观测分别标注。
5. 提交并推送 MAX-197 PR，记录准确 base/head、CI、SQL/HTTP 证据和长期资格缺口；配置子任务 checks 接续，在完整交付后进入 in_review 由父独立审查。

停止条件：授权范围内工程及适用验收完成并交父审查；真实长期观测或标注缺失保持 unknown，由 P12 跟进。不调用产品 LLM，不进行 VM/helper/生产操作。
