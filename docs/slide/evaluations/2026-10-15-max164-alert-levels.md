## 语义与范围

现有 SQL schema、事件聚合排序和默认升级链表明：`info < warning < error < critical < p0`。
P0 为「紧急（P0）」，高于「严重」，保留原始 `p0`，不迁移或并入 `critical`。
列表、详情、等级筛选、等级统计、规则列表及升级规则编辑共用文案/徽章映射。
未知等级显示「未知等级（原始值）」及中性徽章，参与统计，并从统计原始键生成筛选项。
告警规则自身的 severity SQL 枚举仍为四级；不为它新增后端未支持的 P0 创建能力。

`GET /api/alerts` 增加 `level_counts`（原始等级 → 数量）。统计保持授权目标和当前状态范围，忽略分页和等级筛选；`total` 仍是筛选后的分页总数。原 `critical`、`warning` 字段沿用准确的独立等级含义。页面总量按完整分级数量计算，P0 不会遗漏。
等级选择发送 `level` 给服务端并重置页码；旧响应缺少 `level_counts` 时明确显示统计不可用。
严格读取失败返回错误；页面区分加载、错误/无权限及成功空数据，支持键盘重试。
