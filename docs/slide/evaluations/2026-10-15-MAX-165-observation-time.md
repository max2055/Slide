## 字段来源与行为

| 页面信息 | 来源 | 成功、失败及兼容行为 |
| --- | --- | --- |
| 详情成功读取时间（非资源观测） | 当前资源详情 HTTP 成功且 JSON 解码完成后的页面时钟 | 初次失败不产生成功时间；刷新 HTTP/网络/解码失败保留旧成功时间并提示失败；切换资源时清空；服务器旧上下文响应不能改写新资源。该时间只指详情信息，慢查询/会话另有自身读取时间，指标有自身的观测时间与读取错误。 |
| 每个指标桶的观测时间 | `SemanticBucket.observed_at` | 与聚合器原有 `freshness` 共用 `latest`，即有效输入中、该桶结束之前的最新 `observed_at`；不使用页面时间、查询窗口结束时间、配置 `updated_at` 或服务器状态检查时间。无有效输入返回 null；旧后端不提供该字段时显示未知，不推断一个时间。 |
| 新鲜 / 过期 / 未知 | 同一指标桶原有 `freshness` | 前端沿用服务端结果，不因页面刷新改写。不同指标、维度、历史桶分别展示，不用单个“新鲜”覆盖整项资源。质量、覆盖率及能力状态继续独立展示。 |
| 服务器最近状态检查（含失败尝试） | `servers.last_check_at` | `server-collector.ts` 在 SSH 连接成功、尚未读取指标时就会更新该字段，连续失败判定不可达时也更新；因此不再称为“上次采集”。无记录显示“尚无检查记录”。 |

顶部刷新在详情成功后，也读取当前挂载的标准指标组件。指标读取失败继续使用该组件已有的保留/撤权清除语义；不会把指标观测时间改成详情读取时间。详情刷新失败仍沿用 MAX-163 的查询失效处理，401/403 隐藏已展示的详情；未改变慢查询/会话来源、窗口、严格报错、撤权及迟到保护。

新字段是可选、可空的附加响应字段；没有更改请求或原有指标值、新鲜度计算。契约检查通过。

## 浏览器与真实服务证据

最终使用 Chromium、生产 Lit 详情组件、隔离 Fastify/Vite 和专用 MySQL 8.4 容器。测试启动和结束均在同一前台调用内收集；使用随机 schema 并清理，所有代理路径（含 `__slide` 配置读取）指向隔离服务。未部署、重启共享服务或操作共享绑定。

新增观测时间流程经过真实 JWT、实时 SQL Actor、MySQL 策略存储、生产 `MetricConsumerService`、MySQL 正式发布存储与生产聚合器。私有测试绑定仅为该随机 schema 内的夹具，没有启动调度器。实例值来自测试容器实际 `SHOW GLOBAL STATUS LIKE 'Uptime'`；主机文件系统值为明确标注的受控规范化样本，没有 SSH 实机采集。过期通过受控服务/浏览器/写入时钟实现；新鲜样本的时间也由夹具控制，不声称等待了十分钟或发生了在线重采集。

| 状态 | 两类详情页的验收 |
| --- | --- |
| 成功有数据 / 过期 | 持久化并正式发布旧观测；页面显示原观测时间和过期。焦点 + Enter 刷新后，详情成功读取时间推进，指标观测时间保持原值且仍为过期。 |
| 加载 | 延迟详情响应期间刷新按钮禁用；成功读取时间不推进。 |
| 失败 | 详情返回 500 后提示成功读取时间未更新；保留上次成功时间。网络、JSON 解码及初次失败另有单测。 |
| 新鲜 | 发布新的受控观测后刷新，实际观测时间与新鲜度一起变化。 |
| 无观测 / 未知 | 删除私有夹具中的正式发布记录后刷新：不显示时间元素，指标值、时间及新鲜度均保持未知，不以 HTTP 成功推断采集成功。 |
| 无权限 | 指标 403 清除指标时间和值；详情 403 隐藏详情组件。MAX-163 真实撤权路径另行通过。 |
| 主题、窄屏、键盘 | 1280×900 深色、390×900 浅色，两类页面均通过；无 pageerror，无页面级横向溢出。现有长指标列表保留；截图分别保留顶部与实际观测桶，避免缩小整张长图造成时间证据不可读。 |

`detail-observation/` 内 `*-fields.json` 记录 `sampledAt`、服务端 `evaluatedAt`、`browserClockAt`、`freshAt`、两次成功详情读取文本及数据来源；`*-observed.png` 是实际观测桶，不是重新绘制的示意图。`instance-query-acceptance/` 为最终 MAX-163 回归，`max165-baseline-query/` 为修改前集成基线补验。异常受控截图与真实 MySQL 数据截图以文件名区分。
