# MAX-41 字体与图标可读性优化

## 范围与验收

- v1：对比 Slide / GitLab 菜单截图，定位菜单辅助色、透明度和描边问题；已交付分析，无代码修改。
- v2：根据用户“整体排查此类情况，并进行优化”，扩展至前端全站同类颜色问题。扫描 `frontend/src` 的 CSS、Lit 样式与内联颜色；修复共享机制与确认的具体用法。
- 排除：布局重做、业务行为调整、图标库更换、部署、用户已保存的自定义配色强制迁移。
- 验收：默认浅色/深色主题下，常用中性底色上的正文、辅助文字和链接达到 4.5:1；菜单图标达到 3:1；主题切换、默认/悬停/焦点、折叠与移动端键盘抽屉路径可用；前端单测、类型、构建和相关浏览器门禁通过。
- 停止条件：上述验收完成并提交审阅；不因无关问题扩展范围。
- 硬预算：未设定。子代理：0，最大深度 0，仅主线程。实际 input/cached input/output token 和费用遥测不可用，不提供虚构数值；本轮与上一轮均未设置 Goal token 账本。

## 排查及修复

| 问题 | 改动 |
| --- | --- |
| 普通菜单误用辅助灰色，图标额外 72% 透明度 | 菜单使用 `--text`，图标不再额外透明，描边 1.5 → 1.75；折叠箭头与顶部操作图标同步修正 |
| 浅色辅助文字在灰色表面余量小；深色正文与辅助文字偏暗 | 浅色 `--muted` 改为 `#606068`；深色正文 `#d4d4d8`、辅助文字 `#a1a1aa`；保留标题/正文/辅助层级 |
| 亮蓝色直接作为小字和图标前景 | 新增 `--accent-text`，浅色由品牌蓝混合黑色获得较深前景，深色沿用亮蓝；迁移菜单选中图标、页签、链接、聊天工具和设置入口的前景声明，背景/边框仍使用品牌蓝 |
| 白字在默认亮蓝按钮上不够清楚 | 蓝色按钮使用深色前景 `#10243a`；危险/成功按钮独立使用与底色匹配的前景 token；外观设置默认预览同步更新 |
| 状态标签硬编码亮黄、绿、红或固定浅底 | 日志、查询分析、索引、告警、报告和用户角色改用主题语义色；加深浅色语义文字，补齐深色 warning token |
| 文字/操作图标重复降低透明度 | 修正表格排序、搜索图标、时间戳、工具摘要、命令参数、配置占位、提示与展开箭头；保留禁用、动画、空状态装饰的弱化 |
| 表单提示硬编码 `#999`，默认占位灰在深色下偏暗 | 提示用 `--muted`；提取共享 placeholder 样式，应用全局 Light DOM 和 34 个采用共享样式的 Shadow DOM 表单视图/组件 |
| Canvas 图表不会继承 CSS，坐标灰色固定 | 坐标、图例、提示框采用主题 token，观察主题切换更新图表，组件移除时断开观察器 |

共享入口：`frontend/src/app/styles/tokens.css`、`layout.css`、`shared-field-styles.css` / `.ts`、`shared-btn-styles.ts`、`shared-resource-toolbar-styles.ts`。
具体组件：`app-form-field.ts`、`app-card.ts`、`metric-chart.ts`；其余为现有视图内的颜色替换及共享表单样式接入。

- 本次未部署，也未读取测试环境真实数据库。截图来自本地运行源码/模拟数据，不能代替部署后验收。
