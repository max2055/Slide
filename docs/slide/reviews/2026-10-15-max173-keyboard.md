# MAX-173 / UI-021 键盘语义验收

2026-10-15。基线 `cd477da3b3efb16f73a221aa7cc4305eeee14856`（最新审定 main，包含 MAX-165、MAX-168、MAX-172）。独立 `codex/MAX-173-keyboard` 分支；产品改动提交 `134407a5`，交付 head 以 PR/任务评论为准。

## 范围与修复

- `app-data-table.ts`：原生排序按钮负责 Tab / Enter / Space，表头使用原生 columnheader 及 `scope=col`；仅当前启用排序的列带 `aria-sort=ascending/descending`。方向图标对辅助技术隐藏，按钮名称保持为列名称。表头整块鼠标点击、原有事件载荷及帮助按钮保持兼容。
- `appearance-settings.ts`：颜色预设改成 `type=button`，名称复用现有双语颜色文案，`aria-pressed` 表示当前匹配的颜色；自定义颜色不匹配预设时全部未选中。选中环与焦点环分开，沿用主题 token。保存路径与事件不变。
- 原有 `sortable=false` 的列无排序按钮且不能排序。加载时排序原本仍允许鼠标触发，本次保持该行为并让键盘一致；没有增加另一套禁用规则。颜色预设是个人偏好，原组件没有权限禁用规则。

## 定向复现与验证

修改产品代码前，在当前基线运行新增组件测试：2 项均因原有无按钮语义失败。Chromium 运行表格用例，也因找不到名称为“名称”的排序按钮失败；RED 提交 `4632a297`。修复后相同单测与浏览器用例通过。

| 验收 | 证据与结果 |
|---|---|
| 表格键盘与鼠标 | Tab 从表格前按钮进入排序，再进入独立帮助，再进入第二排序按钮，最后离开表格；Enter 升序、Space 降序，每次恰好一个事件。鼠标表头仍能排序，非排序列点击无事件。 |
| 帮助隔离 | 帮助按钮的 Enter、Space、鼠标点击各触发一次帮助，不触发排序。 |
| 空/加载/失效 | 真实组件的受控行数据、有数据→空/加载、非排序列及移除 sortable 配置，保持键盘/鼠标一致；排序状态不落在已经取消排序能力的表头上。 |
| 预设正常/空/加载/失败/无权限 | 真实应用路由 `/settings/platform/appearance`，受控 API/auth/WebSocket；分别为正常偏好、空对象、延迟 GET、503、403/无权限。Enter/Space/鼠标、pressed、本地持久化、切语、刷新均通过。 |
| 未匹配颜色 | 存储 `#123456` 时所有预设未选中；显式选择后仅匹配预设选中，切语不产生额外设置事件。 |

| 视觉 | 1280×720 的浅/深色表格焦点；1280×900 的真实服务预设焦点；390×900 的深色预设选中/焦点，无横向溢出。深色窄屏用例显式加载主题 token，属于受控主题验证。 |

## 真实业务服务验证

`bash scripts/qualification/run-keyboard-ui.sh`：独立临时 MySQL 8.4、当前 Fastify、JWT 与 Vite，不连接共享平台数据库，不调整共享服务，不调用产品模型。测试完成自动清理容器/服务。

1. 真实登录 admin，真实权限与偏好 HTTP；Tab / Enter 选青色，收到 PUT 200；Tab / Space 选翠绿，收到 PUT 200。
2. 切换中文收到 PUT 200；GET `/api/user/preferences` 实际返回 `accentColor=#34d399`、`locale=zh-CN`。
3. 刷新保留按钮 selected/名称；新建无本地偏好的浏览器上下文，从真实服务读取设置，刷新后仍为翠绿/中文。
4. 真实服务浏览器无 pageerror，AX 树和截图已生成。使用仓库本地 Provider 启动 fixture，仅满足启动依赖，无推理请求。

当前没有业务页面设置共享组件的 `sortable`，因此排序验收是**真实组件 + 受控数据的 Chromium 验收**，不宣称真实后端排序业务已实现。共享表格没有失败/无权限输入；这类状态由消费页面负责，未为本题制造新状态 API。外观 403/503 为受控失败：按现有设计仍可保存本地偏好，`aria-pressed` 表示当前应用颜色，不代表远端同步成功。本题没有修改原有同步失败提示策略。
