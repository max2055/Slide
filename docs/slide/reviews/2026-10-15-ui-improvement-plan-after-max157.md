### R01 · 运维状态与事件契约

**目标：** 先让事项、通知、慢查询、会话、告警等级与观测时效表达可信。

事件/关注事项：统一 ID、时间和等级契约；成功空、读取失败、权限不足分别表达。历史 p0/error 等值先核对来源与映射，不能仅将颜色改成红色。失败不推进成功读取时间。

资源观测：把页面读取时间、最近采集时间、历史健康结论分开；慢查询和会话无数据只说明对应时段无记录，不推断资源健康。保留未知、过期和部分证据。

验收：数值/字符串 ID、相同时间事件、历史等级、正常空返回、401/403/503/断网、先成功后失败和旧数据场景均有明确结果；刷新不把旧观测变成“刚刚采集”。

**依赖与边界：** 无原型依赖；等级兼容映射须先依据真实契约与历史数据确定。


### R02 · 共享表单与键盘可达性

**目标：** 字段名称、提示、错误与真实控件关联；排序和主题选择可用键盘。

明确实际控件的可访问名称、帮助和错误关联；解决 Shadow DOM 标签跨边界的问题，不能只给视觉 label 加一个 for 就宣布完成。表头保留列语义，以原生按钮或等价方式支持排序；主题选项有名称和选中态。

验收：消费页实际可访问树能读出名称与错误；Tab/Enter/Space、焦点可见、弹窗关闭/恢复正常。只验证组件实现不能替代调用页面。

**依赖与边界：** 与设计并行；影响 R2 消费页时只作组件回归，不重新设计这些页面。


### R03 · 文案、单位、历史数据和旧入口兼容

**目标：** 消除路由变量、模糊空字段、比例单位和登录提示矛盾，处理旧书签空壳。

文案与格式保留真实值：默认页面选项展示用户术语、存储仍用原路由值；SQL 审核缺失字段说明历史记录未保存/未知，不编造 SQL；权重 1 与 100% 统一显示但不改存储契约；登录必填、按钮动作和错误文案与 JWT 流程一致。

旧 /config、/llm-usage 先核实其含义和权限。存在等价目标时跳转并保留前进/后退；没有等价目标时显示清晰停用说明和去向，不将旧 Gateway 数据静默等同于新调查账本。

验收：新旧记录、中文/英文 fallback、未识别枚举、100%/超限/不足、旧书签与无权限均有检查；不更改业务枚举或财务口径。

**依赖与边界：** 旧用量/配置入口先核实语义；不等价时说明停用和去向，不强行跳到含义不同的新页面。


### R04 · 标准长列表的查找与浏览边界

**目标：** 表结构、索引、旧指标目录、权限目录、报表历史可查找、排序和分批浏览。

使用现有检索、稳定排序、页长/分页或加载更多模式，明确当前已载入条数和总数。筛选变更重置页码，返回保留上下文。不能对远端部分数据作前端筛选后声称是全量结果，也不为美观扩大成新的搜索后端。

验收：100+ 表、数百索引和长权限/报表数据可定位指定项，窄屏表格局部滚动；原筛选不退化。没有真实大数据时使用标注的受控数据，并补现有真实服务的基本流。

**依赖与边界：** 不包含已完成的源码/治理分页；若改动为列表＋复杂详情新结构，转入对应原型包。


### R05 · AI 工作空间引导与调查创建

**目标：** 空调查有明确起步点，有数据时仍能高效查看执行、证据与成果；资源按名称选择。

无调查时，主工作区提供目标说明、创建入口及所需输入，筛选和空证据区域降级；有调查时保留导航、执行协作、证据成果的职责，筛选无结果与真正首次使用分开。

创建/筛选复用有权限资源清单，按名称/类型检索，多选后明确边界；高级 ID 输入保留。资源可见不代表可执行，提交仍实时校验。避免扩大为新的调查引擎或全新产品首页。

原型验收：空/有数据/无匹配、资源长名称、多选、资源失权/不可用、提交未知和窄屏均可说明；开发正常流用真实资源与服务验证。

**依赖与边界：** 沿用调查数据、权限、边界和未知提交保护；与已完成的跨资源诊断页面分开。


### R06 · 资源详情中的指标与日志效率

**目标：** 压缩公共调查关系区；对象、时间、筛选、图表/日志优先；概览/指标/接口职责分清。

资源头部紧凑展示名称、真实时效、调查数量/状态与入口；无调查时不保留大空卡。进入指标/日志立即看到时间范围、筛选和核心数据。概览承担关键状态与风险摘要，指标承担查找比较与趋势，接口承担接口维度；现有能力不足时合并或解释，不虚构图表。

日志保留全文展开、级别、时间、分页和连续操作；指标保留定义与原值详情。数据库日志与指标先接入，验证后推广服务器/网络。数据库大小说明和跨资源诊断 R2 不进入本包。

原型验收：桌面与 390px 首屏可找到对象/时间/核心筛选；有/无调查、长日志、多维指标、空/过期/失败均不遮挡主要工作区。

**依赖与边界：** 依赖 R01 的真实状态口径；不重做资源列表大小说明或 R2 跨资源诊断。


### R07 · Agent 清单与审批历史的信息层级

**目标：** 列表先给名称、用途、状态、时间和摘要；UUID/路径/JSON/全文按需查看。

工具主表突出用途、读写/副作用、审批/授权限制；会话突出可读标题、状态与最近活动；技能突出用途和适用范围。完整 JSON、Schema、路径、UUID 与原始 role 可查找、复制和追溯。

审批历史突出目标、风险、审批与执行结果、时间和短摘要，全文进入详情。待审批的决策必要信息保持可见，不能为了缩短界面隐藏风险内容。四类页面复用规则，仍按各自权限和数据能力实现。

原型验收：工具与审批两个代表样本使用长内容和多条记录；主列表行高稳定，详情完整，检索/翻页/返回上下文明确，键盘能到达详情。

**依赖与边界：** 复用 R02、R04 的基础能力；R07 对自己的清单/详情拥有实施范围，不由 R04 重复改造。


### R08 · 设置表单与平台观测分组

**目标：** 模型基础连接、模型清单和高级参数分层；品牌按任务分组；平台观测呈现可读状态摘要。

模型配置区分连接设置、模型清单、当前模型详情与高级能力/计价，保持保存作用范围和未保存状态明确。一个模型和多个模型均可操作；不删除真实高级配置，不将 API Key 或其他凭据放到设计示例。

品牌设置按一个配置任务分组，避免四个字段各一张重复重卡；平台观测先给版本/运行/日志/信号摘要，再给原始标识和排查详情。无信号、未知、未开启和读取失败分别表达。

原型验收：基础配置无需读完所有高级字段；默认模型/参数来源/未知价格可辨认；保存与错误位置稳定；平台未知不变健康。已完成的 Profiles/策略/预算/用量继续沿 R2。

**依赖与边界：** 沿用全部真实配置能力；平台观测的读取失败表达不依赖美术完成；不改已完成的四个调查治理页面。


### R09 · 文档窄屏补验与全站视觉规则

**目标：** 验证文档 390/768px 风险；建立页面角色、字体/间距/表格/操作权重规则和覆盖矩阵。

从已交付 R2 提炼页面角色、标题与正文、外边距/组间距/组内间距、表格扫描、主/次操作和语义色规则。先在代表原型中确认，再按页面角色复用；不要求所有页面相同宽度，不整体放大运维表格，不靠换字体/主色/渐变创造“高级感”。

文档先在 390/768px 核验目录、正文、代码/表格/流程图。风险成立再采用窄屏目录抽屉/选择器和局部滚动，桌面阅读结构保留；无问题就记录证据，不凭静态命中创建强制改造。

全站覆盖矩阵保留正常对话、已填充调查、网络设备、查询/日志、权限和主题的未测项。补验发现的新问题先归类；不要把“缺少截图”直接等同于产品缺陷。

**依赖与边界：** 已交付 R2 作为参考；不以统一为由全局改 token 或重排 R2；覆盖缺口不是自动成立的新缺陷。

## 6. 原型先做什么，做到什么程度

先制作四组代表原型，不先给全站每个页面各画一套：

| 组 | 必须展示的样本 | 解决的设计决定 |
| --- | --- | --- |
| P-A 引导型 | AI 工作空间空态/有数据、创建调查弹窗 | 起步焦点、三种工作职责、资源选择和调查边界 |
| P-B 效率型 | 数据库日志、指标、紧凑资源上下文 | 首屏分配、调查入口、筛选/数据、概览与详情职责 |
| P-C 清单与详情 | Agent 工具、审批历史及详情 | 摘要字段、技术原值、操作权重、长内容和返回上下文 |
| P-D 设置与概览 | 单/多模型编辑、品牌分组、平台观测 | 基础/高级分层、表单宽度、业务分组、状态摘要 |

P-A 与 P-B 优先讨论；P-C 与 P-D 随后。文档风险若复现，再补一个 390/768px 适配样本。字体、间距、表格、按钮规则随这些原型形成同一版设计说明，不单独开展无界“设计系统重构”。

优先用现有 Lit 组件和主题 token 做可操作原型，演示数据明确标注；页面截图负责讨论构图，原型负责检索、分页、展开、错误与返回行为。原型不连接真实模型、不保存配置或权限，不拿演示图表冒充已实现能力。

讨论确认的对象包括：首屏内容和主要操作、分组与宽度、摘要/详情分界、长数据浏览、正常/空/失败/受限等适用状态、窄屏与明暗主题。确认后将设计版本、说明、截图、交互和可访问材料附到开发任务，不依赖聊天回忆。

## 7. 三种推进方式的取舍

| 方式 | 好处 | 风险 | 建议 |
| --- | --- | --- | --- |
| 确定缺陷直接建单，布局先原型；两线并行 | P1 不等待设计，布局有明确依据，减少返工 | 需要明确每个包的归属和依赖 | **推荐** |
| 所有内容直接建开发任务 | 建单最快 | “优化”“精致”等词仍留给开发猜测，容易重复此前的粗糙交付 | 不建议 |
| 所有问题等全站原型确认后再建单 | 视觉材料较完整 | 排序、错误状态、键盘和文案等确定问题也被延迟；全站一次设计范围过大 | 不建议 |

R01–R04 可直接形成确定修复任务，覆盖 13 条原问题；R05–R08 的 8 条原问题及新增布局建议先进入原型；UI-017 先补实测。这是建单准备度的划分，不是新的缺陷优先级。

如果希望现在就有完整跟踪结构，可以先建“全站 UI 质量完善”主任务和设计子任务，再给 R01–R04 建实施子任务；R05–R08 等原型确认后建立或完善开发子任务。建单与启动是两个动作，不因为分配/模板默认值意外启动。不要重开 MAX-157，也不要将剩余范围全部追加进已完成的任务。

## 8. 实施顺序、依赖与防止返工

1. **缺陷线先启动 R01，R02/R03/R04 按边界推进。** R01 内事件与资源观测分别交付；R04 与后续页面改造分清归属。布局原型同时推进 P-A/P-B。
2. **确认首批原型和角色规则。** 用 R2 作为既有产品参考，不改变 R2 的已确认决定；整理新的页面设计说明。
3. **每类先接入一个代表页。** 引导型接工作空间，效率型接数据库日志/指标，清单型接工具/审批，设置型接模型配置。真实数据对照通过后推广，不批量复制尚未验收的布局。
4. **按原问题编号关闭。** 一条问题只能有一个主实施归属；设计主题可跨包验收。后续发现额外问题先判断与验收关系，不顺手扩大到 Agent 架构、模型质量、全库重构或性能工程。
5. **最后按页面族补齐集成证据。** 共享改动触达的 R2 页面需回归；其原设计不重新制作。

## 9. 交付门槛

- **功能与事实：** 真实服务完成适用的正常业务流；未知/失败/过期不伪装健康；权限、历史兼容、未知提交/重复提交保护不退化。
- **视觉：** 对照已确认设计版本，逐页留当前 Commit、视口、主题、数据情景的截图；检查信息层级、间距、字号、文案、操作、详情与分页。真实内容适配可调整，实质偏离先说明。
- **内容韧性：** 长中文/长路径/JSON/SQL、多条数据、无匹配、分页边界；代码和表格局部滚动，无全页非预期横向溢出。
- **状态与权限：** 覆盖页面适用的正常、空、加载、失败、受限、未知/过期/部分/冲突；包括先成功后失败、权限变化与延迟响应。特殊状态可用受控数据补充，标明来源。
- **可达性与主题：** 桌面、390px 和相关中间断点；明暗及用户强调色；字段名称、Tab/Enter/Space、Esc 与焦点恢复。
- **代码检查：** 开发阶段 focused checks，模块边界测试，最终受影响集成 gate；契约变化运行 contracts:check。CI、构建、健康探针均不能替代视觉和真实业务验收。
- **任务材料：** 每个 Issue 写明原 UI/VIS 编号、唯一范围、依赖、可访问设计版本、验收和证据。不把全部三份材料机械复制进每个任务，不重复计算问题数。
- **产品模型预算：** 用户已澄清 10,000,000 token 仅约束 Slide 产品内 deepseek-flash 测试，不是编码、建单或审查预算。相关产品测试沿用 MAX-155 同批实时累计账本；缓存输入不重复计数、未知发送不盲重放、50%/80%/100% 动作不变。先核实实际模型与累计，不以编码遥测或某个子任务的历史用量当整批产品测试基线。本次方案整理未发起产品模型测试。
