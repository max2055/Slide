## 3. 具体问题与优先级

| 优先级 | 问题及证据 | 改造决策 |
| --- | --- | --- |
| P0 | 截图顶部“数据时间”为 9 月，风险观测为 7 月，刷新与观测新鲜度容易混淆 | 页头改为“快照更新”；资源保留“最近观测”绝对时间与过期标签；采集质量摘要上移。刷新不暗示资源已恢复 |
| P1 | 页头、独立按钮式 Tab、筛选各占一排；搜索和引擎筛选中间大块空白 | 标题行下使用紧凑 Tab 与筛选工具栏；保留可见字段标签；控件填满自身容器，搜索与引擎相邻 |
| P1 | 四张 KPI 外观完全一致，看不出哪里需处理；`renderKpis` 未使用 `stat-card.variant` | 维持四列，但统一较紧凑圆角和高度；风险非零时使用语义变体，零值与未知保持中性；数字使用等宽数字；提供筛选选中反馈 |
| P1 | 风险行中名称、状态、时间和三项动作逐行堆叠，右侧留白；`.risk-row` 仅是纵向 grid | 风险队列改为对齐的紧凑双行列表；第一行对象、运行状态和入口，第二行告警、观测与关联；运行状态和采集状态分组呈现，避免两个橙色标签混在一起 |
| P1 | 默认 `selectedRisk` 为空；关联面板固定显示提示语 | 未选中时只保留简短引导；“关联资源”按钮选中后展开摘要并高亮来源行。明确“未选择 / 无关联 / 查询失败”三种不同状态 |
| P1 | 服务器只有一条风险，但下一行专业指标被右侧两张卡整体推低 | 将采集质量放入紧凑右侧面板；未展开关联时缩短侧栏；专业模块按视图成组排布，避免无内容面板撑高主区 |
| P1 | 网络设备空态文字与通栏“纳管资源”按钮分离，缺少明确中心 | 使用 `app-card` 包住图标、空态说明和正常宽度的主按钮；描述接入后可查看的观测；动作仅对已有管理权限显示 |
| P2 | 健康条粗重，四个状态按钮各有彩色下划线，信息重复 | 使用细分布条与紧凑图例，保留可点击过滤；未知与未纳管使用中性表达，不给零资源画健康比例 |
| P2 | 普通按钮、输入边框接近正文深度，控件视觉权重过高 | 默认用 border token，hover/focus 增强；蓝色只强调选择和动作，红橙绿只表达真实状态 |
| P2 | 卡片 header 中“查看全部”紧跟标题 | 总览内 slotted header 占满可用宽度，使标题与操作左右对齐 |

截图呈现偏紫色，但源码默认 `--accent` 是蓝色，页面使用其混色衍生值。实施时必须检查运行时主题偏好和实际 CSS 变量；目前不能直接断言源码写死了紫色。

## 4. 方案比较

| 方案 | 改造幅度 | 收益与取舍 |
| --- | --- | --- |
| A. 样式精修 | 小 | 调整边框、字体、间距；风险低，但对象交互与低效布局改善有限 |
| **B. 紧凑专业操作台（推荐）** | 中，限定在总览与必要共享组件能力 | 统一工具栏、KPI、对齐风险列表和关联检查区；直接改善首屏利用率与处理路径 |
| C. 深色全屏指挥中心 | 大 | 视觉辨识度更强，但牵涉全站主题与多屏布局，当前六个资源及稀疏观测不足以支撑大量图表 |

选择 B。浅色与深色均跟随用户现有设置，不强制切换主题。Palantir 风格主要落实为工作流、布局和密度。

## 5. 设计稿：结构与视觉规格

以下是布局线框，不是已完成页面；示例数量来自用户截图。

```text
运维总览                                    快照更新：…  [刷新]
综合态势  数据库  服务器  网络设备        搜索资源 […]  引擎 […]
─────────────────────────────────────────────────────────────
纳管资源 6       异常资源 5       未解决告警 7       采集异常 5
─────────────────────────────────────────────────────────────
风险队列 · 5                  查看全部 │ 运行状态分布
资源 / 运行状态                操作    │ 数据库  1 正常 / 4 异常
服务器 #3 · 不可用            查看证据 │ 服务器  1 不可用
观测过期 · 最近观测 … · 关联 0         │ 网络设备  未纳管
───────────────────────────────────── │ ─────────────────────
test-audit-name · 异常         查看证据 │ 采集质量
2 条未解决告警 · 观测过期 · 关联 0     │ 有效观测 1 / 6
…                                     │ [展开缺口]
                                      │ 关联摘要（选中后展开）
─────────────────────────────────────────────────────────────
当前视图的专业指标 / 趋势
─────────────────────────────────────────────────────────────
资源明细                       当前筛选：… [清除]     分页
```

- 标题维持产品页尺度，不引入大幅 Hero 或宣传文案。正文采用现有字体；资源地址、时间和数字使用等宽数字或已有 monospace token。
- 桌面控件视觉高度约 32–36 CSS px；触屏点击目标至少 44 CSS px。主要正文约 13–14 CSS px，辅助信息不能靠过小字号实现密度。
- 使用现有 `--space-*`、`--radius-*` 与颜色 token。面板和 KPI 倾向 `--radius-sm`，页面内部层级主要靠分隔线与背景。尊重用户圆角设置。
- 四张 KPI 桌面同一行，视觉高度目标约 88–104 CSS px；采用 `stat-card` 的局部样式接口。不会为整数计数添加无依据的趋势箭头。
- 主区桌面约 2:1；风险双行每项目标约 64–80 CSS px，长名称允许扩大行高而非裁掉操作。平板改上下排列；小屏风险条目有标签并自动换行。
- 交互只使用短暂 hover、focus、selected 变化；不使用循环发光、漂浮卡片或装饰动画。
- 名称仍链接到资源详情；“查看证据”和“只读诊断”保留既有语义。关联选择有独立按钮和 `aria-pressed`，不让整行点击与内部链接冲突。浏览、切 Tab、选风险均不触发诊断请求。
- 数据量极少时面板自然收缩。未知、过期、无权限、加载失败各自有明确文案，不把缺数据填成 0。

## 6. 四个视图的差异

| 视图 | 专业区布局 |
| --- | --- |
| 综合态势 | 风险队列为中心；右侧三类资源状态与采集质量；关联选择展开真实对象摘要；下方跨类型明细 |
| 数据库 | 紧凑引擎分布与现有容量趋势组合，之后是指标排行与数据库明细；保留容量图局部实例/时间筛选 |
| 服务器 | 状态摘要压缩；CPU / 内存 / 磁盘现有排行上移；只有过期数据时直接说明有效观测不足 |
| 网络设备 | 有资源时显示现有设备排行与最近备份摘要；未纳管时展示完整接入空态，不展示四张零 KPI 和无意义图表 |

## 7. 代码落点与兼容性

- `frontend/src/app/ui/views/dashboard-styles.ts`：页头、Tab、筛选、风险列表、图例、响应式、选中状态。
- `frontend/src/app/ui/views/dashboard.ts`：局部模板分组、KPI 变体、采集摘要位置、关联展开、空态动作组合；保持数据模型与请求边界。
- `frontend/src/app/i18n/locales/operations-overview.ts`：更新快照/观测区分与必要的状态文案，完整覆盖已有语言。
- `stat-card` 已有 `variant` 与 `part="root"`，优先复用。若必须增加紧凑样式接口，默认行为不变。
- `app-card` 的 Shadow DOM 不能被页面普通选择器穿透；必要时只补通用、默认值兼容的 CSS part 或自定义属性，再由总览设置。
- `app-empty-state` 当前使用 Light DOM 却含命名 `<slot>`；不能直接假设其 actions slot 可投影。此次优先在总览空态容器内组合现有空态和按钮，不顺带做影响全站的 Shadow DOM 迁移。
- 风险区保留语义化 article 列表，使用 grid 对齐。资源明细继续复用 `app-data-table`；不用手写第二套数据表。
- 实施前核对当前运行服务的端口、PID、cwd 与分支，避免将其他工作树或旧构建当成本次效果。

## 8. 验收清单

以下是实施后的验收要求；本次尚未执行，不代表已通过。

1. 五个尺寸：1280×720、1440×900、1920×1080、768×1024、390×844。页面无横向溢出；桌面四 KPI 一行；1280×720 首屏显示完整 KPI 与首条风险。
2. 相同 1440×900 测试数据下，首屏应同时容纳五条普通名称风险、状态分布与采集质量摘要；长名称场景允许增高，但全部操作可访问。
3. 四个视图各有截图；浅色与深色分别验证。普通文字与链接对比度至少 4.5:1；不通过改变真实数据美化截图。
4. Tab 键盘切换、搜索、引擎过滤、KPI/状态下钻、关联选择、证据入口、只读诊断入口及返回状态均可用。
5. 已选风险高亮与关联摘要一致；筛选使对象不可见时正确清空。无关联和关联查询失败不得混淆。
6. 网络设备空态动作尺寸正常且遵守管理权限；无权限、请求失败、筛选无结果与未纳管不得共用误导文案。
7. 顶部刷新时间不能取代观测时间；采集过期仍可辨认。指标未知/过期/不支持不画成正常曲线；不新增自动分析请求。
8. 开发阶段只跑受影响检查；最终候选统一运行前端门禁。若共享组件发生相关变更，追加该组件现有回归；无关既有失败单独记录，不扩张范围。
