Slide 运维部署

本文档说明当前的本地与生产运行模型。Slide 后端启动后会获取 Worker lease；只有持有 lease 的副本会启动采集、告警、工作流和 Agent 服务。未持有 lease 的副本仍可提供 HTTP API。

系统概览

组件默认端口说明
前端开发服务器5173Vite 开发服务器，生产环境构建为静态资产并由反向代理托管。
后端 API3000Fastify REST API、认证、控制面和文档接口。
Agent WebSocket28888DirectAdapter 传输层，必须先通过 JWT 认证；不再使用外部 Gateway。
MySQL 控制面3306存储用户、权限、实例、指标、告警、任务和审计数据。
受管数据库按类型支持 MySQL、PostgreSQL、Oracle、达梦；由目标地址策略限制可连接范围。

部署架构

附件 2：运维闭环。持续采集形成可观测数据，告警与事件驱动人工和 AI 协同处置，执行结果回写审计与报告。

flowchart LR
  Browser[浏览器] --> Proxy[HTTPS 反向代理]
  Proxy --> UI[前端静态资产]
  Proxy --> API[Fastify API :3000]
  Browser -->|受控网络内 WS| Agent[DirectAdapter :28888]
  API --> MySQL[(MySQL 控制面)]
  API --> Targets[(受管数据库)]
  Agent --> LLM[LLM 提供商]

生产环境建议将 MySQL 控制面和受管数据库置于私有网络，将 API 和 Agent WebSocket 放在受控入口之后。不要把 28888 直接暴露到公网；通过防火墙、反向代理或私网访问限制 WebSocket 客户端来源。

前置条件

  • Node.js 20 或更高版本，以及 pnpm 10。
  • 可访问的 MySQL 控制面数据库，并允许服务账号创建或迁移应用表。
  • 使用 AI 功能时，在 LLM 设置中配置并启用一个提供商，或提供 ANTHROPIC_API_KEY 作为回退。
  • 生产环境使用 HTTPS、独立服务账户和受限网络策略。

配置项说明

后端读取 apps/db-ops-api/.env。控制面数据库实际使用 DB_HOST、DB_PORT、DB_USER、DB_PASSWORD、DB_NAME；示例文件中的 DATABASE_URL 不是当前运行时的连接配置。

变量用途生产要求
DB_HOST、DB_PORT、DB_USER、DB_PASSWORD、DB_NAMEMySQL 控制面连接使用专用账号和最小权限。
BACKEND_PORTHTTP API 端口，默认 3000也可使用 PORT 或 API_PORT 覆盖。
AGENT_WS_PORTDirectAdapter WebSocket 端口，默认 28888限制网络入口。
JWT_SECRET_KEYJWT 签名至少 32 字符，不能是默认值。
ENCRYPTION_KEY实例和提供商凭据加密必须为恰好 32 字节的 UTF-8、64 位 hex 或有效 base64；不得与 JWT 密钥相同。
INITIAL_ADMIN_USERNAME、INITIAL_ADMIN_PASSWORD初始管理员NODE_ENV=production 时必需。
DB_ALLOWED_CIDRS、DB_ALLOWED_PORTS受管数据库目标允许范围按实际网络和端口收窄。
CORS_ORIGINS允许的前端来源只设置生产域名。
SESSION_RETENTION_DAYS、SESSION_MAX_MESSAGESAgent 会话保留与消息上限默认分别为 30 天和 2000 条消息。

启动流程

  1. 安装依赖：在仓库根目录执行 pnpm install。
  2. 配置 apps/db-ops-api/.env，至少填写控制面 DB、JWT 和加密密钥；生产环境还需初始管理员。
  3. 确认 MySQL 可连接：mysql -h "$DB_HOST" -P "$DB_PORT" -u "$DB_USER" -p -e 'SELECT 1'。
  4. 启动 API：cd apps/db-ops-api && npx tsx server.ts。服务会执行 Schema migration，然后启动 HTTP 监听并尝试获取 Worker lease。
  5. 启动前端：cd frontend && npm run dev。
  6. 访问 http://localhost:5173，登录后检查仪表盘与设置中的 LLM 状态。

后端持有 Worker lease 后会启动 DirectAdapter、指标采集、告警评估、告警升级、CronManager、工作流 worker、维护窗口缓存刷新、提示词热加载和会话清理。通知服务需要先完成渠道配置，不会在未配置时自动启用。

Agent 传输层（替代 Gateway）

Slide 当前没有外部 OpenClaw Gateway。后端中的 DirectAdapter 在 AGENT_WS_PORT 创建 WebSocket 服务，并提供最小的控制台配置端点。客户端连接后，第一帧必须是携带访问令牌的 auth 消息；认证通过后返回 auth_ok，才能发送 chat.send。服务每 30 秒执行心跳并重新验证会话身份，用户被停用或权限变化会立即生效。

故障排查

现象检查与处理
后端启动时数据库连接失败核对 DB_HOST、DB_PORT、DB_USER、DB_PASSWORD、DB_NAME，并用 mysql 客户端验证连接。
生产环境拒绝启动检查 JWT 与加密密钥长度、格式和是否不同，并设置 INITIAL_ADMIN_USERNAME 与 INITIAL_ADMIN_PASSWORD。
聊天连接失败确认 API 持有 Worker lease、28888 未被占用、浏览器可访问该地址，且 WebSocket 首帧发送有效 JWT。
AI 没有回答在 LLM 设置中启用可用提供商；确认模型、密钥和出站网络。无数据库提供商时才会使用 ANTHROPIC_API_KEY 回退。
没有指标或告警确认实例为 active、数据库连接和类型能力正常；检查指标注册表中的采集开关与间隔，并确认 Worker lease 未被其他副本占用。
无法添加实例仅支持 MySQL、PostgreSQL、Oracle、达梦；确认主机地址和端口符合 DB_ALLOWED_CIDRS、DB_ALLOWED_PORTS。
通知未发送通知渠道需要完成配置和测试；检查死信队列与交付记录，确认未被出站 URL 策略拒绝。
