[AI 工作空间体验复盘](https://github.com/max2055/Slide/blob/5cb26fefd538dc377bace47c06d050a4d8dda4f1/docs/superpowers/specs/2026-10-22-ai-workspace-experience-review.md)、

[完整 V4 方案](https://github.com/max2055/Slide/blob/5cb26fefd538dc377bace47c06d050a4d8dda4f1/docs/superpowers/specs/2026-10-22-monitoring-operations-optimization-design.md) §6.4/§7、A14/A15/A18。
原则：复用现有 Investigation/Run/结果版本/行动计划/预检查/审批/执行/审计/验证；不建第二套状态、不新增运维工作台、不扩大工具权限。

> 说明：上述三份设计文档不在本执行基线（`81cdcc92c`）中，只存在于 `732cee45d` 快照及 GitHub 固定提交；本设计以 Issue #266 原文与当前代码为可执行依据，设计文档仅作来源说明，不作为“已实现章节”引用。

## 1. 定位与信息架构

AI 工作空间是**围绕一个具体运维问题的持续工作载体**：调查保存范围、证据、判断、行动与验证；对话只是协作方式之一；报告是结果的一种呈现，不是完成标志。

```
AI 工作空间 /investigations
├─ 发起区（场景 / 对象 / 自由描述）
├─ 需要你处理（投影：补充请求 / 审批请求 / 验证请求 → 引用原调查、原审批、原验证）
└─ 继续调查（列表：问题、主对象、可读进度、最近有效结论或阻塞、更新时间）

调查详情 /investigations?investigation=…
├─ 一句话现状 + 三状态
├─ 当前判断（发现 / 影响边界 / 证据充分度）
├─ 一个优先下一步（其余路径折叠）
├─ 证据与反证（对象 + 绝对时间 + 来源 + 证据引用）
├─ 协作过程（补充、检查进度、关键发现；工具原文折叠）
├─ 行动与验证（计划版本 / 审批 / 执行回执 / 复测）
└─ 交接摘要 / 案例候选
```

不新增菜单。资源诊断、平台诊断、跨资源关联都落在同一列表与详情框架，以对象类型和模板区分。`/resource-diagnosis`、`/attention`、`/events` 保留为既有事实入口，不改成第二套调查工作台（见 [entry-compatibility.md](entry-compatibility.md)）。

## 2. 四条发起路径（0 必填自由文本优先）

处理顺序固定为：**已有上下文自动带入 → 从权威记录读取 → 可复核默认/草案 → 搜索筛选选择 → 只对确实缺失的补充**。任何自动带入都标明来源；自动带入不发起模型分析、不扩大范围、不批准变更、不宣告恢复。

### 2.1 从事件进入（目标：必填自由文本 0 项）

| 步骤 | 系统行为 | 数据来源 | 用户动作 |
|---|---|---|---|
| 1 | 带入事件摘要、严重度、发生时间、资源、指标/阈值/观测窗口、事件引用 | `OperationalEvent`、告警 `tags`（现有 `resource-event-bridge` 已解析 metric/value/threshold/quality/observed_from/to） | 无 |
| 2 | 生成标题：“[对象] [现象] · [时间]”；生成目标句：事实描述，不含结论 | 事件事实 + 场景模板 | 可改名/改目标 |
| 3 | 生成绝对时间窗：事件窗口优先，缺失时取发生时刻 ±15 分钟；显示时区 | 事件 `occurredAt/observed_from/to` | 可改预设（15m/1h/24h/自定义） |
| 4 | 关联对象仅来自有来源的关系（资源关系图/事件关联），逐条显示理由 | `relations` 证据，缺省不纳入 | 勾选/移除 |
| 5 | 能力检查：数据 / 资源与工具权限 / 模型 / 执行范围，四项独立结论 | 见 §3 | 只读确认 |
| 6 | 点击“开始只读排查”，提交创建 | 现有 `POST /api/investigations` | 0 项自由文本 |

事件已自动派生调查时，入口改为“查看该调查”，不重复创建；同一事件再次点击不得产生第二个调查（复用现有告警锁与去重）。

### 2.2 从资源进入（目标：常见场景 0 项）

- 对象已确定。场景从能力注册表按资源类型/引擎筛选：响应慢、连接异常、容量不足、复制/主从异常、变更后核验、其他问题。
- 每个场景只提供当前实现支持的检查；不支持的场景显示“当前模板/能力不支持”，不生成空调查。
- 时间预设：最近 15 分钟 / 1 小时 / 24 小时 / 自定义；默认 1 小时并显示绝对起止与时区。
- “其他问题”只要求一段描述（≤2000 字），标题自动生成；不再要求独立标题。

### 2.3 从指标历史 / 资源详情进入（目标：0 项）

- 带入当前资源、指标标识、时间范围、数据质量、返回位置（原页面 URL + 视图状态）。
- 若窗口内无有效样本：启动前即提示“缺数据”，给出补采集/扩大窗口/查看历史三个可执行项，不生成“当前健康”结论。

### 2.4 自主发起（工作空间首页）

- 搜索选择对象（服务端搜索、分页、重名显示地址/类型/环境；已选项跨页保持）。
- 选择常见问题或输入一段描述；自然语言解析只是可选辅助，选择路径不依赖模型。
- 平台调查：对象为平台组件（api/collector/queue/agent），不携带资源工具权限。

### 2.5 从结果继续（下一步可点选）

- 推荐项来自：未解决缺口（`unresolvedQuestions`）、结果建议（`recommendations`）、失败/部分完成的检查、证据过期提示。
- 每项显示：要检查什么、为什么、预计范围、是否需要额外权限；点选后生成一段明确请求文本（可见、可改），一次提交创建新 Run。
- 保留自由补充入口；提交时仍带 `expectedVersion`，不静默改写正在执行的范围。
- 已有基线：`partial` 结果继续必须绑定 `requestId/runId/resultVersion`（`continuationOf`），未知结果禁止继续。

## 3. 启动前：上下文确认与能力检查

统一确认卡（创建对话框第二步），所有信息只读摘要 + 局部“修改”，不铺满禁用输入框：

| 区块 | 默认展示 | 展开内容 |
|---|---|---|
| 目标 | 自动生成的一行目标 | 来源（事件/资源/指标/对话）、原始事实、可编辑文本 |
| 主对象 | 名称 + 类型 + 地址/环境 + 状态 | 资源标识（技术详情） |
| 关联对象 | 数量 + 每项来源与纳入理由 | 移除/添加（仅授权范围） |
| 时间窗 | 绝对起止 + 时区 + 依据（事件窗口/预设/自定义） | 修改预设、查看原始时间 |
| 执行方式 | “只读排查” | 将使用的工具类别、不可执行变更说明 |

**四项能力分别判断**，不得合并为一个“就绪”：

1. **数据**：窗口内是否有有效样本；无有效样本时明确“可以阅读历史证据，但不能给出当前健康/根因结论”，并给补采集入口。
2. **资源/工具权限**：当前用户可读哪些对象；哪些工具不在 Profile allowlist 或已被实时撤权。缺权限不阻塞只读事实浏览。
3. **模型**：模型是否可用、场景路由是否可达。无模型时仍显示已授权事实读区；“查看事实”和“启动 AI 分析”是两个按钮。
4. **执行范围**：只读边界；变更操作始终走行动计划 + 独立审批，不在调查里直接执行。

费用/用量：只有在服务端给出可靠依据时展示；未知时明说“无法估算”，不生成看似精确的数字。

## 4. 调查详情：先回答“现在怎样、还缺什么、下一步做什么”

### 4.1 顶部一句话状态

由三状态 + 最新结果推导，永远只有一个主动作：

| 场景 | 一句话 | 主动作 | 次要动作 |
|---|---|---|---|
| 准备好分析 | 对象与时间已确认，可开始只读排查 | 开始只读分析 | 修改范围 |
| 正在执行 | 正在读取连接指标…离开后仍可继续查看 | 查看进度 | 取消本轮 |
| 等待补充 | 本轮已结束，还需要确认连接池上限 | 补充信息 | 查看已有结果 |
| 证据不足 | 指定时间没有有效样本，暂不能判断根因 | 补充采集 / 调整窗口 | 查看已有证据 |
| 部分完成 | 完成 2 项，日志读取失败，已有结果保留 | 查看缺口 | 针对性重试 |
| 等待批准 | 行动计划已准备，等待 v3 审批 | 查看计划 | 返回调查 |
| 分析结束 | 已形成判断，故障恢复尚未验证 | 继续验证 | 整理交接 |
| 提交结果未知 | 正在核对原请求，暂不重复提交 | 查询原请求 | 只读刷新 |
| 已恢复 | 复测支持恢复 | 查看验证证据 | 整理案例候选 |

“取消本轮”只取消当前 Run，不关闭调查、不停止正式采集、不关闭事件。

### 4.2 主体结构（默认两栏，窄屏单列）

| 区域 | 默认呈现 | 按需展开 |
|---|---|---|
| 当前判断 | 目前发现、影响边界、证据是否充分（充分/部分/不足三档，不用百分比置信度） | 支持证据、反证、替代假设、历史版本对比 |
| 下一步 | 一项优先动作 + 原因 | 其他合理路径及前提 |
| 协作过程 | 用户补充、检查进度、关键发现、结果更新 | 工具参数、原始回执、技术详情 |
| 证据 | 被引用的关键指标/日志/关系，带对象、绝对时间、来源 | 完整证据包、采集/有效时间、质量、过期状态 |
| 行动与验证 | 计划状态、审批版本、执行回执、复测结论 | 预检查项、回退、审计关联 |

进度只展示真实检查活动（“已读取连接会话数，正在检查慢查询日志”），不展示伪造百分比、持续转圈或“根因置信度 96%”。

### 4.3 结果版本与新输入

- 每次新的 Run 产生新结果版本；旧版本保留可切换查看（已有 `results?before&limit` 与版本选择）。
- 用户补充/否定关联时：确认后影响**下一轮**；正在执行的 Run 不被静默改写。
- 执行中提交的补充，进入下一轮草稿并在界面上写明“将在本轮结束后应用”。
- 改变主对象/时间窗属于新的范围：显示差异并要求确认，不覆盖历史结果。

### 4.4 结构化补充（替代“请确认连接池上限”式纯文本）

补充问题按类型渲染，且先查再问：

| 问题类型 | 交互 | 未知选项 |
|---|---|---|
| 已知配置值（如连接池上限） | 显示已查到的值 + 来源；可修改为数值 | “不清楚” |
| 最近变更 | 有/无 + 关联变更记录选择 | “不清楚” |
| 业务症状 | 已恢复 / 仍异常 / 无法确认 + 可选证据 | “无法确认” |
| 自由描述 | 一段文字（可选） | — |

“不清楚”保留为缺口，不填默认值、不编造选项。

## 5. 异常与边界分支（必须可用）

| 场景 | 界面表现 | 可用动作 | 禁止 |
|---|---|---|---|
| 无数据 | 启动前/结果区提示“窗口内无有效样本”，列出缺失项 | 补采集、调整窗口、查看历史 | 输出“当前健康/根因” |
| 缺模型 | 事实可读，分析按钮禁用并说明原因 | 查看事实、检查模型配置（有权限） | 假装正在分析 |
| 无权限 | 明确缺失的权限/对象，不显示内容 | 重新确认权限、返回原入口 | 用缓存内容顶替 |
| 部分失败 | 保留已完成项，列失败项与原因 | 针对性重试（新 Run） | 重放原执行 |
| 证据过期 | 标注“原文已过期”，保留哈希/元数据 | 重新采集、缩小窗口 | 用过期证据支撑结论 |
| 结果版本变化 | 当前引用版本与最新版本并列显示差异 | 切到指定版本、重新绑定行动 | 静默用最新版替换原判断 |
| 断线重连 | 立即隐藏内容，重连后从服务端快照恢复 | 重新连接、刷新 | 用本地缓存冒充服务端事实 |
| 提交结果未知 | 锁定输入，显示“正在核对原请求” | 核对原请求（同一 idempotency key） | 重复提交新请求 |
| 撤权/会话失效 | 清空敏感内容，回到无权态 | 重新登录/申请权限 | 保留旧内容继续操作 |
| 越权/过期批准 | 计划标注已过期/无权；执行按钮禁用 | 重新提交审批 | 用旧批准执行 |
| 行动无效 | 复测“未改善”，行动记录保留 | 回同一调查继续排查（新 Run） | 自动重试同一变更 |

## 6. 行动与复测闭环

1. **草案**：从用户选定的结果版本生成；带入 `investigationId/resultVersion`、目标对象、可用预检查与验证方案、风险与回退；影响由注册动作 + 目标范围 + 已知证据生成可编辑草案；未知业务影响单列为待确认。
2. **预检查**：执行前展示将要检查的项与预期；缺数据不通过。
3. **独立审批**：审批人不是作者/提交者；批准绑定确切计划版本与内容摘要；改版即失效。
4. **显式执行**：执行需要单独确认；未知回执只核对原 operation，不重发。
5. **复测**：以“后续实际观测 + 明确窗口 + 副作用”为依据，三选一：
   - **恢复**：窗口内关键指标回到基线/阈值内，且无新增负作用；附观测窗口与证据。
   - **未改善**：窗口内仍越界或症状持续；行动记为无效，可回同一调查继续。
   - **证据不足**：窗口内无有效样本/质量不足/观测被中断；不得算作恢复或未改善。
6. **三种完成各自独立**：分析完成 ≠ 执行成功 ≠ 事件恢复。分析结束与命令成功都不自动改变业务问题状态。

现有映射：行动效果报告的 `passed/failed/inconclusive` 可直接作为三类结论的机器证据（`apps/db-ops-api/src/operations/contracts.ts:24`）；调查侧需要新增“未改善/证据不足”的人工记录类型才能形成完整历史（见 [contract-proposal.md](contract-proposal.md)）。

## 7. 首页“需要你处理”与继续调查

- **需要你处理**只投影三类原记录：
  1. 等待本人补充的调查（引用调查与缺失项）；
  2. 等待本人审批的计划（引用计划版本与审批记录）；
  3. 等待本人确认的复测（引用验证记录与结果版本）。
- 不复制事件列表、不建第二套待办状态；已完成项自动消失；点击回到原记录。
- **继续调查列表**字段：问题名称、主对象、可读进度、最近有效结论/阻塞原因、更新时间；按对象/类型/状态筛选；分页沿用现有游标。

## 8. 交接、案例与知识

- **交接摘要**从记录生成，不靠回忆：问题与影响、时间线、证据支持的结论、未解决疑点、已执行动作、效果验证、下一位处理人。用户确认缺口与敏感信息后才可分享；权限不因分享扩大。
- **案例候选**从确切结果版本生成；脱敏 + 审核后才进入知识库；展示适用条件、产品/资源版本差异与反例。
- 案例永远是参考材料，不能作为“当前故障已发生/已恢复”的事实。

## 9. 主动分析与模型调用策略

- 打开首页、列表、详情、证据、刷新、切换版本、查询审批/执行记录：**均不调用模型**。
- 只有用户显式“开始只读分析/继续排查/针对性重试”才创建 Run 并可能计费。
- 自动分析（事件派生）继续遵守服务端准入预算、去重、冷却与并发上限（现有 `budget-configuration`、`trigger-policy`、`alert-bridge`）；超限时在事件上显示“未派生调查”的可读原因，不静默丢弃。
- 不设置“后台自动重跑”或本轮之外的新调度。

## 10. 非目标（本版明确不做）

- 移动/平板专项、暗色、多语言、完整无障碍合规专项、人工听读验收。
- 第二套执行引擎、聊天内“一键修复”、绕过计划的变更。
- Zabbix 导入/表达式兼容/Agent/Proxy；不改变现有 AI Agent 运行时。
- 以巡检/性能优化作为与故障排查同等投入的独立主线（可复用同一框架，但不各建工作台）。
- 自动重置/关闭事件、自动宣告恢复。

## 11. 设计验收（拟采用，本轮未运行）

1. 事件信息完整时，从事件到发起只读排查，必填自由文本 0 项。
2. 资源常见场景按场景 + 时间即可发起；自定义问题最多一段描述，无独立标题。
3. 标准闭环不要求手输资源/调查/计划/审批 ID、结果版本、报告版本或复制证据链接。
4. 同一对象与时间从事件到调查、行动、验证连续带入；有意变更显示差异。
5. 能点选有依据的下一步；未知可标记“不清楚”，不伪造事实。
6. 大规模资源、重名、无结果、读取失败、权限变化、过期版本、缺配置均有可用路径。
7. 每项结论可追溯对象、绝对时间、来源与证据；反证与证据不足可见。
