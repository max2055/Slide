## 本轮实现

- 补充由当前结果的 `unresolvedQuestions` 驱动，选择一个缺口后选择“不清楚”、观察到/未观察到或填写数值。数值必须选择测量/转录监控来源；可选一段描述，常见路径必填自由文本为 0。没有具体缺口时不造问题，引导原自由描述入口。
- 原 Run admission 增加可选 `supplement.answer`，包含 gapIndex 与严格判别的 unknown / choice / number。保留旧 observation 请求兼容。事务内锁定最高结果 id/version，再从服务器原结果解析问题；越界问题、非法值/来源拒绝，不创建请求。unknown 明确保留缺口，用户观察/数值一律未验证，不写回原结果。
- 幂等哈希纳入答案的固定顺序原始字段；同键改变答案拒绝，JSON 字段顺序变化仍返回原回执。异步前深拷贝答案。下一轮消息与不可变快照使用同一服务器规范消息，保留原聊天一致性保护。
- 自主发起支持常见场景、授权资源多选及时间预设，生成标题/只读目标/绝对窗口；自定义仅需一段描述。资源与平台共用 Investigation/Run，平台选择清除资源；提交按钮显式发起原有分析，打开表单不调用模型。原自定义标题、绝对窗口及标识兼容入口保留在高级区。
- 行动草案读取授权来源调查、已保存结果和范围内服务器，不要求手填版本或服务器编号；结果版本变化或来源在途禁止整理，服务端仍复核原证据/注册/预检查。影响通过明确选择确认；独立审批绑定只读显示，不可手工替换，备注选填；原独立审批、显式执行及版本/撤权/过期边界保留。
- 恢复/根因反馈可从授权可用证据选择，带入该证据真实观察窗口与核对方法；未有窗口时不造时间。选用行动效果报告仍需显式人工确认，业务恢复不随分析/执行成功自动确认。旧证据 ID 输入只作高级兼容入口。
- 交接草案从已加载调查/结果生成，包含对象、绝对窗口、事件/返回来源、结果与 Run 绑定、事实与证据引用、反证、缺口及未执行建议。用户可显式读取关联行动与人工记录，草案引用原计划/反馈版本并标明旧结果、分页及读取失败；需要你处理仅投影当前缺口和原计划待审状态，链接回原记录，不维护第二套状态。行动/反馈最新情况仍需核对原记录；可展开/复制，不调用模型、不发布案例。下一步优先展示原结果最高优先级建议，其余折叠。
- 移除主导航独立跨资源诊断；资源概览的新调查链接改向统一工作空间并带入对象、绝对窗口和返回位置。旧 `/resource-diagnosis` 深链接及历史结果读取保持兼容，没有删除历史数据或扩大工具权限。
