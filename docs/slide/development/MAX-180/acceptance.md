## 真实服务与证据来源

运行 `bash scripts/qualification/run-MAX-180.sh`，专属短生命周期 MySQL 8.4 容器、动态宿主端口、完整当前 migrations、独立 Vite/API 端口。任务自有服务直接挂载未改动的生产 `installPlatformObservation`、`registerHealthRoutes`、`consistencyChecker`、`MysqlWorkflowStore`、`createVerifyToken` 与实时 ActorContext/RBAC。

登录适配仅为测试服务入口，实际调用生产密码校验、Actor 加载与 JWT 签发；不把此适配声称为完整 `server.ts` 登录/refresh-token 验收。测试用户拥有真实数据库 config:view 授权，正常页面未截获观测/自检接口；GET 结果来自真实生产处理器及 MySQL 查询。接口实际产生 API request.completed 信号；未注入虚构运行日志。数据库 migrations 中既有配置按原值保留。

没有启动 Agent、Provider、采集器、worker 或共享部署，没有修改线上 binding/采集/遥测开关，没有发产品模型请求。实际应用壳截图使用真实 `/health?view=observations` 路由并切换平台自检；因隔离服务未启动 Agent，其 control-ui-config / WebSocket 连接失败属于已知环境边界，不将它声称为全平台 E2E 通过。

- 正常流：真实密码/JWT、观测与自检读取、日志/队列查询、原值同源、无认证 401；两页在实际应用壳和独立测量页面均覆盖 1440/768/390 × 明暗。
- 真撤权：删除隔离 reviewer 的 role_permissions 后，同一 JWT 两接口返回 403；点击刷新后旧表格、摘要和证据清理。
- 受控补充：未知缺字段、空组件/无信号、部分/过期日志、1040字符分类、240字符 commit、加载中、读取失败、前端撤权事件。HTTP 截获仅用于这些补充状态，每图侧车明确来源，不改变真实采集开关。
- 自检补充：空有效检查、缺准备度/健康维度、加载/503；单测另覆盖全推迟、缺字段、会话失效和迟到响应。
- 已人工查看平台桌面、390深色、证据弹窗、自检390深色与实际应用壳；自动核验各截图整页宽度不超过视口，宽表滚动局限于其容器。
