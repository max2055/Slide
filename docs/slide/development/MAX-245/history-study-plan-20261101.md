# MAX-245 历史趋势与隔离回放实施计划

目标：在既有资源历史入口完成长窗口查询、原始/趋势对照、固定历史规则与证据窗口的隔离回放，以及类型保留和容量清理预览。

采用已有正式历史读侧与 `evaluateTriggerRule`。按需从正式历史建立 5 分钟、小时、日三级统计，父级按子级 count/sum 合并，保留 min/max、无效计数与缺口；不把趋势均值当作回放原始证据。UTC 半开窗口，边界桶裁剪；整数使用现有有理数运算。按需聚合不冒称后台预聚合或已保留的长期数据。窗口最多 366 天，预算超限明确拒绝，原始分页仍使用既有 31 天上限。

1. 增加公开历史研究契约和纯分层 reducer。验证：跨时区输入归一 UTC、边界、峰值、加权均值、大整数、缺口、非数值与坏质量。
2. 扩展正式历史长窗口读取，并增加资源范围服务、实时权限复核和审计事务。清理仅预览，引用既有保全条件；不同值类型可选择不同保留天数。容量使用选中资源实测字节/行，650 目标只作显式参数假设，引用 MAX236 的单指标基线和 P0 门槛。
3. 历史快照作为规则选择列表；按固定 revision/hash/rule/scope 对原始正式历史进行回放，复用评估函数。历史生效证明缺失返回未知。结果为隔离模拟，不调用正式 writer、事件或通知。验证：相同窗口原规则对照、未知初态、坏证据、撤权和跨资源。
4. 在 semantic-metrics 内挂载研究组件，沿用资源和窗口上下文、规则下拉、原始分页入口；使用会话代次和请求代次拒绝旧结果。验证加载/空/失败、资源切换、认证刷新、键盘和三桌面尺寸。
5. 真实 Lit/JWT/Fastify/独占非3306 MySQL 验收，前后摘要核对正式问题、事件、通知不变。运行受影响测试、类型、构建、契约，记录准确源码 SHA 和证据。复用已接受发现证据，不重跑不变协议矩阵。

容量假设必须显示资源数、每资源序列数、周期、类型保留天数和测量样本量；不修改部署配置，不承诺生产 SLO。无可测样本时预测未知。生产清理、共享3306、发布与外发不在本轮授权内。SSH/数据库动态发现矩阵和最终集成仍保留。
