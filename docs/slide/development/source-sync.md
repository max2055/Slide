# 源码同步、快照与版本访问规则

触发范围：源码同步服务、连接器、Git 网络与代理、源码扫描、快照/manifest、部署版本绑定及相关前端入口。根目录 [AGENTS.md](../../../AGENTS.md) 继续适用。

## 排查与可观测性

- 排查前核对实际运行实例：PID → 端口 → cwd → 启动命令 → 分支/Commit → 日志文件；多工作树或残留进程存在时，不能仅凭当前源码判断运行行为。
- 审计中心出现业务操作记录，说明请求已进入后端业务层；文本日志缺失时先核对日志来源、进程身份和 request ID，不能据此直接判断请求未到达。
- 按“配置 → Commit → clone/fetch → checkout → 扫描 → 快照 → manifest”分阶段记录耗时和脱敏错误，保留网络、代理、凭证、Commit、扫描等准确错误码。
- Git 代理由同步任务显式设置或清除，同时处理大小写环境变量和 Git config；重试前先验证配置的代理端口可达。
- 网络链路稳定后再启用 partial clone 等优化，不把性能优化当作网络故障修复。

## 凭据与扫描

- 同步 Token 只用于单次请求，提交后清空，在日志中脱敏；不得写入 `.env`、数据库、Git、快照或文档。
- `SLIDE_SOURCE_ALLOW_UNSAFE=true` 仅限开发验证，生产环境禁止启用。
- 安全扫描使用完整键名和词边界；误报与漏报都补充回归样本。

## 真实验收

涉及同步链路的变更，必须完成：**POST /sync 200 → Commit 一致 → manifest 生成 → GET /manifest 200 → 重复同步**。按实际路由前缀调用，并保存脱敏证据；健康检查、mock 和单元测试不能替代此链路。环境阻塞时明确标注未验证，不宣称通过。
