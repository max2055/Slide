## 运行行为

基线版本与 outbox 先原子提交，再重新取得实时 ACL、目标及采集控制锁，读取准确已提交版本并同步发送。提交失败不发成功；提交期间发生撤权则不发送，资源替换、过期或停用则返回当前 unknown 投影。新写入事务仍在提交前核验权限，读取事务仍在锁内同步发送，不把发送移到授权锁外。

`ops` v1 与 `system` v1 的结构、提示词与 hash 保持原字节语义。新增显式选择的 `ops` v2，HTTP 创建可传 `profileVersion: 2`；省略仍为 v1。预置列表列出三个准确版本，不把工具可用性描述为已授权。v2 仅新增 `search_case_references`：只读、无审批、无凭据、无网络目标和写工具，不注册到普通 Chat。还须启用既有 cases 开关并具备 `operations:cases:view`、全部资源及来源调查的实时权限。

检索只接收 query（1–200 字符）和 limit（1–5，默认 3），不接收 actor、资源边界、SQL、来源身份或任意游标。数据库搜索先按完整调查资源边界与来源可见性过滤；每个返回项再经 KnowledgeService.references 核对 published 状态、来源、精确版本/hash 和有效期。内容保留 applicability 与不可信参考标记，案例指令不获得执行权；案例工具结果不会进入 investigation_evidence。模型如伪造当前 Evidence ID，现有结果绑定校验继续拒绝。

迁移 `130_investigation_case_dependencies.sql` 只增加调查级精确引用依赖表，不复制内容、不新增角色授权、不修改旧迁移。依赖与工具返回回执在同一 fenced SQL 事务提交，跨后继 Run、摘要和新 worker 恢复保留。每个调查最多 20 个不同案例；同一案例不能静默替换版本/hash。超过边界会拒绝，不清除旧依赖来绕过授权。

普通 chat、摘要 chatStream、摘要派生内容后的请求、后继及恢复统一经 Executor dispatch。每次重新读取全部持久依赖，并在 KnowledgeService.references 的来源、版本和 ACL 锁内同步启动 Provider 请求；等待响应在 SQL 事务外。任何旧案例失效即阻止带旧历史/派生摘要的后续出站，不能用一次工具读取授权代替未来授权。尚未启动的请求若因最后核验拒绝，按准确 Run/actor/request/live fence 清除未发送 intent，仅结算此前实测 usage；真正已启动而结果未知的请求继续 unknown/noReplay。
