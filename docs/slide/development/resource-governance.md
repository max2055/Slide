# 资源计量与预算规则

有明确硬预算、用量统计要求或多代理工作时读取本文件。根目录 [AGENTS.md](../../../AGENTS.md) 的范围与委派上限继续适用；本文件不授予额外的代理或执行权限。

## 预算适用范围

- 应用硬预算前先明确其约束对象（产品模型测试或编码代理等）、模型/Provider、同批验收目标、累计账本和缓存计量口径，沿用用户已明确的解释，不只读取一个token上限数字。
- 不把产品模型测试预算套到建单、编码、审查或协调；不同对象的遥测分别记录。某类遥测缺失只影响受该预算约束的步骤，不据此暂停其他已授权工作。
- 下列吞吐统计口径与硬预算扣减分别记录；用户明确缓存不重复计数等预算口径时按其授权执行，不能将平台另列的缓存量再次相加。
- 本项目后续产品LLM调试默认使用`mysql-3306`现有配置的`deepseek-flash`，调用次数不限；同批主任务及全部子任务累计预算为10,000,000 token。主任务写明统一账本，子任务继承；详见[调试任务默认要求](debug-task-defaults.md)。该额度不约束编码、建单、协调和审查，也不因后续建单自动重置既有批次累计。

## 统计口径

- 聚合主线程及全部后代线程的 `input_tokens`（包含 cached input）、`cached_input_tokens`、`output_tokens`、估算费用、代理总数、最大深度及并发峰值；明确实际值、估算值和不可用项。
- `cached_input_tokens` 是 `input_tokens` 的子集。总吞吐统一为 `input_tokens + output_tokens`，不得重复加缓存量；计费按供应商对应价格分别计算，不把吞吐量直接当费用。
- 子线程记录开始自身任务时的累计基线，只计基线后的单调增量，不把继承的父线程历史重复计入。相同计数器的重复快照增量为零。
- Goal/任务范围调整、暂停、恢复和上下文压缩不重置累计用量。计数器重置或数据来源不连续时标明计量缺口，不把较小值当成额度恢复。
- Goal 账本值与模型实际吞吐量分开展示，不用内部预算计数冒充实测；估算注明方法与不确定性。
- 实际遥测不可用时标注“不可用”，不编造实测值。无硬预算不因遥测缺失停工；有硬预算及追加批准要求时，计量缺失不使约束失效，无法可靠执行约束必须说明缺口，不假定仍有额度。

## 硬预算阈值

只有明确设置了相应硬预算时才执行以下动作。未设置硬预算时不自行推导预算，也不要求在每次进度回复重复“未设定”。

| 已用比例 | 动作 |
|---|---|
| 50% | 报告已用资源、剩余范围、主要风险与预计完工成本 |
| 80% | 停止扩展范围和新增代理，重新评估方案，压缩到既定完成标准 |
| 100% | 停止新增工作，保存可恢复检查点并完成最小安全收尾；明确获批追加预算后才能继续 |

多个硬预算并存时分别跟踪，任一达到上限均受其约束。无人值守同样适用，不以“持续完成”为由突破硬预算。
