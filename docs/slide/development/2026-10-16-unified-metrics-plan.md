# 统一指标与采集整改方案

日期：2026-10-16，修订 R2。用户已授权据本方案创建、分派并正常接续主子任务。基线：main `acd0e1b0`（制定期间 MAX-186／PR196 新合入，已再次同步并启动主目录服务）；问题来源：`docs/slide/reviews/2026-10-16-resource-collection-binding-audit.md`。本方案覆盖该报告全部确认问题，并纳入批量绑定及唯一指标标准要求。继承最新资源工具栏、共享控件、默认蓝与布局规范，不重做或回退 MAX-184～187 已交付成果。

## 目标与统一决定

建立唯一指标体系，以现有新版指标语义、能力约束、不可变采集包、权限、生命周期、质量和来源隔离为准。兼容能力合并进唯一执行／查询路径；语义不兼容者按该标准实现，明确旧数据转换、保留或不再适用的原因。不得简单删除旧代码导致已有能力消失，也不得为保留旧数据伪造单位、维度、时间、重启 epoch、速率或健康结论。

产品、当前模块／类型／函数／目录、配置项、API、数据库活动命名采用中性名称，不再维护“指标 V1／V2”“旧指标目录”等产品分支。目标目录 `metrics/`，API `/api/metrics`，环境项 `METRICS_COLLECTION_ENABLED`，持久化命名采用 `metric_*`，具体重名先盘点并提供迁移映射。包和指标自己的语义版本、revision、digest 和来源血缘仍用于兼容性与追溯，不能把它们误当体系代际而删除。

迁移脚本和有期限的旧入口适配器必须能引用真实历史名称；历史已发布文档、schema migration ID、证据文件不改写。适配器只能转发唯一实现，不得继续运行第二套采集／存储／查询逻辑。交付必须列出剩余历史引用、原因和移除条件，不能靠给双轨实现换名称冒充统一。

## 唯一配置与运行流程

资源编辑中的“监控与采集”负责选择兼容模板、有效开关、周期和覆盖。流程为推荐 → 影响预览／权限能力检查 → 有界试采 → 发布 → 调度应用 → 必要的来源接管门禁 → 正式查询可见。普通用户通过一个连贯流程完成，后台明确每阶段状态、失败、重试、取消和冲突。

保留来源 fencing、revision CAS、影子对照和切换门禁。常规配置流程必须编排必要步骤，不能要求用户知道隐藏的 rollout 接口，也不能虚填“全零差异”报告。新建资源与已有采集来源分别定义初始化／迁移路径。没有等价旧指标时用直接真实测量和语义验收，明确“不适用”，不伪称旧新一致。

停用、排空在途、重新启用和服务重启有统一语义。资产停用优先于模板／组继承启用；全局服务关闭时显示全局阻塞及运维处理入口，不擅自打开其他暂停资源。所有周期采集来源服从同一有效状态，手动诊断等独立动作必须另有明确语义，不能误并成自动采集。

API 由后端子任务先固定并提交契约：至少包含资源绑定状态、有效开关及其来源、运行状态、正式源可见状态、阻塞代码、最后尝试／成功／观测时间、模板逐指标覆盖与兼容性。前端通过共享类型适配该契约，不自行从几个核心指标是否为空推断整个对象未绑定。契约提交可先行评审供前端并行开发，最终合入仍以完整后端验收为准。

## 兼容推荐与状态

- 推荐依据资源类型、引擎、真实版本、协议及能力；不适配项禁用并说明原因。MySQL 9.6 不能默选仅支持 5.7／8.0／8.4 的包。
- 模板展示实际指标覆盖及核心列缺口。linux-basic 的 uptime/load 不能被当作文件系统／网络指标；没有容量能力的包应显示“当前模板未覆盖／该版本不支持”，不能笼统引导重新绑定。
- 对象绑定、任务执行、正式数据可见和单项覆盖分层展示；区分未绑定、加载中、全局暂停、资源停用、预检失败、试采失败、等待应用、来源验证中、正式可用、待样本、失败、未知、部分覆盖及陈旧。
- 加载／权限失败不能先显示“未绑定”；发布状态采用有界刷新和明确终态，避免无限手动刷新或无限轮询。

## 入口与交互

资源新增／编辑提供统一的“监控与采集”编辑器：模板推荐、有效开关、周期和覆盖摘要为主要内容，高级覆盖折叠。详情保留模板、有效状态、阻塞原因、最近证据及“编辑采集配置”链接，打开同一编辑器，不再平铺第二套完整编辑表单。设置保留指标定义、采集包／版本、策略组和审计；资源策略入口若保留应作为状态列表并跳共享编辑器。

连接信息保存与采集启用分别报告成功／失败。已有自定义覆盖不得被默认推荐静默覆盖；候选变化使旧预检／试采失效；409 不盲重试；缺权限只读；保留未保存修改保护、取消、键盘焦点恢复及明暗主题。

策略组如仍存在，提供可用枚举／搜索及权限过滤，普通用户不再需要手工输入标识；保留已有有效绑定及继承规则。

批量操作从资源列表勾选进入，跨类型按兼容性分组推荐，预览当前 → 目标差异、覆盖与逻辑读取成本。执行逐对象权限、预检、试采、发布与正式就绪检查；受控并发、幂等和取消；展示成功／跳过／不支持／失败／待接管，并支持仅重试失败项。禁止无提示覆盖已有配置或把部分成功称为全部成功。

## 子任务边界与依赖

为控制共享文件冲突和重复 CI，合并相关缺陷为四个可交付子任务，不为每条报告单独建 PR。

| 工作包 | 责任文件／范围 | 依赖 |
|---|---|---|
| A 后端唯一指标标准与单资源正式出数 | 后端 metrics-v2 → metrics、旧采集入口和消费者、存储迁移、公开契约生成、应用生命周期／有效开关／来源接管／兼容推荐／策略组查询；相关后端测试与文档 | 无，先交稳定契约 |
| B 前端统一采集配置与真实状态 | frontend 指标相关组件／视图、三类资源编辑／详情、设置路由、前端 API 适配和版本化名称清理；相关前端测试 | 可与 A 并行，按本方案和 A 的先行契约；最终集成依赖 A 合入 |
| C 批量绑定与受控执行 | 批量后端路由／执行及状态、三类列表选择和批量对话；相关测试 | A、B 经审查合入后接续 |
| D 迁移与最终真实业务验收 | 批次集成、迁移／重跑／回滚实测、qualification／E2E、名称残留检查、最终报告及文档引用修正 | A、B、C 经审查合入及证据齐备后接续 |

Chief 负责契约／文件锁协调、逐个交付即审、PR/CI、合并与最终验收。15astra 负责四项实施；独立任务最多 3 个实施／恢复运行（含 queued/dispatched），另留 Chief 协调位。C、D 的依赖必须存 metadata 并配置父接续；不得创建后附加“仅建单不启动”。依赖未满足时等真实前序成果，满足后自动正常接续。

迁移需要 A 独占后端共享文件，B 独占前端；C 只在两者合入后触达其文件。A 不在命名迁移时抢改 B 的前端文件，应提交映射并协调。D 不重复大范围实现，发现阻塞由原 owner 修复，当前集成更改走独立可审 diff。

## 验收和运行授权

1. 空绑定初始化、已有策略／覆盖迁移、同名表冲突、迁移重复执行、备份恢复与回滚均有实库证据；保留审计、原值和追溯，不降低 revision 或丢样本。
2. 本机 mysql3306 从正常 UI 完成配置，至少 3 个周期成功，并由唯一正式查询返回与真实源一致的运行时长；列表、详情、设置一致。容量不支持单独说明，不能以健康探针或尝试记录代替出数。
3. VMware 服务器真实验证：停用时无新的周期采集／正式写入，启用后可采；覆盖模板内实际支持的主机指标。协议／维度／epoch 不支持时维持真实 unknown。
4. 其他数据库／网络设备按当前可达性和能力实测；不可达项准确列出。厂商 SNMP 延后测试环境的既有决定保留，不把模拟设备证据称为物理交换机验证。
5. 批量覆盖混合类型、部分失败、权限、冲突、取消、重试、已有覆盖保护；能追溯每个对象结果。
6. 前端使用真实服务，对照本方案信息层级，覆盖桌面／窄屏、明暗、加载／空／失败／权限／部分／未知，保存截图与交互证据。
7. 运行受影响 focused checks、类型检查、前端构建、契约检查；最终候选运行必要完整 gate。失败分类处理，禁止跳过门禁。完成状态必须包含 CI、独立审查、实际 merge SHA、集成版本及真实业务验收。

本批允许在指定本机开发服务和调试 VM 范围内进行必要重启、绑定和有界采集验证；操作者先核对 PID→端口→cwd→命令→commit→日志，迁移前备份并形成回退点，记录对象及有效开关基线，恢复无关对象的暂停状态。共享配置冲突或不能恢复的破坏性操作停止对应步骤。未经本批要求不修改 Provider、生产系统或扩大公网暴露。创建任务不需要先调用 LLM 或登录 VM。

## PR、CI与交接

每项交付一个主要 PR；确有必要的修复提交留在其原 PR，减少重复流水线。创建 PR／每次 push 后，执行者必须在实际关联子任务登记 `until-pr checks / 30m / on-timeout wake`，目标为实施 owner 和实际交付评论线程，主动读取当前 head 已完成结果；失败分类修复、验证、再推送并续设。没有真实 PR 时不虚建 checks 监听。

Chief 在任一子任务完整交付 in_review 后立即审查，不等其他并行项；按准确 head 核验业务／视觉／迁移证据和完整 CI，通过后正常合并并核 merge SHA。stage／done 不代替审查和合入。依赖推进读取集成提交和证据，文件锁及并发空位允许才启动；不能用共同超时一次拉起全部依赖任务。父任务有事件接续与有界兜底，批次完成后关闭自建唤醒。
