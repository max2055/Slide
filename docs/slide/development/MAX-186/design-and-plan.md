# MAX-186 运维总览设计与实施计划

> Execution: 在已授权 R1.1 方向、专属文件所有权和既有仓库门禁内持续实施，不派生代理。

目标：值班人员先判断当前范围的关键风险，再查看证据／关联资源，最后在全量明细中检索与比较。保留现有四种资源范围、筛选 URL、权限、观测与快照时间、容量图、备份和返回路径。

设计依据：已确认 R1.1（原型 SHA256 `112502a0ad6dbadc7eea35efda027ccfb079fed756bf0ed51956ac6fd71347fe`），以及 2026-10-16 视觉差距报告。R1.1 `#overview` 是单资源详情，不作为 dashboard 一对一稿。本页代表布局如下，置于完整现有应用壳内，不改导航：

```text
运维总览                                      快照更新 · 刷新
综合态势 / 数据库 / 服务器 / 网络设备          搜索 [引擎]
纳管资源       异常资源       未解决告警       采集异常资源
风险队列（前5项，按严重性）          运行状态分布
资源名称 · 风险原因  → 查看证据       三类资源与状态计数
  按需：观测时间、关联资源             采集质量与缺口
资源明细与证据（全宽，含筛选、分页、局部横滚）
资源 / 状态 / 采集 / 告警 / 观测时间 / 查看证据 + 按需操作
```

选择理由：只放大字号无法解决重复和窄表；只删除风险队列会损失处理优先级。采用摘要与明细分工：风险行明确真实异常／不可用／采集缺口，不机械重复完整状态列和三操作。证据是默认行动，资源链接、诊断与关联保留；摘要详细时间进入原生 disclosure，明细时间默认可见。不新增健康分、趋势或智能因果。

字号按 R1.1 标题24、区块16、正文14、辅助12，窄屏标题22；通过现有字号 token 比例兼容密度。间距使用既有 token。状态分布和采集质量保持次要权重；全宽明细减少横滚压力，窄屏仅表格局部横滚。小屏统计保持两列，避免单列长卡抢占首屏。

必要状态：正常、未知、过期、部分质量、告警读取失败、刷新保留、撤权清空、未纳管、搜索空、加载与失败。未知和成功空数组不能宣称健康。长名称允许受控换行，完整名称仍可读取。

## 实施与验证

1. 基于审定 main `47f8f4f1` 的独立 `codex/max-186-overview`；基线 dashboard 单测后修改 `dashboard.ts` 和 `dashboard-styles.ts`。不修改共享 token 或 i18n 文件。
2. 风险队列保留 Top5 排序与全部入口；一行展示资源和风险原因、证据；原生 details 提供观测时间和关联控制。明细保留证据入口，把资源／只读诊断收进操作 disclosure。关联摘要跟随所选风险，清除逻辑保持。
3. 风险／分布双列后接全宽明细；专业指标、备份与数据库图继续按范围展示。对齐字号、字重、卡片与控件层级，桌面风险行目标约60–80px（普通名称），长内容自然增高。
4. 更新专属 dashboard 单测和浏览器断言，验证风险原因、所有动作可达、disclosure键盘、筛选与返回，以及失败/撤权/空/未知语义。跑 `pnpm --filter slide-frontend exec vitest run src/app/ui/views/dashboard.test.ts`，再跑受影响浏览器套件。
5. 完整候选跑前端全部单测、typecheck、build/CSP及lint。截取1280/1440/768/390、明暗及三种密度；记录版本、蓝色、数据来源与差异。正常流优先现有真实服务，特殊状态受控注入明确标记。
6. 共享主题归 MAX-184；最终集成需已审提交后复核。单聚合PR与实际子任务关联，交付一次最终评论并设置真实线程 checks/30m/wake 接续；Chief审查与合并独立记录。
