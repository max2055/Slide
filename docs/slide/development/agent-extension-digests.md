# Agent 扩展内容摘要

创建扩展（含提交草稿提案）和保存草稿时，服务对以下五个字段生成 SHA-256。将它们按所列顺序写入一个对象，以 ECMAScript `JSON.stringify` 的无缩进 JSON 表示编码成 UTF-8，输出 64 位小写十六进制摘要。

1. `kind`
2. `name`
3. `description`
4. `definition`
5. `sourceText`

`definition` 中每层对象按固定规则序列化。ECMAScript 数组索引键（`0` 至 `4294967294` 的规范十进制形式）按数值升序排在前面，其余键按 UTF-16 码元升序排列。数组保留元素位置，递归处理其中的值。字符串、数字、布尔值及 `null` 采用 ECMAScript 的 JSON 表示。对象键与字符串值保留原有 Unicode 形式。MySQL 的 JSON 对象输出顺序可随版本变化。 [MySQL JSON 正规化](https://dev.mysql.com/doc/refman/8.0/en/json.html#json-normalization)

审计重算使用读回记录中的五个字段，并应用同一排序规则。写入时描述和正文分别保留前 2,000 和 262,144 个 UTF-16 码元，落在截断边界的孤立代理码元和输入中的其他孤立代理码元按 UTF-8 写入行为替换为 U+FFFD。空描述和 `null` 正文各用原值参与计算。

升级保留历史记录的原始摘要。读取、发布和归档使用已存值，草稿在下一次保存时采用上述规则重新生成摘要。旧算法依赖原始对象键顺序，核验旧摘要需要原始顺序的写入内容。仅凭 MySQL 返回的内容无法确认旧摘要不一致的原因，审计时应结合记录的写入版本判断适用规则。
