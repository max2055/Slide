## 私有资源入口

执行环境注入 `SLIDE_TEST_RESOURCE_MANIFEST`，值为仓库外私有 JSON 文件的绝对路径。公开材料只使用逻辑资源名：`slide-platform`、`mysql-test`、`pg-test`、`oracle-test`、`dameng-test`、`linux-test`、`model-test`。端点、账号、容器、所有者、占用和验证记录保留在私有 manifest 中。

版本 1 的 `resources` 按逻辑名索引，每条记录必须有 `kind` 和 `owner`。数据库记录引用 `profilesFile` 和 `profile`，沿用既有连接文件；VM 记录包含私有端点、端口、账号和 `passwordFile` 引用；模型记录引用 `envFile` 与 `budgetLedger`。不把解密后的秘密复制到 manifest，不新建预算账本。

```bash
node scripts/qualification/test-resource-manifest.mjs --real --resource slide-platform
```

入口仅验证所选资源的文件可读性，不发网络请求，不证明真实认证、采集或轮换成功。配置文件及其秘密引用必须为当前 Unix 执行用户所有、无组及其他用户权限、普通文件、末级非符号链接，并位于当前工作树以外。路径由执行环境私下交接，禁止提交到本页或 Issue。

未注入配置时，显式入口以退出码 1 和 `SLIDE_TEST_RESOURCE_MANIFEST_REQUIRED` 失败；其他错误也只输出固定错误码。默认调用 `loadTestResource()` 不访问文件。真实验收脚本必须显式调用 `loadTestResource({ enabled: true, resource })`，再将返回配置传入项目驱动。该入口尚未迁移所有历史脚本，不能推断全仓默认测试均已隔离。

清理公共 AGENTS 前，须在实际执行身份及独立工作树检查全部逻辑资源，并确认后续任务仍有持久注入入口。文件可读不等于资源已预留；切换共享资源前仍须登记消费者、活动验收及恢复点。平台库与测试库隔离，普通查询、管理员操作和故障注入权限分别选择。

## 文本扫描

```bash
# 工作树全量审计，包含未忽略的未跟踪文件
pnpm security:scan:all
# 本地新增风险检查
node scripts/ci/check-secrets.mjs --base HEAD
# CI 使用已解析的提交区间；PR 的 base 取共同祖先
node scripts/ci/check-secrets.mjs --base <base-commit> --head <head-commit>
# 扫描、配置隔离、CI 选择和失败传播回归
node --test scripts/ci/*.test.mjs
```

退出码：0 为本次扫描范围内无匹配，1 为存在匹配，2 为参数、Git 或文件读取错误。输出为 JSON，只包含文件、行号、规则、SHA-256 指纹和范围摘要。指纹用于对账，不代替凭据存储保护。

扫描所有 Git 文本路径，不排除文档、测试或样例。覆盖私钥头、常见 API Key 前缀、JWT、Bearer、含认证的 URL，以及常见敏感字段的引号、环境变量、多行 YAML 和百分号编码写法。这是启发式扫描，无法证明任意格式或短凭据都不存在。二进制以 `binaryPaths` 列出，须另行检查；Actions ZIP、Release、LFS 和外部副本不在当前树扫描覆盖内。

增量模式逐文件比较规则和指纹的出现次数，阻止新文件复制、新增副本或值变更；保留原位置的旧匹配不会被增量模式重新阻断。全量审计仍报告旧匹配，本次没有目录级忽略或凭据 allowlist。存量命中须逐项分类、指定 owner 并处置，不能把增量检查通过解释为基线清洁。真实配置的精确比对只在受控本机内存中进行，结果不得含配置值。
