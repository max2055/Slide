## 私有资源入口

执行环境注入 `SLIDE_TEST_RESOURCE_MANIFEST`，值为仓库外私有 JSON 文件的绝对路径。公开材料只使用逻辑资源名：`slide-platform`、`mysql-test`、`pg-test`、`oracle-test`、`dameng-test`、`linux-test`、`model-test`。端点、账号、容器、所有者、占用和验证记录保留在私有 manifest 中。

版本 1 的 `resources` 按逻辑名索引，每条记录必须有 `kind` 和 `owner`。数据库记录引用 `profilesFile` 和 `profile`，沿用既有连接文件；VM 记录包含私有端点、端口、账号和 `passwordFile` 引用；模型记录引用 `envFile` 与 `budgetLedger`。不把解密后的秘密复制到 manifest，不新建预算账本。

```bash
node scripts/qualification/test-resource-manifest.mjs --real --resource slide-platform
```

入口仅验证所选资源的文件可读性，不发网络请求，不证明真实认证、采集或轮换成功。配置文件及其秘密引用必须为当前 Unix 执行用户所有、无组及其他用户权限、普通文件、末级非符号链接，并位于当前工作树以外。路径由执行环境私下交接，禁止提交到本页或 Issue。

未注入配置时，显式入口以退出码 1 和 `SLIDE_TEST_RESOURCE_MANIFEST_REQUIRED` 失败；其他错误也只输出固定错误码。默认调用 `loadTestResource()` 不访问文件。真实验收脚本必须显式调用 `loadTestResource({ enabled: true, resource })`，再将返回配置传入项目驱动。该入口尚未迁移所有历史脚本，不能推断全仓默认测试均已隔离。

本次已有实际身份/独立工作树的引用可读证据，公共 AGENTS 资源章节及当前文件中确认复用的值已清理。持久注入仍待 owner 复核提议并跨任务验证，未注入的显式真实入口保持明确失败，不能为兼容而恢复公开密码。文件可读不等于资源已预留；切换共享资源前仍须登记消费者、活动验收及恢复点。平台库与测试库隔离，普通查询、管理员操作和故障注入权限分别选择。

## 文本扫描

```bash
# 工作树全量审计，包含未忽略的未跟踪文件
pnpm security:scan:all
# 本地新增风险检查
node scripts/ci/check-secrets.mjs --base HEAD
# CI 使用已解析的提交区间；PR 的 base 取共同祖先
node scripts/ci/check-secrets.mjs --base <base-commit> --head <head-commit>
# 扫描、配置隔离、CI 选择和失败传播回归
node --test scripts/ci/*.test.mjs
```

退出码：0 为本次扫描范围内无匹配，1 为存在匹配，2 为参数、Git 或文件读取错误。输出为 JSON，只包含文件、行号、规则、SHA-256 指纹和范围摘要。指纹用于对账，不代替凭据存储保护。

扫描所有 Git 文本路径，不排除文档、测试或样例。覆盖私钥头、常见 API Key 前缀、JWT、Bearer、含认证的 URL，以及常见敏感字段的引号、环境变量、多行 YAML 和百分号编码写法。这是启发式扫描，无法证明任意格式或短凭据都不存在。二进制以 `binaryPaths` 列出，须另行检查；Actions ZIP、Release、LFS 和外部副本不在当前树扫描覆盖内。

受限验收可附加 `--known-values-stdin`（放在其他参数前），由仓库外的受控入口向标准输入传递待核对的非空字符串 JSON 数组。精确命中不受增量基线抵消；只输出路径、行号和规则，不输出值或其指纹。不要把运行凭据写入命令行、工作树、流水线日志或扫描报告。发布包解包后也需单独做文本与嵌套产物检查。

开发基线的合成账号种子与资格验证初始化都由各自的写入入口确定。生产空库不执行开发基线中的用户种子语句，只按仓库外配置创建指定管理员；升级不会按用户名、哈希或密码猜测既有账户的来源。已有数据库的基线账本接受明确列出的旧校验和与清理后的固定校验和配对，不重写旧行、不重跑基线。旧 SHA-256 账户仍沿用既有登录逻辑，在成功登录后自动升级为 bcrypt，不改变密码、角色、状态或会话版本。清理当前文件不会使已暴露且继续保留的凭据失效；历史、既有产物和外部副本仍需单独登记，不在本次自动重写。

迁移器写入开发基线种子时，在同一事务按账号 ID 记录来源。转生产时停用已记录的种子并提升其会话版本；重复启动不重复撤销。对已知旧校验和的已完成基线，只有基线执行时间窗内尚未停用、又无来源记录的账户触发对账停点；时间重叠只用于圈定待审核范围，不用于判断账号归属。生产启动在监听前以 `LEGACY_DEVELOPMENT_ACCOUNTS_RECONCILIATION_REQUIRED` 拒绝继续，不打印账户、文件路径或凭据。

显式 `init-db --baseline` 接管的账本时间和账户创建时间可能来自不同时区。首次生产启动按账号 ID 核对所有未登记来源的存量账户。成功对账后，启动事务将这组历史 ID 与基线校验和一并存入库内；后续用原文件重启，首次接管后创建的管理员和普通用户无需追加到文件。接管登记的 SQL 校验和用于绑定记录，账号来源以核对证据为准。

维护者用原初始化记录或可信快照确认待核对 ID 的来源，再通过 `SLIDE_LEGACY_ACCOUNT_ORIGINS_FILE` 提供仓库外的受限 JSON 文件（绝对路径、运行用户所有、无组/其他访问、末级不得为符号链接）。字段为 `serverUuid`、`schema`、`baselineChecksum` 和 `accounts`；每条账户记录仅含 `id` 和 `source`（`development-seed` 或 `existing-account`）。只接受绑定当前库、账本中的基线校验和及候选范围的完整分类；只停用确认的开发种子，判为既有账户的记录在后续启动继续使用该文件保留，不重写账本。不要把凭据、哈希、文件或其中的身份明细提交到仓库。

增量模式逐文件比较规则和指纹的出现次数，阻止新文件复制、新增副本或值变更；保留原位置的旧匹配不会被增量模式重新阻断。全量审计仍报告旧匹配，本次没有目录级忽略或凭据 allowlist。存量命中须逐项分类、指定 owner 并处置，不能把增量检查通过解释为基线清洁。真实配置的精确比对只在受控本机内存中进行，结果不得含配置值。

## 后续检查点与停止条件

1. A：按最新 main、真实配置和远端 ref 建立分类清单；补齐产物内容、LFS、二进制及历史覆盖，记录未知项。
2. B：完成持久注入与实际驱动验收后，才能清理公共入口并逐一迁移历史脚本。保留原账本和加密数据。
3. C：先完成隔离环境演练、消费者对账、活动任务协调和独立复核，再切换 JWT、平台库及达梦。逐步记录未知回执，禁止盲目重放。新认证成功、旧认证失效、登录权限、采集及数据可读性均须实测。
4. D：清理当前文件与发布排除项，归类扫描基线，复扫最终发布物；合成测试使用运行时生成的虚构材料，不把其当作运行默认凭据。
5. E/F：先使有效秘密失效，再准备历史处置预演及协作恢复方案。历史改写、强推、远端引用删除必须另行获批；未经用户明确接受的历史延期保持未完成。最终 main 候选 CI、独立复核和业务验收分别记录。

遇到未核清的活动消费者、私有注入缺失、未知操作结果或授权外操作，只停止相关切换步骤并交接。原加密密钥、模型配置和共享预算不因本任务自行重置；没有新增泄漏证据时，不扩大轮换范围。
