## 故障根因与实现

原实现将租约续租失败视为最终进程关闭，HTTP 与共享 pool 随后台资源一并关闭；认证将依赖异常归为 401；前端轮换 5xx 清理会话，概览无恢复读。修复将后台代次恢复与最终退出分离，复用稳定 pool，旧代次实际排空后才重新选举并启动新代次。

历史三次未重启数据库的 5 秒租约超时：原日志没有连接池 checkout、SQL 等待阶段或锁快照，现存平台只读诊断不能追溯当时根因，因此不能判定是采集、连接池饥饿、锁等待还是瞬断。此次增加脱敏错误码、checkout/query 阶段和时长诊断，并通过隔离租约行锁明确重现 query 阶段超时后进程内恢复；这不代表历史故障已被证明由行锁引起。

控制面查询 4 秒超时，迟到 checkout 释放且不发 SQL，已开始 SQL 超时销毁单连接；恢复循环串行，指数退避 1–10 秒加抖动。迁移和 HTTP 路由仅初始化一次，恢复只读核对迁移账本。排空超过 10 秒报告 blocked，仍等待原代次；停止失败或 schema 不兼容保持 blocked。初始 standby 不晋升，恢复他方持租保持 standby。最终信号停止恢复并关闭 HTTP/pool，最终关闭 deadline 10 秒。

认证实时读取失败为 503，拒绝访问；真实无效/过期/撤销保持 401。WS 临时依赖故障 1013，真认证失败 4001。每次重连先在 5 秒内取得并签署新设备挑战，再打开 WebSocket，避免复用已消费 nonce 或把等待挑战计入服务端认证窗口；失败不能省略设备证明，断开时取消准备。前端只重试共享 readiness GET，恢复通知只读刷新，不重建页面，不自动重发业务副作用。刷新轮换结果未知时保留会话和草稿，阻止重发原 refresh，明确要求重新认证。

## 首次 CI 失败及定向修复

首次 CI 候选 b42025e7 的 recovery-qualification 在 `startup-readiness.test.ts` 等待 leader lease acquisition 超时。直接原因是本次变更把单次 API 初始化移到获取租约之前；测试持有真实 `agent_security_policies` 表锁，HTTP 已存活，但初始化被锁阻塞，尚未取得租约。该失败为本次引入，不能靠延长等待或盲重跑解决。

dc27b941 将单次 API 初始化交回初始 WorkerStartup：先取得租约，初始化期间继续续租，恢复代次不重复初始化 API。初始化未完成不得启动新后台代次；不可恢复的首次启动失败会经过最终清理后退出、释放租约。保留 standby 的既有 API 行为（包括登录），后台触发仍受 requireWorker 限制而返回 503。

启动验收的旧断库判据要求进程退出，与本任务新行为冲突，现改为验证数据库 pause 时 readiness 503、HTTP 存活、后台代次不替换，unpause 后同一 PID 恢复并只启动第二个 Agent 实例。pause 恰逢在途原生 SQL 时可以进入 WORKER_DRAIN_BLOCKED；必须等原操作结束才能建立新代次。脚本请求 deadline 从 4 秒改为 7 秒，以接收服务端 5 秒 readiness 边界的实际 503；未增加服务端边界。隔离 MySQL 使用 512MB 上限及小缓存，结束删除自己的容器与匿名卷，失败打印已完成阶段及脱敏子进程日志。

修复后本地复验：生命周期 22 项通过、2 项环境依赖跳过；安全 336 项通过；后端 typecheck、contracts、secret scan 通过；lint 0 错误、284 个既有警告。未修改前端，沿用上表前端全量与 build/CSP 结果。最新 CI 结果由 PR 实际检查提供，不把本地复验视为 CI 通过。
