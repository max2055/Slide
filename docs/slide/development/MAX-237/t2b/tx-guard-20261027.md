## 2. R1：事务连接处置

`up`/`down` 的复制事务统一走 `runCopyTransaction`：

- 连接只在**服务端确认 commit 或确认 rollback** 后 `release()`。
- `getConnection`/`beginTransaction` 失败、`rollback()` 未确认、`commit()` 抛错 → `destroy()`，且
  `destroy()` 抛错不覆盖原失败、不回退 `release()`。
- `commit()` 抛错后不再猜测结果、不重放写入：用连接池的新连接只读重查 source/target manifest，分类为
  `commit-not-applied`（目标为空，服务器未提交）、`commit-unconfirmed`（目标等于期望 manifest，服务器已提交，
  只是确认丢失）或 `commit-unknown`（其他/重查失败）。分类结果不声称 rollback 已撤销成功的 commit。

| 证据 | 性质 | 结果 |
|---|---|---|
| Chief `migration-probes.json`（复审提交 `5767be919`） | 真实 MySQL，base `0098555a7` | up/down 均 **FAIL**：`releases=1 destroys=0`，无关事务后目标出现 2 条 parent |
| drill 步骤 14 / 27 | 真实 MySQL，故障 wrapper 仅不转发 rollback，socket 存活；独立 observer 读取 | `destroys=1 releases=0`，无关 `BEGIN/COMMIT` 前后五表均 0，source/candidate 不变 |
| drill 步骤 11 / 12 / 26 | 真实 MySQL，正常 rollback | `releases=1 destroys=0`，目标为空、源 manifest 不变 |
| drill 步骤 13 | 真实 MySQL，begin 未转发 | `destroys=1 releases=0` |
| drill 步骤 15 | 真实 MySQL，destroy 自身抛错 | 原失败保留，`releases=0`，未回退 release |
| drill 步骤 16 | 真实 MySQL，COMMIT 未发出 | `commit-not-applied`，目标前后均 0，源不变 |
| drill 步骤 17 | 真实 MySQL，真实 COMMIT 成功后丢确认 | `commit-unconfirmed`，目标 manifest = 期望；随后显式 `up` 为 `no-op`，无重复写入 |
| drill 步骤 18 / 28 | 真实 MySQL，连续 destroy 后同 writer 池 | 正常 commit `releases=1 destroys=0`，证明池健康 |

故障 wrapper 带 `fault:` 前缀的注入消息，仅用于制造事务边界故障；所有通过/失败数据均由独立连接读取，
不把 wrapper 或 mock 当作真实事务结果。原 18 步 drill 的 rollback 注入、manifest、no-op、漂移、不可表示
down 拒绝与安全 roundtrip 全部保留（现为 30 步，见 `evidence/t2b-drill.json`）。

`source=max237_t2b_d1`、`candidate=max237_t2b`、`restore=max237_t2b_restore` 做显式冻结结构比对：

- 列集合（缺列/额外列）、`COLUMN_TYPE`、nullability、字符集/collation；
- 表 engine 与 collation；
- 主键、`uk_content` 唯一索引、`idx_canonical` 及 T2B 的 128/16 前缀、其余保留索引；
