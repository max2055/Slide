## 隔离演练及复现

```bash
pnpm --filter slide-api exec tsx ../../scripts/qualification/max681-isolated-rotation.ts \
  --real --output "$MAX681_EVIDENCE_DIR" \
  --mysql-image "$MAX681_MYSQL_IMAGE" --dameng-image "$MAX681_DAMENG_IMAGE"
```

由执行者显式提供本机缓存镜像及绝对输出目录；达梦镜像安装位置通过 `MAX681_DM_INSTALL_DIR` 注入。路径/镜像身份在私下交接，不从公共样例猜测。可增加 `--database mysql` 或 `--database dameng` 单独复现。无参数退出 1，未启用时不创建容器；不读取共享 manifest、原环境或真实凭据。镜像 `--pull=never`，只创建带本次随机标签的独立容器、匿名数据卷和随机账号；清理先核对完整容器 ID 和标签，失败单列，不处理共享容器。

隔离 MySQL 8.4 与达梦已通过初次演练；发现实际平台 MySQL 主版本为 9 后，另用共享平台所用镜像的独立新容器验证，避免把 8.4 结果冒充真实版本。镜像导入时未保留默认启动命令，已显式提供 MySQL entrypoint/命令；不是更改共享镜像或容器。达梦也用同镜像的新容器，数据目录独立，未挂载既有数据。

演练覆盖：旧账号成功→数据库改密确认→旧凭据新连接认证被拒绝→新连接和 SELECT 授权通过→模拟消费者配置未更新→用已确认的新值向前改为另一独立值→新旧认证对账→原密文读取和原密钥解密保持。无未知 DDL 回执被自动重放。JWT 使用生产配置校验及现用签验库验证旧签名拒绝、新签名通过，**未覆盖真实应用登录、实时权限或 WS 会话**。

MySQL、达梦均观察到旧连接在改密后仍可查询。真实窗口必须排空/重建所有旧池；旧密码新连接失败不等于旧会话已吊销。演练账号是隔离普通查询账号，尚不能代替实际管理员授权、插件、备份恢复和业务采集验收。

## 持久 manifest 注入：具体差异与作用范围

已只读检查 15-Coder-01：当前 `has_custom_env=false`、`custom_env_key_count=0`；运行中的本任务环境也没有自动注入。已准备仓库外 0600 提议载荷，**未提交或应用任何 agent/daemon 配置变更**。

```json
{
  "custom_env": {
    "SLIDE_TEST_RESOURCE_MANIFEST": "<private-absolute-manifest-path>"
  }
}
```

由 owner/admin 在私下核对载荷后使用平台支持的入口：

```bash
"$MULTICA_CLI_PATH" agent env set <agent-id> --custom-env-file <private-payload-file>
```

该命令替换完整 custom_env，不是 JSON patch。当前零键只是一份快照；执行前重新核对，若出现已有键则由 owner 安全读取、合并并备份，不能覆盖其他配置；禁止将明文环境输出到 Issue。agent 身份不能读取明文环境或自行代 owner 写入。

上图表示 agent 记录差异；实际 `--custom-env-file` 文件是内部的键值对象，不含外层 `custom_env` 字段。提议载荷已按这个 CLI 格式准备在受限位置，未应用。

此设置针对一个 **agent**，在 daemon 下一次 claim 任务时读取，已有运行进程不随之改变；并非天然限定 Slide 项目。先只提议指定实现 agent，后续复核者/其他 agent 必须逐个确认权限与运行宿主。若该 agent 还执行其他项目，owner 须明确接受此路径元数据的作用范围或改选既有 Slide 专用执行身份；本任务不新建身份，不给全 workspace/daemon 广泛注入秘密。载荷只含 manifest 路径，不含数据库密码或密钥。

跨任务验证由 owner 协调两次正常、独立 claim：一次在当前宿主另一工作树，一次在复核执行身份。各自检查环境键存在、所选引用权限和只读连接，记录运行 ID、head、身份摘要、所选逻辑资源与结果，不打印值。默认收集缺环境仍不读私有文件，显式真实入口缺环境必须报错。异机/容器先提供该身份受限文件和安全注入，再单独验证，不能假设同一绝对路径可达。

恢复注入配置时只恢复本次新增键的原状态，保留同时新增的其他键；新任务验证恢复生效，不重启共享 daemon，不更换账本或加密密钥。上述作用范围、载荷及两次 claim 的操作尚待具体方案确认。
