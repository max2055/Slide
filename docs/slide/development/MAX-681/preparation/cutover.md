# 真实切换执行清单

本清单可用于逐项执行与签收，尚未获得窗口和资源 owner 确认。所有“待确认”字段必须在进入相应步骤前填写；无签收即停止该步骤。Chief 协调 owner/admin，实施者采集技术证据；独立复核与消费者确认按 PLAN.md 执行。

## 开窗前的执行记录

在受限 evidence 目录建立一份不可公开的运行记录，公开报告仅记录摘要/哈希：

| 字段 | 当前值 |
|---|---|
| UTC 开始/结束、当地日期、时区（连续60分钟） | 待确认 |
| 资源 owner / 平台服务 owner / 数据库管理员 | 待 Chief 指定并签收 |
| 全部消费者、负责人、暂停/恢复签收人 | 待确认；不得由静态引用清单推定活动占用 |
| manifest 版本/哈希、owner/权限/引用可读性 | 执行前核对 |
| JWT 加载方式、所有实例、重启/会话失效方案 | 待服务 owner 确认 |
| MySQL 账号 Host、认证插件/权限、管理连接 | 待数据库 owner 核对 |
| 达梦实际账号/授权、驱动、容器身份/启停许可 | 待数据库 owner 核对 |
| 明确的受限写入/恢复脚本、脚本哈希及目标摘要 | 待现场账号身份核实后形成；隔离账号 SQL 不能直接套用 |
| 当前候选 head、进程 PID→端口→cwd→命令→head→日志 | 执行前记录 |
| 数据恢复备份 ID、加密密钥引用、唯一账本摘要/未决条目 | 执行前记录，秘密仅在受限材料中 |
| 未知结果联系人/停步决定人 | 待 owner 签收 |

每个消费者各建一行：consumer ID、运行位置安全引用、依赖资源、当前配置版本、连接池/调度入口、暂停步骤、最后已知成功业务点、在途 request/transaction ID、结果已知/未知、恢复点、恢复验证、owner、签收时间。至少覆盖 API HTTP/WS、后台调度/采集、平台 DB manager、Provider/恢复 CLI、手工冒烟、真实数据库验收脚本，以及全部活动验收任务。CI 隔离资源单列并证明不连接共享目标。

## 前置执行与退出条件

1. 读取实际 manifest 的选中逻辑引用，执行已存在入口：
   `node scripts/qualification/test-resource-manifest.mjs --real --resource slide-platform`；其他资源逐个选择 mysql-test、pg-test、oracle-test、dameng-test、linux-test、model-test。只验证可读性，不当作连接成功。
2. owner/admin 重读固定 agent ID 的现有 env，备份并合并 manifest 路径键；作用范围按既有跨项目确认执行。两次独立 claim 记录 run ID、head、身份、选中逻辑资源及只读连接结果。未确认/未注入，不进入共享写入。
3. 使用项目实际驱动显式传入选中引用做只读认证，核对真实账号/授权、服务器版本和目标身份；VM 核实租约。任何目标不一致、消费者未知或备份不可读即停止。
4. 暂停所有消费者发起新任务/重试和调度；记录已完成检查点。等待已知在途事务结束，超时只登记未知回执，不重放；需取消/终止的精确事务须由 owner 确认。
5. 采集原业务行数/关键主键摘要、选中既有密文读取/解密结果、备份可恢复证据；唯一账本保留 used/reserved、请求条目和文件哈希，检查锁归属。发现未决模型请求先对账，禁止重置账本。本清单不需要模型生成请求。

## 切换与业务验收

| 步骤 | 动作与成功证据 | 失败/未知结果 |
|---|---|---|
| R0 冻结与快照 | 所有消费者暂停签收、进程/账号身份、受限备份和检查点完整；Reviewer 通过适用执行材料 | 前置缺项即停，不以服务探针代替 |
| R1 JWT | 独立随机新值落入受限配置；按已核对实例重新加载；旧令牌请求被拒绝，新登录成功；保留角色与无权限对照 | 核对每个实例当前加载版本；用确认的新值向前修复，不还原公开值 |
| R2 平台 MySQL | 已建立管理连接上执行经过核对的真实账号变更一次；记录服务端确认；原子更新全部配置引用 | 超时保留请求 ID，先通过管理连接和独立新连接核对账号状态；不得盲重发 ALTER |
| R3 排空旧池 | 对全部登记消费者关闭旧池、创建新池；核对旧连接/事务的终态；旧凭据独立新连接认证失败，新凭据查询与必要授权成功 | 旧连接仍存活不等于改密失败；按精确会话处理，不按端口杀进程；未知事务继续停步 |
| R4 达梦 | 核对账号/授权/驱动后重复一次确认变更与全部消费者切换、新旧认证和实际采集验证 | 停在已确认检查点，用受限新值向前恢复；不更改未知账号 |
| R5 观察签收 | 全部业务验收、数据/密文/备份/账本对账与消费者恢复签收，记录实际时间和证据索引 | 任一消费者未签收，不能宣告全部切换；保留暂停范围及恢复负责人 |

JWT 业务矩阵：旧 token 的 HTTP 请求拒绝；旧 WS 的存量连接按既有会话策略断开/拒绝后续消息；新登录和新 WS 建连/消息成功；合法角色业务请求成功；低权限角色拒绝；登录后撤销权限的后续 HTTP/WS 操作按实时权限拒绝。不把隔离签验库测试替代上述矩阵。取证只留状态码、审计 ID 和脱敏摘要，不留 token。

数据库业务矩阵：旧认证新连接失败、新认证真实驱动连接/最小SQL成功、必要权限与越权拒绝、平台配置读写、任务独占对象的实际采集产生可追踪记录；恢复已暂停消费者后检查任务队列/检查点无丢失或重复。测试对象按任务隔离并在核对归属后清理。覆盖两个真实账号的所有 Host/授权与读取方，不以容器环境变量推定账号已变更。

原冒烟入口使用受控注入 SMOKE_BASE_URL/SMOKE_USER/SMOKE_PASS 执行
`pnpm --filter slide-api exec tsx tests/smoke-test.ts`；该脚本只是业务矩阵的一部分，不证明 WS/所有采集或存量会话处置。实际脚本目标与密码在内存/受限注入中传递，禁止在命令行展示。

## 保全与收尾

用同一选中样本对账原密文可读、原加密密钥引用未变、关键业务数据/备份恢复成立。账本请求历史、used/reserved 和锁归属逐项比较：没有测试调用时内容应保持；如有授权并发消耗按唯一请求条目解释增量，不用哈希不同推定损坏，也不复制另一本账。

消费者恢复只恢复确认的业务检查点；未知副作用先对账，不自动重放。恢复代码仍引用新秘密。R5 后再运行受影响回归和当前集成候选完整 gate，独立复核执行证据；发布包设置统一 RELEASE_OUTPUT_DIR，逐包检查300000000字节限制、校验和及独立扫描。历史和外部副本另按 history-disposition.md 获批处置，不能因真实轮换完成自动关闭 E1。
