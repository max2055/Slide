# 历史及外部副本处置方案

只读盘点于 2026-11-17 完成。7580 个 Actions 元数据合计 17170973841 字节；其中 2 个有有限内容审计，其余 7578 个未做内容审计。0 个 Release，1 个 fork。远端快照有 1081 条广告：1079 个命名 ref（517 heads、561 pull refs、1 个附注 tag），另有 HEAD 别名及该 tag 的一条 peeled 广告。peeled OID 仅关联到 tag，不是独立更新目标；pull refs 为托管方管理对象。远端查询不是托管方内部引用完整枚举。

精确对象快照和逐对象动作位于受控 artifact-disposition.json 与 ref-disposition.json，包含 artifact ID/name/run、ref 原 SHA、权限及恢复约束；不使用会随时间扩大的“删除所有”目标。执行前必须重取快照并审核差异，新增对象不自动继承批准。

## 历史与 LFS

检查本地全部可达 97281 个对象，对不超过 1024 字节的 blob 验证 LFS 指针格式，结果 0；当前环境没有 git-lfs。仅代表本地可达闭包，不覆盖远端独有 refs、已删除对象、较大非标准指针或 LFS 服务端孤儿对象。641 个触及登记路径的历史 commit 已列出，仅为调查候选，不当作641个泄漏提交。

下一步由实施者在受限独占镜像中 fetch 快照列出的 heads/tags/可获取 pull refs，记录不可读取 ref；由 repository admin 提供服务端隐藏 refs/LFS 存储盘点。对对象闭包做独立格式扫描与受控秘密内存精确比对，输出 blob OID、路径、命中类型及 ref 可达性，不输出值。只有核实的对象进入改写清单，不能按路径命中过度删除整段历史。

历史替换规格应使用受限输入文件，公开预览只列 blob OID、路径、ref 原/预计新 SHA、受影响 PR 和迁移策略。当前不具备全部历史内容的确认清单，因此不得执行改写；该项明确未闭环，不把路径调查清单充作最终精确替换规格。

## 备份、权限、恢复及验证

1. repository admin 确认每个目标 ref 的写入权限、分支保护与协作冻结；fork 由其 owner 单独授权。GitHub read 权限不等于改写/删除权限。
2. 在仓库外 0700 目录制作 mirror 与 bundle，保留 ref 原 SHA、对象清单、校验和、工具版本、时间及保管 owner；备份含已暴露秘密，禁止上传公开附件。git fsck、bundle verify 和独占离线 clone 必须成功后才能继续。
3. 在第二份独占镜像离线预演改写，记录每条 ref 旧/新 SHA 对应；核对业务树/迁移字节、tag 签名变化、PR diff、失联 commit。重新格式扫描和受控比对后，由 Reviewer 复核精确差异；向用户申请此固定快照的历史改写/强推授权。
4. 获批后按逐 ref 期望旧 SHA 条件写入；出现并发变化停止该 ref，不使用无条件批量强推。托管方 pull refs/缓存可能需支持团队处理，不能承诺本地推送清除它们。
5. 恢复首先保护业务树与已轮换秘密。旧 mirror 仅在受限环境用于调查/恢复代码，不能直接重新公开暴露值；恢复公开 ref 另经审批、重新脱敏及复核。
6. 重新列远端 refs，并核对新对象扫描、CI、可克隆性、业务迁移 checksum；协作者按固定 ref 映射重克隆。第三方 clone/搜索缓存不能强制销毁，登记通知、回执和平台限制。

## Actions、fork 与外部副本

逐 artifact 下载须验证完整 ZIP、tar 内校验和、RELEASE commit、解压安全与大小限制，格式扫描要覆盖解压内容、图像/字体及构建文件。当前只复用两份既有 artifact 的有限结论；不能把7580项元数据当作内容覆盖。下载先预算磁盘和受控保留期限，不输出秘密。

确认含暴露值的 artifact：先完成秘密失效和依赖恢复点，由 admin 按 artifact ID 明确批准处置；备份 payload/hash/发布元数据，删除前回读 ID/run/name，删除后读 API 验证404和下载不可得。删除不可恢复原 artifact ID，恢复只能另行发布已扫描新包；所需历史 payload 不能安全备份时停步。未确认对象保留待审，不按宽匹配数量批量删除。

fork 精确仓库名见 coverage.json；Chief 联系其 owner，提供不含秘密的受影响对象和替换 ref 对照，获取处理/延期签收。外部 clone、邮件附件、缓存及未知副本无法从仓库 API 穷举：由资源/产物 owner 登记去向、是否含旧值、保存/删除权限和回执。没有用户明确接受的延期范围、owner、风险和截止日期，E1 保持未完成。
