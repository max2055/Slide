# 质量门与独立复核规则

生效日期：2026-10-25。触发范围：所有功能、安全、运维和发布脚本改动；凭据、备份/恢复、权限、审计、部署流程类改动强制执行独立复核。根目录 [AGENTS.md](../../../AGENTS.md) 第 3、5 节继续适用。

## 1. 为什么需要

2026-10-25 #244 复核案例：实现方 112 个单测、5/5 MySQL 演练和真实连接测试全部通过，独立复核仍发现两处问题：

- URL 查询凭据白名单只覆盖已知名称，`x-api-key`、`subscription-key`、`clientSecret` 等变体原样进入备份产物，脱敏扫描报告 0 findings；
- 文档声明退出码 2/3/4，但推荐的 `pnpm provider-config` 入口把非零码归一为 1，按文档判断的自动化会失效。

根因不是测试数量，而是：用例按实现写而非按需求威胁模型写；验证走内部函数而非文档入口；实现方自证缺少对抗视角；真实证据不可复现；同一任务被并发会话重复实现。

## 2. 两个审查维度

独立复核不是重复实现方自检。两个维度都要有明确负责人和交付物。

### 2.1 实现方自查：业务语义与数据保全

- **路由与默认值**：禁用对象时同步清理默认标记，避免路由选中已禁用项；场景绑定与默认回退行为与运行时一致。
- **数据保全**：能禁用不删除；密钥/密文保留；悬空引用按既有产品决定保留，不静默改变路由。
- **锁与事务**：快照/回滚与业务写入使用同一事务视图；连接归属、锁范围和顺序明确，持锁期间不嵌套申请连接；覆盖小连接池和并发竞争。只有确认回滚且可安全重放的事务才允许有界重试，未知 SQL 结果不得自动重放。
- **回滚一致性**：回滚产物本身经过同一脱敏/校验流程，且能精确恢复到事务观察到的状态。
- **兼容性**：旧数据（空字段、历史格式）可 round-trip；结构约束复用应用自身校验。权限/校验变更成组覆盖正常请求、历史合法输入、非法输入、角色变化、授权撤销和保留的资源上限；修改旧断言说明对应需求依据。
- **运维闭环**：文档写清运行时缓存刷新、重启/热加载、业务高峰限制等生效条件。
- **文档契约**：新增命令、退出码、默认路径、禁止项必须按文档入口实际执行过。

### 2.2 独立复核：威胁模型与接口契约

复核者使用新上下文，先读 issue 验收标准，再看代码；不继承实现方结论。

- **默认拒绝**：安全控制按 deny-by-default 设计；问“名单之外、格式变体、未知输入会怎样”，不接受“已知列表都覆盖了”。
- **对抗性输入**：为每个安全边界构造变体（大小写、`_`/`-`/camelCase、百分号编码、前缀、同名不同义），确认失败是拒绝而非放行。
- **独立二次扫描**：脱敏/过滤后的产物由与过滤器不同实现的扫描器复核；两者不共享同一份名单认知。
- **文档入口**：按文档中的命令、相对/绝对路径、退出码实际执行，而不是直接调用内部函数。
- **证据可复现**：核对 commit、命令、输出、审计查询、产物哈希与处置；证据不成立时按未验证处理。
- **范围与副作用**：只提交本任务文件；真实环境操作限定为最小只读或可回滚步骤。

## 3. PR 质量门

在 AGENTS.md 第 5 节验证要求之上，PR 合并前逐项确认：

- [ ] 每条 issue 验收标准对应第 5 节证据包，命令按完整入口执行，所有必选检查和包装脚本均成功。
- [ ] 安全边界按默认拒绝设计，包含“名单外/格式变体/未知输入”用例。
- [ ] 文档新增或修改的命令、退出码、默认路径已按文档入口实跑，输出与文档一致。
- [ ] 实现方自查覆盖路由、默认值、锁/事务、回滚、兼容与运维生效条件。
- [ ] 安全/运维类改动通过独立复核；复核意见有明确处理结论（修复或记录理由）。
- [ ] 无并发会话、重复分支或重复 PR；分支与 issue 归属明确。
- [ ] 缺陷及文档契约按第 7 节闭环；新增代码通过 `pnpm ci:source-policy`。

## 4. 分层验证

| 层级 | 覆盖 | 不能替代 |
|---|---|---|
| 单元/契约测试 | 纯逻辑、边界、对抗变体 | 真实 schema、事务、外部连接 |
| 一次性真实环境演练 | 真实 schema、事务、回滚、审计 | 生产配置与外部依赖 |
| 真实环境最小验证 | 集成链路、真实连接、权限 | 全量回归、异常矩阵 |
| 独立复核 | 需求威胁模型、文档契约、证据 | 实现方对业务语义的深度 |

- 单测必须随 CI 运行；一次性演练放固定命令或发布/夜间门禁，不占用关键路径。
- 真实业务验收和证据时效按根规则第 5 节执行。

### 4.1 按变更选择验证

| 触及边界 | 编码及验收约束 |
|---|---|
| 数据库迁移 | `MODIFY COLUMN` 显式保留 comment、默认值、字符集/排序规则等需要保持的属性；验证空库、旧版升级、重复运行和最终 schema invariant，不修改已应用迁移绕过 checksum。复用现有迁移门禁。 |
| 共享接口 | 事务/连接锁等必需能力用明确类型表达，避免可选能力到运行时才失败；核对生产调用方、包装器和测试替身，运行受影响契约与集成用例。 |
| 测试配置 | 默认收集不得读取本机凭据；显式启用真实验收时缺配置应报错，不静默跳过。测试 schema、端口、输出和容器须可隔离，清理仅处理本任务对象。 |
| 初始化与外部命令 | 记录阶段耗时和失败阶段，为初始化 hook、命令及整个作业分别设置有依据的有限预算；先定位慢阶段或阻塞，再调整局部预算。禁止以统一加大超时、自动重跑、跳过用例代替修复。 |
| HTTP/WS/浏览器夹具 | 先停止生产请求的客户端，等待或撤销在途路由/请求，再关闭服务和数据库；失败及清理异常分别保留，不让后者覆盖首个有效错误。 |
| 观测及门禁包装器 | 分别记录测试退出码、观测错误和清理错误；测试通过不代表完整命令通过。必须的证据采集仍失败关闭，禁止为变绿删除观测或吞掉退出码。 |

### 4.2 自动检查边界

`pnpm ci:source-policy` 检查相对 HEAD 的新增行（含暂存、未暂存和未跟踪文件）；`pnpm ci:source-policy <base> <head>` 检查提交区间。CI 在 plan 阶段运行同一入口，PR 使用 base/head 的共同祖先，push 使用 before/head，定时和手工运行检查最新提交。

检查代码目录中的开发者 home 绝对路径、私有 `slide-test-access` 路径和直接的 `test/it/describe.only` 声明。报错只输出文件、行号和规则，不输出可能含凭据的源码。存量未修改行不追溯；重命名按删除与新增文件处理，目标文件重新扫描；文档和整行注释不扫描，手工验收脚本也不能新增硬编码个人目录。

这是增量文本检查，不能识别动态拼接路径或全部测试 API 写法，也不能证明迁移、权限、资源隔离或生命周期正确；这些仍按第 4.1 节验证，不新增重复的 SQL 检查器。

## 5. 验收证据包

真实环境或跨模块验收至少保留：

```text
commit（完整 SHA；未提交变更另附 diff 哈希）：
任务/issue：
执行的完整命令、配置来源及选中的测试范围：
退出码和关键输出摘要（测试/观测/清理分别记录，不含密钥）：
审计查询与结果：
产物/快照哈希与处置方式：
未完成项与环境限制：
```

存放位置：`outputs/<task>-acceptance-<commit>/REPORT.md`（不入库）。PR 描述链接证据包，不粘贴产物内容或密钥。

## 6. 并发与归属

- 一个任务只分配给一个会话/负责人；开工前核对 `git status`、`git log -3`、`gh pr list --head <预期分支>`。
- 发现已有分支/PR/并发会话时先确认归属，不重复实现；确需接手时由用户明确切换 owner。
- CI 失败以“首个失败阶段/用例 + 错误码或关键断言”归并，记录受影响 run/job/SHA；同一根因在多个分片、`release-artifact`、`ci-gate` 的传播不重复建单。建单前查已有任务和 owner；交接保留原任务、根因、复现入口、已验证提交及未完成项。同一问题不重复实现或审查，除非用户明确要求独立交叉验证。

## 7. 缺陷闭环

- 复核发现的问题修复后必须补回归用例；用例名或注释引用问题来源。
- 文档中新增的每条承诺（命令、退出码、路径、禁止项）都要有对应的可执行检查或人工验收步骤。
- 失败先按根规则第 5 节分类；无关问题记录为 backlog，不进入本次修复范围，但必要门禁未通过时不能宣称可合并。无 job/日志或证据不足时标注未知，不凭红灯推断代码原因。
