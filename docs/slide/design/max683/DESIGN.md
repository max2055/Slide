## 设计判断与现状问题

工作台首先帮助用户决定“先处理哪件事、为什么、下一步是什么”，随后帮助用户判断“流程推进与业务恢复是否一致”。菜单并入完成了入口收敛，但尚不足以形成决策首页。

## 信息优先级

| 优先级 | 用户决策 | 显示信息 | 取舍 |
|---|---|---|---|
| 1 | 我现在能做什么 | 服务端资格对应的下一步、需处理原因、事项标题与目标 | 不将所有 pending_approval 都算作我的待办；不显示未经授权的事项数量 |
| 2 | 为什么要先处理它 | 当前结论、影响、明确归属的更新时间、证据不足/失败/未知回执 | 无严重级别时不编造紧急度；更新时间不充当等待起点 |
| 3 | 事情走到哪里 | 调查状态、计划审批、执行状态、恢复验证分列 | 执行 succeeded ≠ 验证 passed ≠ problemStatus 已恢复 |
| 4 | 判断是否可信 | 证据摘要、时效、缺口、有效期、来源版本 | 缺失不显示零或通过；跨域无权时不给来源标题 |
| 5 | 如何核验与追溯 | 完整参数、ID、哈希、审批记录、原始证据 | 首页不铺陈；审批/执行之前仍须完整可读，不省略确认条件 |

- [详情 1440×900](detail-1440.png)：左侧结论、范围、证据与必要条件；右侧下一步及阶段状态，原始资料折叠。
- [详情 1366×768](detail-1366.png)：首屏看得到结论、目标、影响、有效期和操作入口；长证据正常纵向滚动，操作区不覆盖正文。
- [首页 1920×1080](home-1920.png)：保留业务密度，扩展列宽，不增加装饰或额外仪表盘。

推荐先用完整详情页，保留列表筛选、滚动和原 returnTo；从旧链接可直接进入。Chief 提出的侧边详情适合快速预览，但审批/证据链文字长，在最小桌面尺寸下会挤压列表。因此本轮选择完整详情作为首版，暂不再建设等价侧栏入口，避免双路径。

需要处理首版命名与说明为“每调查一个当前下一步”，使用现有 workspace-attention 分页；仅遍历 open/waiting 调查，优先命中一个执行，否则命中一个计划即停止；同调查最多一行。不是所有计划/待审批逐条清单，翻完全部页仍不能发现该调查的其他计划或已关闭调查历史。首页持续展示“完整调查列表 / 完整行动列表”入口，按授权逐页发现，不扫描全库、不扩权、不承诺全域总量。进行中/已结束不能通过首屏客户端拼接来宣称完整统一排序。若不补统一投影，过渡实现保留调查/行动类型筛选及各自分页，明确当前类型和范围。默认入口命名先用“需要处理”，不承诺统一派工负责人机制。

列表一行只给一个读取型下一步。审批进入既有独立审批流程，执行进入既有确认弹窗，首页不提供一键执行。URL 保留 plan/investigation、版本/哈希/报告/执行引用及 returnTo；沿用现有 attentionUrl 语义和旧链接兼容。实现验收要求返回恢复原筛选、页游标、滚动与焦点，浏览器前进/后退一致；当前原型未实现该能力，详见下文。

## 状态与权限规则

| 状态 | 首页表达 | 详情与下一步 |
|---|---|---|
| 待审批 | 待独立审批；目标、影响摘要 | 先审阅确切版本与有效期；作者不可自批；无资格不出现审批动作 |
| 进行中 | 调查运行中 / 执行中 / 验证观察中 | 分别展示阶段，不虚构百分比、ETA；读取当前请求，不重复派发 |
| 验证失败 | 执行状态与验证失败同时显示 | 展示 reason 与观察窗口；读取报告；不自动执行或重试 |
| 证据不足 | 无法判断恢复，显示缺口 | missingSamples、reason、证据时效；核对证据，不写成故障已恢复 |
| 未知回执 | 结果未确认 | 核对原动作，禁止盲目重发 |
| 空数据 | 当前页没有事项 | 区分未筛选无记录与筛选无结果；有下一页必须提示，不能宣称全局无待办 |
| 加载/失败/部分失败 | 骨架或读取失败，独立重读按钮 | 保留资格 unavailable 提示；未知数量不显示 0；不保留已撤权敏感资料 |
| 无权限/登录失效 | 无读取权限时不加载该域，不显标题或计数 | 404 使用“不可访问或不存在”；401 引导重新登录；撤权清空详情和草稿 |
| 过期/版本变化 | 已过期或版本变化 | 操作禁用；只读刷新核对当前版本，不沿用旧批准 |

原型底部提供待审批、进行中、验证失败、证据不足、空状态、权限受限的状态入口；不是生产新增菜单。失败/证据不足摘要展示演示 reason、missingSamples、observedFrom/Until 和报告引用；未绘制完整原始报告。加载、部分失败、过期等以本表作为后续实现验收约定。

| 调查结论、阶段、负责人 | InvestigationRecord problemStatus/lifecycle/derivedRunState/latestOutcome/owner/updatedAt | 已有；owner 是调查归属，不等于待办 assignee，也不保证有人名 |
| 验证缺口与过程 | ReportView reason/missingSamples/observedFrom/observedUntil/evidence/before/readiness/observation | 详情可用；需按版本和执行引用读取，不挪用上一轮报告 |
| 待办行上的目标、阶段结论、原因摘要，以及独立行动标题/事项更新时间（若后续需要） | WorkspaceAttentionItem 本身没有全部这些字段；行动标题须来源绑定计划，计划时间来自 plan.updatedAt，报告时间须对应绑定报告的可靠时间，不能以调查时间代替 | 可复用授权详情，但不能逐行无限 N+1；若首页要求完整列，后端负责人评估为现投影补齐最小只读摘要，名称/字段契约由后端确认 |
| 逐计划覆盖、已关闭调查历史覆盖 | attention 每调查一个 next step，仅 open/waiting | 首版保留投影，以完整类型列表弥补发现路径；如要求首页逐计划覆盖，属于后端投影范围变更，待确认契约。不可只用“有界分页”解释 |
| 全域严重级别/影响排序、等待起点、统一游标、完整总数 | 当前 attention 只限有界记录窗口；items.length/authorizedCounts.total 不是全域总量 | 真实缺口。首版不显示全局总量、等待时长、严重级别或客户端全局排序；如确认需要，再由后端设计权限内统一投影，不发明现成 API |

注意现有 attention 需要 chat:view；仅行动权限身份不能直接复用此入口获得待办。该身份保留授权行动计划列表作为首页降级，不显示调查摘要或暗示无待办。不为视觉整合扩大权限。统一首页可用性需覆盖仅调查、仅行动、两者都有、两者都无。

## 本轮 Must Fix 对照与实现验收约定

1. **覆盖单位与完整发现**：首页说明每调查一个下一步，并固定完整类型列表入口。演示调查 A 同时有待审批计划 A1（15:42）与 A2（15:46），调查更新时间为 15:20：首页仅显示 A 的一个下一步，进入完整行动列表可逐条发现 A1/A2 并读取第二个计划。已关闭调查 H 不进入 attention，但其授权历史计划 H1 可从无状态过滤的完整行动列表读取；H1 示例已过期，只读。调查完整列表也保留 H 到行动列表入口。若用户只有行动权限，直接降级完整行动列表，不发 attention、不展示来源调查摘要；仅调查、双权限、均无权限及实时撤权仍须真实 API 验收，原型未模拟这些身份。
2. **字段语义**：V1 首页行标题为来源调查标题，列为“调查更新时间”。V2 将结论作为视觉主标题，title 明确标为“来源调查”辅助行，updatedAt 仍标“调查更新时间”，字段语义不变。A 行显示 15:20，不显示 A1 的 15:42；行动完整列表单独标记“计划更新”，A1 15:42、A2 15:46；H1 无可靠时间显示“未提供”。原型是演示值，不证明后端已有行动摘要投影。当前保留调查字段语义；若改用独立行动标题/事项时间，纳入最小只读摘要契约缺口，由后端负责人确认来源和缺失降级。
3. **对象与下一步**：首页“需继续调查”进入 `mode=continue`：调查面包屑、无活动请求、补证据后继续原调查。运行中是独立调查 R，通过完整调查列表或底部状态入口进入 `mode=running`：有活动请求、等待结果、只读进展，不提示再派发。两种状态不使用同一行互换；运行中不伪装 attention 的无行动 continue 分支。两页均去除行动审批、有效期与作者自批提示。

后续产品验收用例必须构造以上 A/A1/A2/H/H1 与两种请求状态，以真实授权数据分页发现，并核对调查/计划时间不同的字段；不能以原型点击代替。列表刷新后重新核验绑定与资格，游标失效明确重载，unavailable 与空页分别表达。首版进行中/已结束维持调查、行动各自分页；attention 不支持类型/原因过滤，原型 select 仅示意，不能静默对首屏过滤并宣称完整结果。若要服务端过滤或统一排序，先确认新契约。

### 导航与焦点恢复（实现前验收约定）

- 进入完整详情：路由内容就绪后将焦点移至详情标题（`tabindex=-1`），保留可见焦点；不自动聚焦审批/执行按钮。记录原触发对象、类型、过滤、游标及滚动位置；不依赖不稳定的列表索引。
- 返回或浏览器后退：恢复原授权列表的筛选/游标，数据渲染完成后恢复滚动与原触发行链接焦点。触发行消失、状态变化或撤权时，不恢复旧敏感行；优先同页下一条可访问行，否则列表标题，并说明列表已更新。游标过期时重新读取首页并说明上下文已失效。
- returnTo 沿用候选 workspaceReturnTo 的同源及允许路径校验；保留 plan/investigation、版本/哈希/报告/执行引用绑定，拒绝外域及不允许路径。新增上下文不能放开任意 URL。
- Tab/Shift+Tab 顺序可达，Enter 进入链接、展开原生 summary；详情页面 Escape 不隐式发起或取消业务。若打开既有确认弹窗，沿用焦点限制、Escape/取消和关闭后恢复触发控件的规范；触发控件失效则采用上述替代焦点。
- **原型限制**：仅静态 query 导航，所有返回仍回首页，不实现 returnTo、筛选、游标、滚动、焦点恢复、真实浏览器历史上下文及确认弹窗。未宣称这些产品行为验证通过。类型列表和运行状态只是演示发现路径，不是新接口或已完成产品功能。
