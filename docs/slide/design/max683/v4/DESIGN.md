## 核心选择

V3 将对象、依据和建议分别放入横向区域。此次反馈允许重新取舍三列，目标是减少来回扫读，让中文长建议有足够宽度。V4 采用“先形成判断，再核对依据”的纵向结构。

| 位置 | V3 的负担 | V4 选择与代价 |
|---|---|---|
| 首页事项 | 独立对象栏、正文和操作列；依据摘要常与结论重复 | 来源、状态、调查时间收为一行辅助信息；20px 结论与15px蓝色建议沿同一左边线排列；目标和依据定位后置。仅操作保留右侧稳定位置。移除单独依据摘要，需要细查时进入对应详情。 |
| 详情首屏 | 对象侧栏挤占主体，建议在1366下只有226px | 取消侧栏；结论26–28px，风险紧接；宽幅浅蓝建议区与主操作组成一个决策段。对象属性和阶段随后水平排列，完整详情仍沿页面向下阅读。上下文不固定在屏幕边缘，向下阅读需自然滚动。 |
| 证据 | 原因、窗口和报告绑定在正文与表格重复 | 恢复报告只保留一份引用表：原因/缺样与执行报告绑定一行，日期窗口一行。审批与调查保留不同的说明，不将所有类型套成行动报告。前置、验证及原始资料继续保留。 |
| 长建议 | 窄列多次断行，按钮与结论关系弱 | 1366实测建议文字区816px；普通建议一行，临时注入的长文样本三行，按钮保持右侧。自然增长、不截断，不用省略号隐藏决策内容。 |

科技感来自精确对齐、稳定字阶、浅色工作面和克制冷蓝：仅建议与主操作强化蓝色，边界按阅读段落使用细线，状态仍保留失败红与未知棕。沿用中文系统字体，不引入装饰动画、图谱、地图或官网式展示背景。

首页仍有一个辅助信息横行；这里的横向排布用于识别对象与时间，不要求在三块正文之间拼出建议。1440首页四项完整可读；1366第四项的目标/依据入口需滚动。详情1366普通状态的结论、风险、建议、主操作、对象属性和证据表可见；审批附加说明、处置条件和完整原始资料需继续向下读。主操作提前并不意味着可以跳过这些审批前置条件，实际审批仍必须独立确认。

## 与 AIP 研究的关系

本轮复用 V3 已实际浏览并经独立复核的来源与视频记录，不新增或冒称重新浏览研究。

- Analyst 的来源就近、明确对象与可追溯性（V3 研究 S1/S2）：保留同对象 `[1]` 定位与证据引用表；移除首页重复摘要。来源接近结论不要求它们必须横向并列。

- Actions 的读取与执行边界（S3）：首页是读取入口，详情业务按钮仍禁用，未来独立审批及显式执行确认不变；不引入自动提交例外。
- 官网展示与浅色构建器（S6/S5）：只作为风格区分背景；不将官网视觉或构建器误用为运维工作台规范。

纵向顺序、具体字号、816px宽度、浅蓝建议区均是 Slide 本轮适配选择，不是 Palantir 官方规范。来源原链接、视频时间点和证据存档见 V3 RESEARCH.md / sources.json。

## 数据、权限与原型能力

沿用主设计文档全部已审定约定：每调查一个当前下一步，仅 open/waiting；完整调查/行动列表为独立授权逐页发现入口，A2及关闭调查H的H1可发现，历史过期只读。调查时间不是计划时间，不推导等待时长、全域计数、紧急度或恢复成功。执行成功、验证通过、业务恢复仍分开；缺样表示未知，建议补证据而非重复执行。

首页摘要仍需最小只读契约，原型没有发明可用 API。chat:view 与独立行动权限、仅行动身份降级、逐条授权和实时撤权、版本/哈希/执行/报告绑定、安全 returnTo 均不变。无活动请求与运行中调查保持不同文案和入口。
