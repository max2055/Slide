# MAX-68: V2 semantic query boundary

`apps/db-ops-api/src/metrics-v2/query.ts` exposes `SemanticQueryService.query` and its pure `aggregate` reducer. Both canonical and extension observations pass through the same exact metric/version/unit/dimension checks. The caller supplies the authorized, pinned definition and policy; the service authorizes **every** requested metric/resource series before reading. Inventory attributes use a separate read with a separate, required resource authorization callback. No HTTP route or legacy API has been switched over.

`MysqlMetricStorage.queryWindow` reads normalized observations by the existing `idx_metric_v2_range` index. The window is `[from,to)`; one predecessor and one successor are supplied to the reducer for bounded intervals crossing its edges. More than 1000 observations per series/window or 1000 output buckets fails explicitly, never silently truncates. A query spans at most 31 days and 50 explicit series. The original legacy `range()` and historical AVG results are untouched.

Rules (the same reducer runs for live, historical, and downsampled windows):

- Input rows are validated against one exact semantic version, unit and dimension identity. At identical timestamps the lexically greatest ID wins deterministically; duplicates do not increase coverage. A time bucket is anchored at `from`, and its last endpoint is exclusive. No series is inferred from a template or grouped across incompatible definitions.
- Gauge `last/min/max/mean` uses actual samples. A requested time-weighted mean holds each sample until the next reading or `max_gap_ms`, whichever comes first, and clips that interval to the bucket. No interpolation over a gap. A spatial mean requires explicit positive integer population weights; an unweighted mean of differently sized populations is not substituted. A spatial sum/min/max uses only a definition that allows it.
- Coverage is the fraction of expected observation slots for sample, ratio, and histogram modes (distinct valid slots / `ceil(window_ms / interval_ms)`); interval modes (time-weighted gauge, state, counter) use covered milliseconds / window milliseconds. For spatial operations it is the arithmetic mean of per-series coverage, so a missing series cannot disappear. Below the definition's `min_coverage`, the value is null/unknown; partial but sufficient windows are marked partial. `sample_count` counts distinct physical observations inside that bucket, while `sources` retains all contributing inputs, including predecessor/successor. Freshness uses observed time, never an attempt timestamp or a future bucket input.
- Cumulative counter increments are processed per series with the shared MAX-66 counter processor (epoch, source, reset, gap and integer precision) **before** aggregation. An accepted increment crossing a bucket edge is allocated proportional to interval overlap under a uniform-within-interval assumption. Rate = allocated increment / covered seconds; reset or untrusted gap contributes neither value nor coverage. Invalid input breaks the baseline. A source/transform switch does not bridge epochs.
- Ratio pairs numerator and denominator at exactly matching time, resource and dimensions, skips missing or nonpositive denominators, then divides **sum of numerators by sum of denominators** across samples and selected series. Ratios are not averaged. A zero denominator without any usable pair returns `invalid_denominator`, not zero. State duration holds a state only through `max_gap_ms`, clips at bucket boundaries, and emits milliseconds (0 is a real measured duration when fully covered).
- Histogram `delta` samples merge only with equal finite/+Inf bucket boundaries. Cumulative histograms are first differenced inside one proven epoch and bounded gap; if a source has no predecessor, no distribution is generated. A distribution increment belongs to the bucket containing its ending observation (there is no justified within-interval distribution to interpolate). Quantiles from a merged histogram return its finite upper bucket bound as an estimated value; an unbounded result remains null. Summary quantiles can only be read from one last sample, never merged or averaged. No histogram or p95 is manufactured from scalar or summary-only sources.

Outputs contain semantic contract/version, unit, dimension identity (null for a spatial aggregate), window, quality, accuracy, coverage, freshness, physical sample count, and input IDs with source and provenance versions. `fixtures.json` contains synthetic, hand-calculable values; tests load it by module-relative URL. Revert is to stop calling this optional V2 service; existing APIs, migration history and old MySQL history need no rollback.
