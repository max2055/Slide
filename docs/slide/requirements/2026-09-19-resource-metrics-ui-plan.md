# 资源管理与指标页面 UI 优化方案

日期：2026-09-19。状态：设计建议，尚未实施。

修订记录：V1 建议将类型、型号及版本收进名称副行；V2 根据用户要求改为三类资源列表的独立默认列，并纳入筛选设计，以支持后续按类型、型号和版本定位资源。本次仅调整方案，不扩大实施范围。

## 1. 目标与范围

以“找到资源 → 判断状态 → 查看指标 → 处理问题”为主线，统一数据库、网络设备、服务器管理以及指标目录、采集包、采集策略、资源采集配置页面。

本次交付为方案，不修改业务代码、不改变指标语义、权限、采集策略继承关系或兼容协议。资源预算未设定，实际 token 遥测不可用；未使用子代理。方案以页面结构、字段、状态规则、依赖和验收清单完整为结束条件。

## 2. 现状依据

依据用户数据库截图及 main 工作树 `fde93a648369592fb6a65ca879ab562a5ad474a8` 源码静态检查。其他页面尚未进行浏览器实测，以下不视为运行时验证结论。

- `instances-db.ts`、`servers-page.ts`、`network-devices-page.ts` 均在资源表之外插入 `semantic-core-list`，同一资源重复列出。
- `semantic-metrics.ts` 把状态、维度、多个时间桶、质量徽章、覆盖率同时渲染进单元格，适合证据查看，不适合资源列表。
- 核心列表逐资源串行查询，全部完成后替换结果；合并布局时还需避免慢资源阻塞其他行。
- 数据库详情的概览、指标、趋势，服务器详情的概览与指标，重复嵌入相同指标组件。
- `metric-settings.ts` 使用资源 ID、策略组 ID 输入；目录、采集包与配置中直接暴露 Canonical、Revision、JSON 等内部表达。
- 服务器现有列表已有 CPU、内存、磁盘、网络、状态、质量、新鲜度等多列，不能直接把新核心表的所有列继续追加。

## 3. 三类资源统一使用一张列表

删除独立核心指标区域，核心指标直接并入对应资源行。全量未配置也保留资源列表，不能因缺少指标隐藏资源。

```text
数据库管理                                      [添加实例]
全部 5  健康 1  警告 0  异常 4  未知 0
[搜索名称、地址] [类型] [版本] [采集状态]  [刷新] [列设置]
─────────────────────────────────────────────────────────
实例   类型   版本   地址       健康   运行时长   容量   采集   操作
名称   MySQL  9.6.0  host:port  状态   值/状态    值     时间   ⋯
─────────────────────────────────────────────────────────
显示范围 / 筛选结果                                分页
```

该线框中的数量沿用截图，仅用于布局说明；实施时全部来自真实数据。

- 状态统计为紧凑筛选条，不另加一排大卡片；搜索与筛选区允许按视口自然换行。
- 名称作为详情入口；常用“测试连接”是否外露按实际操作频率确定。编辑、采集配置、删除进入更多菜单，删除保留确认和危险色。
- 健康筛选与采集状态筛选相互独立。显示“筛选结果 2 / 5”和清除入口，移除“未启用筛选”。
- 列设置只控制可见性与用户显示顺序，不修改产品指标定义或采集配置；提供恢复默认。
- 默认稳定排序；刷新保留筛选、排序、页码、滚动位置与已展开内容，不因状态变化突然重排行。

### 推荐默认列

| 页面 | 默认列 | 次要信息及可选列 |
| --- | --- | --- |
| 数据库 | 实例、数据库类型、数据库版本、连接地址、健康、运行时长、容量、采集状态/最近成功时间、操作 | 健康分、所属主机可选；QPS、连接数仅在已有可靠数据时提供 |
| 网络设备 | 设备、设备类型、型号、系统版本、管理地址、站点、设备状态、接口摘要、采集状态/最近成功时间、操作 | 厂商、备份状态可选；流量细节进入接口页 |
| 服务器 | 主机、操作系统类型、系统版本、连接状态、CPU、内存、磁盘、网络速率、采集状态/最近成功时间、操作 | 地址可作副行；环境/标签可筛选；网络错误、质量详情、挂载点明细按需展开 |

- 类型、型号、版本均为独立结构化字段，不拼接到名称中；对应列默认显示，不能为压缩宽度自动合并。
- 数据库提供类型、版本筛选；网络设备提供设备类型、型号、系统版本筛选；服务器提供操作系统类型、系统版本筛选。服务器硬件型号若已有可靠数据，可作为独立可选列与筛选项，不与操作系统类型混用。
- 筛选支持组合条件；版本选项随类型范围收敛，网络型号选项可随厂商/设备类型收敛，已有条件失效时明确提示。缺失值显示“未知”并可筛选，不从资源名称猜测。
- 选项及数量基于用户有权限的完整资源范围，不能仅取当前分页；实施前核对列表接口字段和筛选支持。空间不足时将部分筛选收进“更多筛选”，表格内部横向滚动，独立列语义保持不变。

### 指标摘要规则

- 数据库运行时长格式为“12 天 3 小时”；容量区分已用空间与总容量，不混用标签。
- 网络接口摘要写“已观测接口：在线 18 / 20”，明确分母来自观测范围。只对管理状态启用且运行状态异常的接口计入异常；若缺少管理状态，展示运行状态分布，不推断故障。
- 服务器磁盘建议显示“最高使用率及挂载点”，全部挂载点进入详情。需要后端确认 used/size 同维度且同窗口后计算，不把不同挂载点或重复文件系统直接相加。
- 网络列展示入/出速率及明确接口范围。缺少有效连续采样时显示“等待速率计算”；不把累计字节数当速率，不默认叠加物理接口和虚拟接口。
- CPU、内存或其他旧数据若尚未完成新口径迁移，保留明确的来源说明与时间；不得静默回退并伪装成新指标。
- 多维指标在列表只给有明确定义的摘要；无合适摘要时显示“查看 N 个接口/挂载点”，不在单元格内展开全部序列。

## 4. 状态与数据可信度

必须区分资源健康、采集状态、数据质量。采集未配置不等于数据库故障；连接成功也不足以证明全部指标健康。健康分只在已有有效评估依据时显示，无依据使用“未评估”，不能替换为 0。

| 情况 | 列表表达 | 后续入口 |
| --- | --- | --- |
| 数据有效 | 数值 + 单位；正常质量不重复贴多枚徽章 | 查看趋势/来源 |
| 未配置 | 未配置 | 有权限时进入采集配置 |
| 已停用 | 已停用 | 查看配置 |
| 不支持 | 不支持 | 展示原因和适用条件 |
| 采集权限不足 | 权限不足 | 查看所需权限；不展示未授权数据 |
| 能力尚未确认 | 待验证 | 查看能力或试采 |
| 临时失败 | 采集失败，可显示有权限的上次值并标记其时间 | 重试/查看失败原因 |
| 数据过期或部分缺失 | 上次值 + 已过期/数据不完整 | 查看采集记录 |
| 查询失败 | 指标加载失败 | 仅重试该行，不改变健康结论 |
| 无查看权限或资源失效 | 无权限/资源不可用 | 清除此前缓存结果 |

“最近更新”不可混用请求时间、最近尝试时间与最近成功采集时间。列表默认后者；详细面板展示三者。时间显示相对时间并可查看完整时间与时区。

## 5. 资源详情页分工

统一头部：资源名称、地址、类型、连接/健康状态、采集提示及主要操作。统一时间范围与刷新入口；不同标签页有明确职责。

| 页面区域 | 内容 |
| --- | --- |
| 概览 | 资源身份、关键指标摘要、当前异常及操作入口，不重复完整指标表 |
| 指标与趋势 | 指标选择、时间范围、趋势图、维度选择及质量说明；数据库原“指标/趋势”合为一个入口 |
| 采集配置 | 当前有效配置、编辑、预检、试采、发布、应用状态 |
| 专项标签 | 数据库保留会话/慢查询等；网络保留接口/关系/备份；服务器保留进程/服务/日志等 |

旧路由和书签继续定位到等价标签。旧版数据仍有必要时放在显式“兼容数据”入口，显示来源与限制，不在每个标签重复一整套新旧页面。

指标与趋势页：默认使用中文名称，ID 可复制；数据点展示值、单位与采集时间。维度、覆盖率、精确/估算、来源、质量原因在可点击详情中查看，不仅依靠 hover 或原始 JSON title。无效区间保留断点，不补零或连成正常趋势。

## 6. 指标相关页面

保留现有导航骨架，统一“指标管理”下的四类入口：指标目录、采集包、采集策略、兼容指标。资源详情里的“采集配置”复用同一配置组件。

### 指标目录

- 顶部提供名称/ID 搜索、资源类型、标准/扩展筛选。
- 主列为名称、适用资源、单位、指标类型、来源；语义版本为可选列。
- 详情展示含义、维度、允许的聚合、适用条件和版本。使用“标准指标/扩展指标”替代 Canonical/Extension；计数器标为“累计计数”。
- 产品固定定义只读，明确修改入口属于旧版兼容指标还是策略配置，避免用户以为调整模板会改变指标定义。

### 采集包

- 列表展示名称、版本、适用资源/条件；版本摘要和权限要求进入详情。
- 详情分为“包含指标、所需权限、推荐配置、版本信息”，替代默认 JSON 长块。
- 版本选择保留同 ID 升级和原有覆盖值规则。原始 JSON 仅放在高级诊断折叠区。

### 采集策略

- 用“资源策略 / 策略组”页签分开任务，避免上下两套表单并列。
- 资源选择使用名称、地址、类型可搜索列表，保留 ID 作为次要信息。
- 策略组使用可选择的名称/ID 列表；若后端暂不提供枚举，标为接口依赖，不虚构可选项。
- 每个参数显示有效值与来源，例如“60 秒 · 继承策略组”，覆盖时明确标识“本资源覆盖”。
- 策略组发布先展示影响资源数量与逻辑读取估算变化；只有接口支持时才提供逐资源明细。

### 资源采集配置

```text
资源身份    [已应用 / 等待应用 / 应用失败]
当前发布版本 8    当前应用版本 7

基础配置：采集包、版本、策略组、采集开关、采集间隔
高级配置（折叠）：超时、过期阈值、并发、行数与序列上限
指标配置表：名称 | 能力 | 有效状态 | 来源 | 继承/启用/停用

1 编辑配置 → 2 预检与影响 → 3 试采 → 4 发布并查看应用状态
```

- 时间字段使用秒/分钟输入，按原精度转换，不能因格式化改变配置。
- “有界试采”改为“试采”，说明“限制执行时间与读取量，不写入正式指标”。保留后端安全限制。
- 试采结果先展示成功/部分成功/失败、样本及原因；JSON 置于高级信息。
- 发布成功表达为“已发布，等待应用”；只有权威应用状态确认后才显示“已生效”。
- 修改配置使旧预检和试采结果失效；409 冲突要求重新加载、核对差异。按钮门槛服从后端契约，不能仅凭试采对象存在显示验证通过。
- 最近采集记录以可读状态、开始时间、耗时和失败原因呈现；错误码与请求标识可复制，且脱敏。
- 无管理权限保留只读配置；加载过程中不提前显示“无权限”。离开未保存配置时提示。

## 7. 交互与视觉规范

- 使用现有蓝色 `--accent`、字号、图标和设计 token，不另造紫色主按钮。
- 资源管理保持紧凑表格。移除重条纹、重复卡片边框和大面积留白；数字右对齐并使用等宽数字，名称左对齐。
- 优先复用 `app-data-table`、`app-card`、`app-badge`、`app-form-field`、`app-dialog`、共享按钮样式、Toast 和 skeleton。
- 同类指标单元格与状态展示至少被三页复用，应提取公共渲染和数据状态逻辑；避免重新创建包办所有资源差异的巨大组件。
- 1440/1920 宽度下默认列表以可读为先；窄屏减少次要列、允许表格内部横向滚动，禁止页面整体被撑宽。名称与主要操作保持可达。
- 菜单、筛选、质量详情支持键盘操作和可见焦点，不能仅以颜色区分异常。深浅主题均检查对比度。

## 8. 数据依赖与实施顺序

| 阶段 | 内容 | 边界/依赖 |
| --- | --- | --- |
| P0：统一资源列表 | 合并三页核心指标、精简单元格、统一空值/错误与操作列 | 先使用现有查询接口；分页内有界并发、逐行更新、过时响应丢弃；刷新不重跑昂贵采集 |
| P1：重整详情页 | 概览摘要、指标趋势、采集配置职责分离 | 复用既有图表；确认维度、时间窗口和新旧数据来源，保留旧链接映射 |
| P1：采集配置易用性 | 中文状态、基础/高级字段、预检试采与应用状态 | 保留发布权限、版本冲突和后端校验 |
| P2：管理入口完善 | 目录/采集包详情、资源和策略组选择、列偏好 | 检查现有搜索/枚举接口；缺失接口单独列为必要配套工作 |

接口核对项：指标中文名称映射、最近成功采集时间、接口管理状态、同窗口挂载点统计、策略组枚举、应用状态查询。当前 UI 可呈现的字段优先实施；缺失的数据不可用猜测或默认 0 补齐。

批量指标查询属于性能备选：先用可见页有界查询证明体验；只有确有必要时再新增批量接口，并保留逐资源鉴权和部分失败语义。不在 UI 优化中顺带重写采集引擎。

## 9. 验收清单

1. 三个管理页均只有一张资源主表，核心指标按资源 ID 正确合并，不按名称或数组位置关联。
2. 未配置、失败、过期、部分缺失、无权限资源都不会被隐藏；有效 0 与无值明确区分。
3. 资源健康与采集状态分别筛选，失败查询不改写健康结论，无依据不显示 0 分。
4. 单行查询失败不阻塞其他行；切换筛选/页码后旧请求不能覆盖当前页面。
5. 多接口/挂载点摘要遵循明确口径；累计值不当速率，未知接口不计为健康。
6. 点击指标能到对应资源和指标详情，并保留时间范围；返回列表恢复上下文。
7. 配置修改后必须重新验证；只读、试采失败、发布等待、应用失败、版本冲突均有可操作反馈。
8. 默认界面不要求用户输入内部资源 ID，不直接铺陈 JSON 和英文内部状态。
9. 1440、1920 与 375 宽度，深浅主题、键盘导航、空列表和多维长文本场景通过检查。
10. 实施时运行相关组件状态测试、三个列表及配置发布流程的浏览器验证，再执行受影响模块门禁；本方案未执行这些测试，不宣称已通过。
11. 三类资源的类型/型号、版本按上述定义独立成列并默认显示；组合筛选、未知值筛选和跨页结果一致，字段不并入名称副行。
