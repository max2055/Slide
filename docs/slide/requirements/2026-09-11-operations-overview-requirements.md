版本：v1.0  
日期：2026-09-11  
用途：交接给开发者实施，可独立阅读，无需依赖原讨论。  
范围决策：采用方案 B「专业视图重组」，同期纳入方案 C 的「风险 → 关联资源 → 只读诊断 → 查看证据」路径。完整 AI 运维驾驶舱不属于本期。

## 1. 产品目标与用户

Slide 当前定位是 AI 原生基础运维助手，覆盖数据库、服务器和网络设备，提供跨资源监控、告警、关联影响分析、只读诊断和审计能力。

主要用户为 DBA、服务器运维、网络运维及值班人员。总览需要帮助用户完成四件事：

1. 判断当前范围内哪些资源需要优先关注。
2. 区分已观测的运行异常、告警和采集缺口。
3. 定位具体资源，查看关联对象及支撑证据。
4. 按需发起只读诊断，查看真实结果，并返回原工作位置。

四个入口保留在现有 `/dashboard` 页面：**综合态势、数据库、服务器、网络设备**。「综合态势」替代原「全部资源」的可见名称，仍对应全部有权查看的资源。侧边栏继续使用「运维总览」，不新增平级业务模块。

## 4. 通用信息结构与交互

### 4.1 页面骨架

```text
运维总览                              数据时间 / 刷新
[综合态势] [数据库] [服务器] [网络设备]
[当前视图筛选条件]
[核心指标 1] [核心指标 2] [核心指标 3] [核心指标 4]
[风险队列：约 2/3 宽度] [健康 / 关联摘要：约 1/3]
[当前视图的专业图表或指标区]
[资源明细与证据 / 诊断入口]
```

- 默认综合态势；桌面下四张核心卡一行，中等宽度 2×2，小屏单列，不出现孤立第五或第七张卡。
- 在 1280×720 窗口首屏必须看到完整核心指标及风险队列首条，不要求所有明细首屏展示。
- 侧边栏维持现有布局；主体自适应可用宽度，长名称不能撑宽页面。
- 图表容器不强制与长风险列表等高；单一状态条使用紧凑面板。

### 4.2 范围和导航

- Tab 范围控制 KPI、风险、告警、健康分布、质量提示、图表与资源明细。
- 数据库提供引擎筛选；服务器和网络设备提供资源搜索。搜索、引擎筛选组成页面资源范围，所有范围内模块同步更新。
- 点击 KPI 或健康条对资源明细增加状态筛选，不反向改变顶部基准统计；明确显示已选筛选标签并可清除。
- 容量图的实例与时间选择仅作用于该图，标明局部筛选，不假装改变实时快照。
- Tab、页面筛选和图表时间范围可通过 URL 恢复；非法参数回到安全默认值。资源详情返回时恢复范围及原列表位置。
- 点击资源名称打开对应类型的实际详情，禁止仅打开未筛选列表。诊断入口预选 `{type, id}`。
- 从综合态势可查看本次风险相关的跨类型资源。专业视图的关联区允许展示跨类型对象，但必须标明「关联资源」，不能计入该视图 KPI。
- 不提供当前系统尚无可靠字段支持的环境、机房、业务系统等筛选器。

### 4.3 刷新与加载

- 本期默认手动刷新，不新增周期性 AI 调用或自动轮询全页。
- 首次加载使用布局匹配的 skeleton；刷新保留上次成功结果和更新时间，显示刷新中。
- 各模块分别处理失败，局部失败不清空整页、不把错误值改成 0。
- 快速切换 Tab 或筛选时，取消或忽略过期响应，不能让旧请求覆盖新视图。
- 历史图表按需加载；不为所有资源逐一请求证据或发起诊断。新增排行如需读取多个资源，应采用有界批量读取或已有服务端聚合。

## 5. 数据语义与统计口径

### 5.1 核心 KPI

| 视图 | 卡 1 | 卡 2 | 卡 3 | 卡 4 |
| --- | --- | --- | --- | --- |
| 综合态势 | 纳管资源 | 异常资源 | 未解决告警 | 采集异常资源 |
| 数据库 | 数据库实例 | 异常实例 | 未解决告警 | 采集覆盖率 |
| 服务器 | 服务器 | 不可用服务器 | 未解决告警 | 采集覆盖率 |
| 网络设备 | 网络设备 | 不可达设备 | 未解决告警 | 采集覆盖率 |

- 纳管数量：当前用户有权查看、符合页面范围的去重资源数，资源键为 `{type}:{id}`。
- 异常资源：具有可解释运行异常或未解决告警的去重资源数。同一资源多个告警只计一个异常资源。仅缺数据不计作已证实运行异常。
- 不可用/不可达：来自对应资源的明确运行状态或有效可达性观测；不由采集请求失败推导。
- 未解决告警：沿用后端的告警生命周期语义，已确认但未解决的告警仍计入。按告警唯一 ID 去重，不把分页长度、资源关联次数或聚合事件数当成告警总量。
- 采集异常资源：过期、缺失或质量异常的资源去重数量；说明具体分布。
- 采集覆盖率：当前范围 `fresh` 资源数 / 纳管资源数，旁注「最近观测有效 X/Y」。它只表示资源级近期观测覆盖，不表示所有指标齐全。质量降级或部分指标缺失另行提示。
- 分母为零显示「— / 尚未纳管」，不得显示 100%。接口失败显示不可用，不能显示 0。
- 指标级覆盖显示「有效 X/Y」，Y 为当前范围内支持该指标的资源数；不支持的资源单列说明。支持范围未知时只显示有效资源数，不编造分母。

若现有查询有记录上限、采样或截断，必须返回或呈现不完整标志。不能把有界样本数标成全量准确统计；确实只能得到下界时显示「至少 N」及原因。

### 5.2 运行状态与采集状态

两组状态不能复用同一个颜色计算函数：

| 维度 | 可见状态 | 规则 |
| --- | --- | --- |
| 运行 | 正常、异常、不可用/不可达、未知 | 必须对应实际字段和证据；配置启用 `active` 不能自动等价于运行健康 |
| 采集 | 有效、已过期、无数据、采集失败 | 来自观测时间、有效期和采集结果 |
| 指标能力/质量 | 支持、不支持、部分可用、无效、未知 | 不能把不支持转成 0、离线或正常 |

- 过期数据可展示为「上次状态：……」，但不能作为当前健康的唯一证明。
- 采集异常仍进入风险队列，原因写为「采集数据过期」「采集失败」等，不能消失在未知状态里。
- 健康分布采用互斥的正常、异常、不可用、未知分类，每个资源只计一次；明确不可用优先于异常。专业用词可调整为不可达。
- 无告警不等于健康；未知值不默认归入正常。
- 不凭前端自行发明统一 CPU/温度告警阈值。存在已配置阈值时可引用并说明，否则只显示实际数值和排行。

### 5.3 时间、聚合与影响

- 页面刷新时间、资源最后观测时间、诊断生成时间分开显示；后端 `collectedAt` 不代表所有数据刚刚产生。
- 相对时间可悬停查看绝对时间与时区；超过一天显示真实日期/天数，不使用「今日汇总」。未来时间和无效时间显示时间异常/未知。
- CPU、内存、磁盘等使用率汇总必须标明聚合方式；现有摘要中的数值类使用率为资源均值，不能标为最大值。
- 现有连接数与 QPS 摘要采用求和，仅在可比口径下展示，并标明覆盖范围；不同引擎语义不可比时按引擎分组。
- 不使用当前摘要的单个 `device_reachability` 数值推导全网可达率；应从各资源状态或有效观测逐项计算。
- `impactScope` 当前是关系另一端的去重资源集合，不是已确认故障传播证据。默认文案为「关联 N 个资源／潜在影响」，不宣称「导致 N 个资源故障」。
- 零条关系且查询成功显示「未建立关系」；查询失败显示「关联信息不可用」；无权限不泄露关联对象名称或数量。

## 6. 四个视图详细需求

### 6.1 综合态势

**目标：先看需要处理什么，再看涉及哪些资源。**

1. 四张 KPI 按第 5 节展示；健康/未知数量进入状态面板，不再堆叠七张卡。
2. 主区域为风险队列，默认展示前 5 项，提供「查看全部」和总量/不完整提示。
3. 风险排序依次考虑：有依据的运行不可用或严重告警、其他运行异常或告警、仅采集异常；同级按告警严重程度、已知关联资源数、告警数、稳定资源键排序。不能凭空生成风险评分。
4. 风险行显示资源类型图标、名称、明确原因、运行状态、采集状态、最近观测时间及关联数量；名称为空时使用「服务器 #123」等兜底。
5. 行内操作为「查看资源」「查看证据」「只读诊断」；不把整行点击和多个按钮做成冲突的交互。
6. 右侧健康分布为数据库、服务器、网络设备三行横向堆叠条，带图例、数量和点击筛选能力。
7. 选中风险后可展开关联摘要，展示已知关系与证据入口。不选中时显示引导，不后台发起分析。
8. 采集异常摘要提供有效、过期、缺失/失败、质量缺口说明，按需展开，避免占据整屏。
9. 底部资源明细默认异常优先，提供搜索、分页和清除筛选。
10. 数据库类型与容量图移出综合态势；不新增无数据支撑的跨资源总性能曲线。

### 6.2 数据库

**目标：识别具体实例的运行、性能和容量问题。**

1. 顶部引擎筛选列出实际纳管引擎及数量，不只支持最初的四类数据库。
2. 风险队列仅显示当前数据库范围的运行、告警和采集异常。
3. 容量趋势作为主要图表，保留现有实例选择、24h/7d/30d、自定义起止日期能力；自定义日期通过「自定义」展开，提供明确应用动作及日期校验。
4. 容量图展示已用容量、单位、采样时间和覆盖范围；历史缺口断线，不补零或插值伪装观测。没有总容量时不展示剩余量或耗尽时间。
5. 数据库类型采用降序横向条形图，直接标数量和占比；点击类型与页面引擎筛选一致。只有一种引擎时可紧凑显示，避免巨大单色饼图。
6. 专业指标固定选择 CPU、内存、磁盘、连接数、QPS 中实际可用且口径可比的项目。具备资源级明细时提供指标切换与 Top 5 实例排行；不同时堆叠五张大图。
7. 明细列：实例名称、引擎、运行状态、采集状态、未解决告警、最近观测、操作。资源/主机关系通过展开区查看。
8. 排行和容量项可直达具体实例的对应详情；本期不新建 SQL 分析或执行能力。

### 6.3 服务器

**目标：区分主机不可用、资源压力和观测缺口。**

1. 仅展示当前服务器范围的告警和统计，不残留数据库最近告警。
2. 专业指标区使用 CPU、内存、磁盘使用率切换排行，同一指标使用一致量程；显示主机名称、值、观测时间和有效覆盖。
3. 1 分钟负载可作为辅助指标，但缺少 CPU 核数时不得直接用于跨规格主机的压力排名或标注过载。
4. 选中服务器后，可在已有历史能力支持下查看该主机的指标趋势，不在总览同时绘制所有主机曲线。
5. 关联摘要展示其数据库和其他已知关系，不将“部署于同一主机”自动解释为故障影响。
6. 明细列：主机名称/可辨识地址、运行状态、CPU、内存、磁盘、采集状态、未解决告警、最近观测、操作。缺少指标显示原因。
7. 不可用但没有告警的主机仍必须进入风险队列。

### 6.4 网络设备

**目标：识别不可达设备、观测缺口及已支持的设备指标。**

1. 可达性摘要基于逐设备状态，显示可达、不可达、未知数量。
2. 专业指标区可切换已支持的 CPU、内存、温度，展示资源排行及单位，不支持项显示具体原因。
3. 不支持华为厂商指标时，可达性及其他受支持内容仍能使用；不能把整个视图判为失败，也不能假装该指标为 0。
4. 有现成备份读取接口时展示最近配置备份时间、成功/失败状态和详情入口；没有时按第 8 节降级，不新建备份系统。
5. 明细列：设备名称/地址、型号（已有时）、可达状态、采集状态、未解决告警、最近观测、操作。备份状态为具备数据后的附加列。
6. 本期不展示未采集的端口流量、带宽利用率、丢包率和自动拓扑。
7. 未纳管设备时用整体引导态替代七张零值卡和空白图表：「尚未纳管网络设备」＋说明＋有权限时的纳管入口；无权限时仅提供查看权限说明。

## 7. 本期 AI 与证据路径

### 7.1 用户路径

```text
风险队列 / 资源明细
  ├─ 查看资源 → 对应类型与 ID 的详情 → 返回原总览
  └─ 查看证据 → 预选资源的跨资源诊断页面
                 ├─ 查看事实、推论、假设及缺口
                 ├─ 获取关联证据 → 关联对象 → 返回原对象
                 └─ 主动发起只读 Agent 诊断 → 状态 → 真实结果与证据入口
```

复用现有跨资源诊断页面，允许对预选、返回、状态和结果展示作必要修改；不要求在总览重建完整诊断工作台。

### 7.2 行为要求

- 「查看证据」进入 `/resource-diagnosis?resourceType=...&resourceId=...` 对应选择，不自动提交 Agent 请求。
- 「只读诊断」从总览进入预选诊断页面，由用户点击明确的「开始只读诊断」按钮提交；导航与提交不可隐式捆绑。
- 获取关联诊断包使用既有能力；没有调用或返回不足时说明关联证据尚未获取，不宣称没有关联。
- 复用原有身份、资源授权、`ai:manage` 及对应后端授权机制，不为页面方便放宽权限。
- 工具能力必须保持只读业务边界；诊断可创建分析记录和证据记录，但不能执行运维变更。上线前核实实际调度/工具限制，不能仅以提示词作为只读保证。
- 未配置模型、Agent 不可用、无诊断权限时，资源和证据浏览仍可用；诊断入口显示明确原因及允许的下一步。
- 提交中禁用重复操作。返回 `analysisId` 后展示真实任务 ID，并复用既有状态或历史读取能力。
- `202/queued` 表示受理，不表示完成；`200/cached` 表示复用记录，也不保证该记录已成功完成，必须读取实际状态。
- 展示提交中、已受理/运行中、完成、失败及状态暂不可用。客户端等待超时显示「等待超时，任务状态待确认」，不能擅自把后端任务改判失败。
- 状态检查离开页面后停止；不能形成无限请求或多份并行轮询。返回页面可按 ID 恢复查询。
- 完成后展示分析对象、生成时间、摘要、证据/详情入口。无摘要但有原始结果时显示结果可查看，不伪造自然语言结论。
- 事实、推论、假设分开；已有关联关系不代表因果；没有可靠 Evidence ID 关联的历史结果标明「历史诊断上下文」，不能包装成已验证证据。
- 保留证据原始观测时间、有效期、来源、质量、缺口和截断提示。读取或刷新不能让旧证据看起来重新有效。
- 不在总览保留无上下文的全局「AI 分析总数」主卡，不新增默认自动生成的全局 AI 摘要。

## 8. 数据能力清单与降级规则

### 8.1 已确认的复用入口

下表确认的是源码能力，返回字段、权限和运行状态仍需实施者验证。不得把建议字段当成现成契约。

| 数据/操作 | 已存在入口 | 使用边界 |
| --- | --- | --- |
| 可访问资源 | `GET /api/resources` | 当前用户范围 |
| 总览 | `GET /api/resources/overview` | 资源状态、观测时间、质量、告警与关系摘要；确认记录上限及准确性 |
| 指标摘要 | `GET /api/resources/metrics/summary` | 均值/总量摘要，不是资源排行或历史序列 |
| 单资源观测 | `GET /api/resources/:type/:id/observations` | 支持指标和 limit 参数；不能仅凭接口名称认为支持完整历史窗口 |
| 数据库列表与容量 | `GET /api/database/instances`、`GET /api/dashboard/capacity-trend` | 复用现有筛选和时间能力 |
| 告警 | `GET /api/alerts` | 核对分页、资源关联和生命周期；现有总览仅筛未确认记录不满足本需求 |
| 证据 | `GET /api/resources/:type/:id/evidence` | 可能采集并持久化有界证据；不是零成本静态读取，不用于全资源后台轮询 |
| 关联诊断包 | `POST /api/resources/:type/:id/diagnose` | 既有关联与诊断证据能力 |
| Agent 诊断 | `POST /api/resources/:type/:id/diagnose-agent` | 返回 analysisId 和 queued/cached；需继续查询真实结果 |

### 8.2 条件能力的明确取舍

| 能力 | 首选实现 | 数据条件不足时的本期交付 |
| --- | --- | --- |
| 实例/主机/设备 Top 5 排行 | 从现有资源级有效观测做有界批量读取与排序 | 展示现有摘要，明确「平均/合计」和覆盖，保留资源详情入口；不伪造排行 |
| 服务器及网络设备历史趋势 | 复用已存在且支持对应窗口、单位、维度的历史接口 | 仅显示最新有效观测及时间，移除不可工作的趋势控件 |
| 配置备份摘要 | 复用当前设备备份记录 | 移除总览备份模块，保留设备详情入口；不以空列表暗示从未备份 |
| 全量准确告警统计 | 复用准确 count/聚合及资源关联 | 必要时补齐最小查询；只能读部分时明确下界或不完整，不能展示伪精确总量 |
| 关联资源展示 | 复用已有关系摘要及关联诊断包 | 无关系、未获取、失败、无权限分别说明；不新增自动拓扑发现 |
| 诊断结果跟踪 | 复用实际分析状态/结果接口，按 resource 和 analysisId 定位 | 如缺三类资源适配，属于核心路径所需的有界补齐，不能只返回 JSON 受理结果就算完成 |

实施开始时将每项记录为「可复用／需有界适配／采用约定降级」，附接口、样例字段与原因。采用上表约定降级无需重新讨论完整方案；交付必须明确列出，不能声称交付了未实现的排行或趋势。新增采集器或持久化体系不在此授权内。

## 10. 空态、失败与权限

| 状态 | 必须呈现的内容 |
| --- | --- |
| 未纳管 | 明确尚无该类资源；有权限时提供实际纳管入口 |
| 筛选无匹配 | 显示当前筛选无结果和清除筛选，不显示未纳管 |
| 有资源但无观测 | 保留资源身份，指标显示未知及采集入口/原因 |
| 全部已知正常 | 才可显示「当前观测未发现异常」，同时保留采集覆盖说明 |
| 只有采集缺口 | 显示采集风险，不能显示系统正常 |
| 部分接口失败 | 就近错误提示、最后成功时间及模块重试；其他模块继续可用 |
| 无权限 | 不泄露对象详情；403 显示无权限，不伪装成零资源 |
| 指标不支持 | 明确不支持及已知原因，不显示为故障或 0 |
| 数据截断 | 显示不完整范围，不给出全量结论 |
| 诊断失败/不可用 | 保留资源上下文、任务 ID（若已创建）、错误和重试/查看状态入口 |

内部错误码翻译为可理解的中文，详情可保留原始码与 request ID；页面不展示凭证、完整内部错误栈或未脱敏内容。
