  <action>
    Create `servers-page.ts` in the views directory as an `@customElement('servers-page')` LitElement class following the same patterns as `instances-db.ts`.

    **Template structure:**
    - Page header with title "服务器管理" and "+ 添加服务器" button (using app-components shared CSS classes: `.page`, `.page__header`, `.page__title`, `.page__actions`, `.btn-primary`)
    - Main content area: `<app-data-table>` (reuse existing `app-data-table` component from Phase 120) with columns:
      - Status badge column — uses `<app-badge>` with variant per status (green/online, grey/offline, red/error, amber/unreachable)
      - Host column — primary display name per D-02 (show host, with label as secondary below in lighter color if label exists)
      - Label column — optional alias (empty dash if not set)
      - OS type badge — `<app-badge>` with neutral variant, text like "CentOS", "Ubuntu"
      - Port column — TCP port number
      - Actions column — edit icon + delete icon + rotate-key icon
    - Empty state: `<app-empty-state>` with message "暂无服务器" when list is empty

    **Data loading:**
    - `_loadServers(): Promise<void>` — fetch GET /api/servers (will be 401 if not logged in; alert and redirect if so)
    - Call in `firstUpdated()` and after any mutation (create/update/delete/rotate-key)
    - Handle 401 by alerting user to log in

    **Add/Edit dialog (uses `<app-dialog>`):**
    
    Single-column form layout (per D-03), inside `<app-dialog>` with header "添加服务器" / "编辑服务器":
    
    Fields (per D-01, D-05):
    1. IP/主机名 — `<app-form-field>` with input, required, placeholder "192.168.1.100"
    2. SSH端口 — `<app-form-field>` with input type="number", default 22, placeholder "22"
    3. 标签 (可选) — `<app-form-field>` with input, placeholder "例如：生产环境主服务器"
    4. 操作系统 — `<app-form-field>` with select dropdown: CentOS / Ubuntu / Debian / RHEL / Other (per D-01 fixed list)
    5. SSH认证方式 — radio/select: 密码 / 密钥 pair
    6. SSH用户名 — `<app-form-field>` with input, required, default "root"
    7. 密码 或 SSH私钥 — conditional field based on credential type:
       - If password: `<app-form-field>` with input type="password"
       - If key: `<app-form-field>` with textarea for private key content
    8. Inline credential note: small text "凭据将使用 AES-256-CBC 加密存储" (informational, per D-07)

    **Buttons in footer (per D-08):**
    左侧（flex-start）: 无
    右侧（flex-end）in the footer:
    - "测试连接" button (secondary) — calls POST /api/servers/test-connection with form data
    - "保存" button (primary) — calls POST /api/servers or PUT /api/servers/:id
    
    **Test connection flow (per D-09):**
    - Click "测试连接" → show spinner/disabled state on button → POST /api/servers/test-connection
    - Success: show `<app-toast>` with success message "连接成功：{host}:{port}"
    - Failure: show `<app-toast>` with error message "连接失败：{error details}"
    - Simple pass/fail per D-09 — no detailed SSH banner display

    **Delete confirmation:**
    - When delete icon clicked, show confirm dialog: "确定要删除服务器 {host} 吗？此操作不可撤销。"
    - On confirm: DELETE /api/servers/:id → reload list
    - On success toast: "服务器已删除"

    **Key rotation:**
    - Rotate-key icon opens a small `<app-dialog>` with:
      - New credential type selector (password/key pair)
      - New credential username input
      - New credential value (password input or key textarea)
      - Confirm button: POST /api/servers/:id/rotate-key
      - On success toast: "密钥已轮换"

    **Error handling:**
    - API errors show via app-toast with error message
    - Network failures catch and display generic "网络错误"
    - 401 responses show alert prompting login, then redirect to login

    **Styling:**
    - Use existing `.page`, `.page__header`, `.page__title`, `.page__actions` CSS classes
    - Form field layout uses `<app-form-field>` component (do NOT hand-roll form field CSS)
    - Status badges use `<app-badge>` with appropriate variants
    - No custom CSS in component's static styles unless absolutely necessary — match instances-db.ts style approach

    **State properties:**
    - `_servers: ServerRow[]` — list of servers from API
    - `_loading: boolean` — loading state
    - `_showDialog: boolean` — dialog visibility
    - `_editingId: number | null` — null for add, number for edit
    - `_form: { host, port, label, os_type, credential_type, credential_username, credential_value }` — form fields
    - `_testingConnection: boolean` — test connection loading state

    **Import pattern:**
    ```
    import { html, nothing } from 'lit';
    import { customElement, state } from 'lit/decorators.js';
    import { t } from '../../i18n/index.ts';
    import '../components/app-dialog.ts';
    import '../components/app-form-field.ts';
    import '../components/app-data-table.ts';
    import '../components/app-badge.ts';
    import '../components/app-empty-state.ts';
    import '../components/app-toast-container.ts';
    ```

    Draw explicit design decisions from Phase 120's UI patterns (the "添加数据库实例弹窗" section of ROADMAP that details the polished dialog pattern).

    }

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> API | Frontend sends CRUD/test-connection/rotate-key requests to backend |
| browser -> navigation | Permission-gated tab visibility via TAB_REQUIRED_PERMISSIONS |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-124-08 | Spoofing | servers-page API calls | medium | mitigate | Backend requirePermission('servers:view'/'servers:manage') already enforces; frontend hints via TAB_REQUIRED_PERMISSIONS but backend is the authoritative guard |
| T-124-09 | Information Disclosure | server list response | low | accept | Server list shows host, port, label, os_type, status — all non-sensitive metadata. credential_encrypted is stripped by backend before sending |
| T-124-10 | Tampering | test-connection API body | low | accept | Test connection is stateless and non-persistent; no data written. Errors show generic messages, not credential content |
</threat_model>
