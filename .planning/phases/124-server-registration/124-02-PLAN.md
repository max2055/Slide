<action>

**Create** `frontend/src/app/ui/views/servers-page.ts` following the exact patterns in `instances-db.ts`.

The component is a LitElement with `@customElement("servers-page")`.

**Imports (mirror instances-db.ts):**
- `LitElement, html, css, nothing` from `lit`
- `sharedBtnStyles` from `../../styles/shared-btn-styles.ts`
- `customElement, state` from `lit/decorators.js`
- `app-dialog`, `app-form-field` from `../components/`
- `icons` from `../../../icons.js`
- `authFetch` from `../../../api/index.js`
- `showToast` from `../components/app-toast-container.js`

**Data model:**
```ts
interface Server {
  id: number;
  host: string;
  port: number;
  label: string | null;
  os_type: string;
  username: string;
  status: 'online' | 'offline' | 'error' | 'unreachable';
  last_check_at: string | null;
  created_at: string;
}
```

**State:**
- `servers: Server[]` -- loaded from GET /api/servers
- `showAddDialog`, `showEditDialog`, `showDeleteDialog` booleans
- `formData` with fields: host, port (default 22), label, os_type (default 'Other'), username, password, private_key
- `editingServer: Server | null`
- `deletingServer: Server | null`
- `testStatus: 'idle' | 'testing' | 'success' | 'error'`, `testMessage: string`
- `isSubmitting: boolean`

**Methods (mirror instances-db.ts):**
1. `connectedCallback()` -- fetch servers via `authFetch('/api/servers')`
2. `_fetchServers()` -- GET /api/servers, set this.servers
3. `_addServer()` -- reset formData, set showAddDialog = true
4. `_editServer(server)` -- pre-fill formData (leave password/private_key empty), set editingServer, showEditDialog = true
5. `_deleteServer(server)` -- set deletingServer, showDeleteDialog = true
6. `_handleDelete()` -- DELETE /api/servers/:id, refresh list
7. `_updateForm(field, value)` -- update formData
8. `_handleTestConnection()` -- POST /api/servers/test-connection with formData fields (host, port, username, password, private_key), show success/error per D-09
9. `_handleSubmit(isEdit)` -- POST or PUT /api/servers/:id, close dialog, refresh list

**Render methods:**

1. `render()` -- main page layout matching instances-db.ts card structure:
   - Card header with title "服务器管理" + "添加服务器" button
   - Toolbar/search (optional minimal implementation)
   - `_renderTable()` or empty state

2. `_renderTable()` -- table matching instances-db.ts pattern with columns:
   - Host/IP (bold, primary display per D-02)
   - Label (optional alias, shown in muted text if exists)
   - Port
   - OS Type (app-badge per UI-05)
   - Status (app-badge with color: online=green, offline=gray, error=red, unreachable=orange)
   - Last check time (formatted relative time or "从未")
   - Actions (edit/delete icon buttons)

3. `_renderAddDialog()` / `_renderEditDialog()` -- app-dialog with single-column form per D-03:
   - `app-form-field` for each field:
     - Host/IP (required, input)
     - SSH Port (number, default 22, per D-01)
     - Label (optional, input, per D-01)
     - OS Type (select dropdown: CentOS/Ubuntu/Debian/RHEL/Other, per D-01)
     - Username (required, input)
     - Password (password input, per D-05. In edit mode: label says "留空不修改")
     - Private Key (textarea, per D-05. In edit mode: leave empty to retain)
   - Test connection result display: icon + message (check-circle for success, x-circle for error)
   - Footer with buttons: test connection, cancel, submit. Test connection button must be near submit per D-08.
   - Test connection result is simple pass/fail per D-09 (no detailed server output).

4. `_renderDeleteDialog()` -- confirmation dialog matching instances-db.ts pattern

5. `_renderEmptyState()` -- when no servers, show app-empty-state with "暂无服务器" message (per UI-05)

**Styling:**
- Use existing CSS patterns from instances-db.ts (card, card-header, table styles, form-row, form-input, form-select, form-textarea)
- Reuse sharedBtnStyles
- Do NOT add new component-level global styles

All API calls use `authFetch` from `../../../api/index.js`.
