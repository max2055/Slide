  <name>Task 2: Create server-database-service.ts with CRUD, SSH test, and key rotation</name>
  <files>apps/db-ops-api/src/server-database-service.ts</files>
  <action>
    Create `server-database-service.ts` as a singleton class following the exact pattern from `instance-database-service.ts`. Import from `./db-connection`:
    - `dbConnection` (for getPool/isConnected)
    - `encryptData` (AES-256-CBC encryption per D-07)
    - `decryptData` (AES-256-CBC decryption per D-07)

    **Server Interface (type ServerRow):**
    Fields matching the SQL columns: id, host, port, label, os_type, credential_type, credential_encrypted, host_key_fingerprint, status, last_check_at, collection_enabled, created_at, updated_at

    **Methods (follow instance-database-service.ts patterns exactly):**

    1. `getAllServers()` — SELECT * FROM servers ORDER BY host. Returns all fields including credential_encrypted (caller decides if decryption needed).

    2. `getServerById(id)` — SELECT * FROM servers WHERE id = ?. Returns null if not found.

    3. `createServer(data)` — Accepts: { host, port?, label?, os_type, credential_type, credential_username, credential_value, created_by? }. Steps:
       - Encrypt credentials: `encryptData(JSON.stringify({username: data.credential_username, [credential_type === 'password' ? 'password' : 'privateKey']: data.credential_value}))`
       - INSERT INTO servers (...) VALUES (...)
       - Return { success, serverId }
       - Check for duplicate host+port first (like instance-database-service.ts checks physical dup at line 181)

    4. `updateServer(id, data)` — Dynamic UPDATE building (like instance-database-service.ts line 248-300). If credential_username or credential_value provided, re-encrypt and update credential_encrypted+credential_type. Skip null/undefined fields.

    5. `deleteServer(id)` — DELETE FROM servers WHERE id = ?. Return { success, error? }.

    6. `testConnection(host, port, credentialType, credentialValue, username)` — SSH connection test using ssh2 Client:
       - Import `{ Client } from 'ssh2'`
       - Return new Promise((resolve, reject)):
         ```
         const client = new Client();
         client.on('ready', () => { client.end(); resolve({ success: true, message: `连接成功：${host}:${port}` }); });
         client.on('error', (err) => { resolve({ success: false, message: `连接失败：${err.message}` }); });
         const connectConfig: any = { host, port, username, readyTimeout: 10000, hostVerifier: () => true };
         if (credentialType === 'password') { connectConfig.password = credentialValue; }
         else { connectConfig.privateKey = credentialValue; }
         client.connect(connectConfig);
         ```
       - `hostVerifier: () => true` per planning guidance ("Phase 125 will fix")
       - Follow the same try-catch + return-object pattern as instance-database-service.ts testConnection (line 326-425)

    7. `rotateKey(serverId, newCredentialType, newCredentialUsername, newCredentialValue)`:
       - Validate server exists via getServerById
       - Re-encrypt credentials with encryptData(JSON.stringify(...))
       - UPDATE credential_encrypted, credential_type, host_key_fingerprint = NULL (fingerprint reset on key change)
       - Return { success, message }
       - This is the SRV-06 key rotation endpoint implementation

    8. `getDecryptedCredentials(serverId)` — Returns { username, password/privateKey } after decryptData + JSON.parse. Used internally by testConnection route.

    **Security considerations:**
    - credential_encrypted stores JSON of the form {"username":"...","password":"..."} or {"username":"...","privateKey":"..."}
    - NEVER log decrypted credentials
    - The credential_encrypted TEXT field holds AES-256-CBC output (iv:hex format matching encryptData in db-connection.ts)
    - collection_enabled defaults to 1 (per D-04)
    - Updated_at is handled by ON UPDATE CURRENT_TIMESTAMP in the DDL
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> API | Unauthenticated/unauthorized requests to server CRUD endpoints |
| API -> Database | SQL injection via server CRUD parameters |
| API -> SSH target | Sidecar connection to user-specified SSH targets |
| API -> credential storage | Plaintext credentials before/during encryption |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-124-01 | Spoofing | POST /api/servers | high | mitigate | requirePermission('servers:manage') on all mutating routes; verifyToken on all routes |
| T-124-02 | Information Disclosure | GET /api/servers/:id | high | mitigate | Strip credential_encrypted from GET response; never send encrypted blob to frontend |
| T-124-03 | Information Disclosure | test-connection route | medium | mitigate | Never log decrypted credentials; error messages show only host:port not credential content |
| T-124-04 | Tampering | credential_encrypted storage | medium | mitigate | AES-256-CBC via existing encryptData; stored as JSON {username, password/privateKey} — re-encrypt on every update |
| T-124-05 | Tampering | rotation | low | mitigate | rotate-key clears host_key_fingerprint; resets to no known fingerprint |
| T-124-06 | Spoofing | server CRUD body | low | mitigate | validate required fields with strictBody pattern; check duplicate host+port before insert |
| T-124-07 | Elevation of Privilege | role-permission seeds | medium | accept | servers:manage assigned to admin + dba roles only (not developer/analyst/viewer/auditor); intent of Phase 124 is admin/DBA only |
| T-124-SC | Tampering | npm install (ssh2) | high | mitigate | Run `npm install ssh2@^1.17` and `npm install --save-dev @types/ssh2@^1.15`. Verify via npmjs.com/package/ssh2 before install. |
</threat_model>
