<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client->API | Unauthenticated HTTP requests crossing into Fastify route handlers |
| API->Database | SQL queries to servers table containing encrypted credentials |
| API->SSH Server | ssh2 Client making outbound SSH connections to managed servers |
| API->encryption | Credential data flow through encryptData/decryptData |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-124-01 | Tampering | SSH credential_encrypted storage | high | mitigate | encryptData AES-256-CBC before write, decryptData only in memory at connection time. credential_encrypted column stores only the encrypted blob, never plaintext. |
| T-124-02 | Information Disclosure | SSH test-connection endpoint | medium | mitigate | Error messages expose connection failure details but NOT the credential value itself. Use try/catch to return generic {success: false, error: message} without leaking password/privateKey. |
| T-124-03 | Spoofing | Server registration | medium | mitigate | requirePermission('server:manage') on all write routes, verifyToken on all routes. Unauthenticated GET /api/servers returns 401. |
| T-124-04 | Tampering | hostVerifier bypass | low | accept | Phase 124 uses hostVerifier: () => true for test-connection only. Phase 125 will implement proper host key verification. Documented as known gap. |
| T-124-05 | Denial of Service | Outbound SSH connections | low | accept | test-connection creates ephemeral ssh2 Client per invocation. No pooling yet — acceptable for Phase 124 scope. Phase 125 SshSessionPool will add connection reuse. |
</threat_model>
