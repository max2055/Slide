**Step 1: Install ssh2.** Run `cd apps/db-ops-api && npm install ssh2` to add the ssh2 package to dependencies. The `Client` from ssh2 is used for the one-shot connection test (no pooling or keepalive needed in this phase).

**Step 2: Create migration file** `apps/db-ops-api/sql/migrations/019_add_servers_table.sql`.

The table definition matches the architecture from RESEARCH.md and user decisions D-01/D-02/D-07:

- `id` INT UNSIGNED AUTO_INCREMENT PRIMARY KEY
- `host` VARCHAR(255) NOT NULL -- IP or hostname; serves as display name per D-02
- `port` INT NOT NULL DEFAULT 22 -- SSH port per D-01
- `label` VARCHAR(100) DEFAULT NULL -- optional alias per D-01
- `os_type` ENUM('CentOS','Ubuntu','Debian','RHEL','Other') NOT NULL DEFAULT 'Other' -- per D-01
- `username` VARCHAR(100) NOT NULL -- SSH login user
- `password_encrypted` VARCHAR(500) DEFAULT NULL -- AES-256-CBC encrypted password per D-07
- `private_key_encrypted` TEXT DEFAULT NULL -- AES-256-CBC encrypted private key content
- `host_key_fingerprint` VARCHAR(256) DEFAULT NULL -- SSH host key fingerprint (stored on save after test)
- `status` ENUM('online','offline','error','unreachable') NOT NULL DEFAULT 'offline'
- `last_check_at` DATETIME DEFAULT NULL
- `created_by` INT UNSIGNED DEFAULT NULL
- `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
- `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

Primary key on id, indexes on host and status. Use InnoDB with utf8mb4_unicode_ci.

**Step 3: Create** `apps/db-ops-api/src/server-database-service.ts` following the pattern in `instance-database-service.ts`.

The service file exports:
- `Server` interface matching the table columns (omit password_encrypted and private_key_encrypted in read responses for security; expose decrypted values only via explicit methods)
- `default` export of a singleton `ServerDatabaseService` class

Methods (each pattern-matched from instance-database-service.ts):

1. `getPool()` / `isConnected()` -- same wrapper pattern (imports `dbConnection`)
2. `getAllServers()` -- SELECT all, ORDER BY created_at DESC. Returns all columns.
3. `getServerById(id)` -- SELECT WHERE id = ?
4. `createServer(data)` -- INSERT with encrypted credentials. Encrypt password_encrypted and private_key_encrypted via `encryptData()` from `./db-connection`. Duplicate check by host+port combo (same pattern as instance create).
5. `updateServer(id, data)` -- UPDATE with conditional field patching. Only re-encrypt password_encrypted/private_key_encrypted when non-empty value provided. Do not clear if omitted.
6. `deleteServer(id)` -- DELETE WHERE id = ?
7. `testConnection(config)` -- one-shot SSH connection using imported `Client` from `ssh2`:
   - Accepts { host, port, username, password?, privateKey? }
   - Creates `new Client()`, calls `.connect()` with provided config
   - On `ready` event: stores host key from `this._hostKey`, then `.end()`
   - On `error` event: returns `{ success: false, error: message }`
   - On successful connect+disconnect: returns `{ success: true, fingerprint: sha256 hash }`
   - Use `hostHash: 'sha256'` and `hostVerifier: (key) => true` for now (strict verification deferred to Phase 125 SshSessionPool). Store the returned fingerprint on save.
   - Timeout: `readyTimeout: 10000` (10s).
8. `rotateKey(id, data)` -- re-encrypts and updates { password, private_key } in-place. Returns `{ success: boolean, error?: string }`.

All methods use pool.execute() for parameterized queries.
