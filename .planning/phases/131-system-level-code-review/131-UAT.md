# Phase 131 UAT 与运行时审计

## 当前测试状态

[测试已完成：已复现生产阻断问题]

## 运行环境

- 保留了占用 3000/28888 端口的现有后端进程。
- 使用现有 Vite 前端；未终止任何应用进程。
- 实时 MySQL 中有 63 张表、5 个活跃数据库实例、1 台服务器、10 个 Cron 任务和 30 个告警模板。
- 除使用零行 UPDATE（`WHERE 1=0`）证明审批绕过外，API 测试均为非破坏性操作。
- 浏览器操作均为只读；未提交任何 CRUD、删除、审批或通知操作。

## UAT 用例

### 1. 后端健康接口

**预期：** `GET /api/health` 返回 200。

**实际：** HTTP 200，`status: ok`。

**结果：** 通过

### 2. 受保护 API 拒绝无 token 请求

**预期：** 实例 API 拒绝未认证请求。

**实际：** HTTP 401。

**结果：** 通过

### 3. 登录成功/失败行为

**预期：** 错误密码被拒绝；配置的管理员和普通用户凭据可以认证。

**实际：** 错误密码返回 401；两个账户均返回 200 和 token。

**结果：** 通过

### 4. Chat 会话隔离

**预期：** 普通用户只能列出或读取自己拥有或显式共享给自己的会话。

**实际：** 管理员和普通用户均看到相同的 9 个会话。普通用户提交管理员会话 key 后，读取到了其中 2 条消息。

**结果：** 失败 — CR-02

### 5. SQL 写操作审批边界

**预期：** 直接执行接口拒绝 DML，并要求创建审批请求。

**实际：** `UPDATE database_instances SET name=name WHERE 1=0` 返回 HTTP 200 / `success:true`；未创建审批记录。

**结果：** 失败 — CR-03

### 6. 健康中心真实性

**预期：** 有四个 critical 活跃实例时，不得报告 100% 健康或全部就绪。

**实际：**

- `/api/health/consistency`：9 项通过、0 项警告、0 项失败、1 项 deferred；五个准备度布尔值均为 true。
- `/api/database/instances`：5 个活跃实例；1 个 healthy，4 个 critical 且分数为 0。
- 浏览器显示“健康度 100%”和“全部就绪”。

**结果：** 失败 — HI-05

### 7. 实例凭据响应

**预期：** 列表/详情 DTO 绝不包含凭据材料。

**实际：** 已认证列表为全部五个实例返回 `password_encrypted`。该路由只要求有效 token。

**结果：** 失败 — HI-13

### 8. SQL 审批/审计关联

**预期：** 获批执行会将 SQL 历史关联到对应审批请求。

**实际：** 实时数据库有 55 条 SQL 历史记录和 11 条审批记录；关联 `approval_request_id` 的历史记录为 0。业务代码中没有使用 `rollback_info`。

**结果：** 失败 — ME-07

### 9. 服务器指标注册表与数据对齐

**预期：** 每个已采集的服务器指标都能作为服务器目标指标定义被发现。

**实际：** `server_metrics` 中有当前的 `cpu_usage`、`memory_usage`、`disk_usage_*`、负载和 uptime 时序数据；查询服务器指标定义返回零行。

**结果：** 失败 — HI-07

### 10. 服务器 RCA 持久化准备度

**预期：** 服务器告警可以创建归属于该服务器的 AI 分析。

**实际：** 实时 `ai_analysis.instance_id` 为 NOT NULL 且没有 `server_id`；服务会拒绝没有 `instance_id` 的告警。

**结果：** 失败 — HI-08

### 11. 定时报表配置

**预期：** 报表页面提供调度配置 CRUD，到期任务会生成配置的报表。

**实际：** 页面只显示手动生成和历史记录；未渲染调度入口、列表或对话框。实时 `report_configs` 数量为 0。种子 Cron 任务没有报表配置或报表生成工具。

**结果：** 失败 — HI-09

### 12. 浏览器关键页面遍历

**预期：** Cron、Chat、服务器、告警、SQL 控制台、审批和 Agents 页面均能加载主要控件。

**实际：** 七个路由均已加载。可见控件包括 Cron 创建/运行、服务器添加/详情、告警确认/AI、SQL 执行/解释/历史和审批标签页。

**结果：** 通过，但存在缺口

### 13. Agent 管理控件

**预期：** 可见标签页/控件应当可用，不支持时则应隐藏。

**实际：** Files/Tools/Skills/Cron 标签页可见，但只显示“DirectAdapter 模式下此功能暂不可用”。Overview 的模型、fallback 和 reload 回调为空。

**结果：** 失败 — ME-05

### 14. 浏览器控制台/网络行为

**预期：** 已认证路径遍历期间没有非预期错误。

**实际：** 登录后没有新的路由特定 4xx/5xx。首次加载登录页时，branding/preferences 请求产生 401，并在认证前发出了 preference PUT。

**结果：** 部分通过 — LO-01

### 15. 通知渠道保密性

**预期：** 渠道列表只返回已脱敏的公开配置。

**实际：** 实时渠道响应包含完整配置和 webhook URL；代码直接返回存储对象。

**结果：** 失败 — HI-11

### 16. 重复启动后端

**预期：** 无法取得服务端口的进程不得执行迁移、任务或状态修改。

**实际：** 重复进程先初始化数据库/迁移、健康检查/重连/清理/采集器/Cron，最后才因端口被占用退出。

**结果：** 失败 — HI-12

### 17. 延期的 Cron 事件

**预期：** 判断 STATE 中“全部已禁用”是否仍是当前状态。

**实际：** 3 个任务已启用、7 个已禁用；日志有 1,157 次成功和 20 次错误。历史“全部已禁用”状态已不再存在。

**结果：** 诊断通过；应关闭或重新分类该规划项

### 18. 延期的 capacity/null metrics 事件

**预期：** 用当前数据解释延期事项。

**实际：** Capacity 有 16,682 行和当前数据。四个数据库服务不可达且仍为 critical；目标不存在时采集器行为符合预期，但健康聚合掩盖了该状态。

**结果：** 部分通过 — 环境问题并存 HI-05 应用缺陷

### 19. 前端类型检查与生产构建

**预期：** 两者均通过。

**实际：** 类型检查通过。构建通过；主 JS 为 2,776.59 kB（gzip 后 827.21 kB），并产生 chunk 警告。

**结果：** 通过，但有性能警告
