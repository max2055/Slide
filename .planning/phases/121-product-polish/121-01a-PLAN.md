  db_reachable: boolean;

  timestamp: string;  // ISO string
  summary: { pass: number; warn: number; fail: number; deferred: number; total: number; };

}

  <action>
    Create `apps/db-ops-api/src/consistency-checker.ts` as a TypeScript module at the package root level (same directory as db-connection.ts).

    Export types:
    - `CheckStatus` — union `'pass' | 'warn' | 'fail' | 'deferred'`
    - `ConsistencyCheck` — interface with fields: `id: string`, `label: string`, `category: string`, `status: CheckStatus`, `severity: 'info' | 'minor' | 'major' | 'critical'`, `summary: string`, `details?: unknown`, `recommendation?: string`
    - `ReadinessStatus` — interface with fields: `db_connected: boolean`, `db_reachable: boolean`, `llm_provider: boolean`, `cron_running: boolean`, `agent_engine: boolean`
    - `ConsistencyResponse` — interface with fields: `timestamp: string`, `summary: { pass: number; warn: number; fail: number; deferred: number; total: number; }`, `checks: ConsistencyCheck[]`, `readiness: ReadinessStatus`

    Export a class `ConsistencyChecker` with:
    - Method `async runAllChecks(): Promise<ConsistencyResponse>` — calls each check method sequentially (NOT parallel, to avoid pooling 10 connections), calls `_checkReadiness()` separately, aggregates results into a ConsistencyResponse with ISO timestamp and summary counts.
    - Method `async _checkSafe(fn: () => Promise<ConsistencyCheck>, id: string, label: string, category: string): Promise<ConsistencyCheck>` — wraps each check in try-catch. If the fn throws, returns `{ id, label, category, status: 'fail', severity: 'critical', summary: `检查异常: ${err.message}`, recommendation: '请检查服务日志和数据库连接' }`.
    - 10 individual check methods, each returning `Promise<ConsistencyCheck>`:

    1. `_checkInstanceCountMatch()` — Query `SELECT COUNT(*) as active_count, SUM(data_size_gb) as total_data_size FROM database_instances WHERE status = 'active'`. If active_count > 0: pass, summary shows count. If 0: fail severity=critical, recommendation "请添加数据库实例".
    
    2. `_checkCapacitySumMatch()` — Query active instances data total, then query `SELECT COALESCE(SUM(total_size_gb), 0) as cap_total FROM capacity_history ch1 WHERE recorded_at = (SELECT MAX(recorded_at) FROM capacity_history ch2 WHERE ch2.instance_id = ch1.instance_id)`. Compare database_instances SUM vs capacity_history SUM. If difference < 1GB: pass. If diff between 1-100GB: warn with delta. If diff > 100GB or no capacity data: fail.
    
    3. `_checkMetricsFreshness()` — Query `SELECT MAX(recorded_at) as latest FROM metrics_history`. If latest is within 10 minutes: pass. Within 1 hour: warn. Older than 1 hour: fail. If no data at all: fail severity=info (new system).
    
    4. `_checkAlertRuleMetricRefs()` — Query `SELECT ar.id, ar.name, ar.metric_name FROM alert_rules ar LEFT JOIN metric_definitions md ON ar.metric_name = md.id WHERE md.id IS NULL AND ar.metric_name IS NOT NULL`. If none: pass. If some: fail with count and recommendation "请修复告警规则中引用的无效指标名".
    
    5. `_checkEventMemberStatusMatch()` — Query `SELECT ae.id, ae.event_id, ae.title, ae.status as event_status, COUNT(aem.id) as open_members FROM alert_events ae JOIN alert_event_members aem ON ae.id = aem.event_id JOIN alerts a ON aem.alert_id = a.id WHERE ae.status IN ('resolved', 'closed') AND a.status NOT IN ('resolved', 'closed') GROUP BY ae.id, ae.event_id, ae.title, ae.status`. If none: pass. If found: fail with count and recommendation "请检查已关闭事件中仍有 open 状态的成员告警".
    
    6. `_checkRbacOrphanRecords()` — Two queries: (a) `SELECT rp.id FROM role_permissions rp LEFT JOIN roles r ON rp.role_id = r.id WHERE r.id IS NULL` (b) `SELECT ur.id FROM user_roles ur LEFT JOIN users u ON ur.user_id = u.id WHERE u.id IS NULL`. Combine both counts. If no orphans: pass. If orphans exist: warn with count (orphans don't break anything but indicate cleanup needed), recommendation "请清理悬空的 role_permissions 或 user_roles 记录".
    
    7. `_checkCronHungJobs()` — Two queries: (a) `SELECT cj.id, cj.name, cjl.started_at FROM cron_jobs cj JOIN cron_job_logs cjl ON cj.id = cjl.job_id AND cjl.status = 'running' WHERE cj.enabled = TRUE AND cjl.started_at < NOW() - INTERVAL 10 MINUTE` (b) `SELECT id, name, next_run_at FROM cron_jobs WHERE enabled = TRUE AND next_run_at IS NOT NULL AND next_run_at < NOW()`. If none: pass. If hung jobs: fail with count and recommendation "请检查 cron 执行器或手动复位悬挂任务". If stalled jobs: warn with count.
    
    8. `_checkChatSessionStats()` — Query `SELECT cs.id, cs.session_id, cs.message_count as stored_count, COUNT(cm.id) as actual_count, cs.last_message_at as stored_last_msg, MAX(cm.created_at) as actual_last_msg FROM chat_sessions cs LEFT JOIN chat_messages cm ON cs.session_id = cm.session_id GROUP BY cs.id, cs.session_id, cs.message_count, cs.last_message_at`. Count sessions where stored_count != actual_count OR stored_last_msg != actual_last_msg. If no mismatch: pass. If mismatches: warn with count.
    
    9. `_checkApprovalEventIntegrity()` — Two queries: (a) `SELECT ar.id FROM approval_requests ar WHERE ar.status IN ('approved', 'executed') AND NOT EXISTS (SELECT 1 FROM approval_events ae WHERE ae.request_id = ar.id AND ae.event_type IN ('approved', 'executed'))` (b) `SELECT id, created_at FROM approval_requests WHERE status = 'pending' AND created_at < NOW() - INTERVAL 7 DAY`. If no issues: pass. If orphaned approvals: fail with count. If old pending: warn with count.
    
    10. `_checkNotificationDeferred()` — Hard-coded return: `{ id: 'notification_closure', label: '通知闭环完成性', category: 'notification', status: 'deferred', severity: 'info', summary: '通知闭环检查已推迟到下一 phase 实现', recommendation: '通知发送链路（钉钉/企微/飞鹰/webhook）需在后续 phase 完整实现' }`. Must NOT actually query any notification tables — no half-implementation.

    Method `async _checkReadiness(): Promise<ReadinessStatus>`:
    - `db_connected`: `dbConnection.isConnected()`
    - `db_reachable`: true if `db_connected` AND pool queries work (try a `SELECT 1`), else false
    - `llm_provider`: query `SELECT id FROM llm_providers WHERE enabled = TRUE LIMIT 1`, true if count > 0
    - `cron_running`: query `SELECT id FROM cron_jobs WHERE enabled = TRUE LIMIT 1`, true if count > 0
    - `agent_engine`: attempt a TCP connect to the DirectAdapter WS port. Read AGENT_WS_URL from process.env (fallback: 'ws://127.0.0.1:28888/ws'), parse the host:port, use `net.createConnection()` with 2000ms timeout. resolve true on connect, false on error/timeout. Wrap in try-catch.

    Import `{ dbConnection }` from `'./db-connection'` (no .js extension, matching existing pattern).
    Import `* as net from 'net'` for the agent engine TCP check.

    Export singleton: `export const consistencyChecker = new ConsistencyChecker();` — matching the singleton pattern used by alertEventService, brandingConfigService, etc.
