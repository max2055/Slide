<task type="auto">
  <name>Task 1: 建立 ActorContext 与一致撤销语义</name>
  <files>apps/db-ops-api/sql/migrations/025_security_actor_context.sql, apps/db-ops-api/src/auth/actor-context.ts, apps/db-ops-api/src/auth-middleware.ts, apps/db-ops-api/src/auth-database-service.ts, apps/db-ops-api/src/adapter/direct-adapter.ts</files>
  <action>
    定义不可变 `ActorContext`，至少包含 userId、username、roles、permissions、sessionVersion、instanceScopes 和 requestId。JWT 只提供会话索引，服务端必须加载 active 用户、当前角色/权限和 session version；数据库读取失败、用户缺失/停用或版本不匹配均 fail-closed。refresh 先消费/轮换 refresh token，再签发带 session version 的 access token；角色、密码或状态变化时提升版本并撤销 refresh token。WS 握手调用同一服务，连接保存 ActorContext 并周期重验；重验失败关闭连接。migration 只增加必要的 session version/索引，不复制角色事实。
  </action>
  <verify><automated>pnpm --filter slide-api vitest run src/auth/security-boundaries.test.ts -t "actor|refresh|websocket"</automated></verify>
  <done>active 用户四条入口获得同一授权快照；inactive/deleted/stale/database-error fixture 在 REST、refresh 和 WS 均被拒绝。</done>

<threat_model>
| Threat | Boundary | Disposition |
|---|---|---|
| 伪造 JWT claims / WS userId | client -> REST/WS | 服务端重建 ActorContext，忽略客户端身份字段 |
| 跨用户 session IDOR | REST/WS -> chat DB | repository owner/share predicate + 双用户测试 |
| Prompt 诱导危险工具 | LLM -> tool handler | 确定性 PolicyDecision，默认拒绝且拒绝分支不可调用 handler |
| 用户停用后长连接继续执行 | auth DB -> WS | session version 与周期重验，失败主动断开 |
</threat_model>
