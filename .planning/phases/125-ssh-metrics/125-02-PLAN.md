    **Efficient loading:** Instead of N+1 queries, if the /api/servers endpoint can include latest metrics, modify the backend to include them. Alternatively, make a single batch metrics endpoint.

    Actually, create a new endpoint: `GET /api/servers/metrics/summary` that returns latest metrics for all servers in one query:
    ```sql
    SELECT sm.server_id, sm.metric_name, sm.metric_value, sm.recorded_at
    FROM server_metrics sm
    INNER JOIN (
      SELECT server_id, metric_name, MAX(recorded_at) AS max_time
      FROM server_metrics GROUP BY server_id, metric_name
    ) latest ON sm.server_id = latest.server_id AND sm.metric_name = latest.metric_name AND sm.recorded_at = latest.max_time
    ```
    Then the frontend fetches this in parallel with /api/servers and merges the data.
