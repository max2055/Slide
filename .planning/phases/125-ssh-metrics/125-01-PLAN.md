  <action>
    Create `ssh-session-pool.ts` as a singleton class:

    ```typescript
    import { Client } from 'ssh2';
    ```

    **Interface:**
    - `SshSession` — wrapper around ssh2 Client with { client: Client, host, port, lastUsed, inUse }
    - `SshSessionPool` — singleton with configurable pool options

    **Methods:**

    1. `getConnection(host, port, username, credentialType, credentialValue): Promise<Client>`:
       - Check pool for existing idle connection to same host:port
       - If found and connected (client._sock?.writable), return it
       - If stale/disconnected, remove and create new
       - Max 3 connections per server (respects MaxSessions)
       - Set keepaliveInterval: 60000, keepaliveCountMax: 3
       - readyTimeout: 10000
       - hostVerifier: () => true (Phase 125 doesn't fix host key — deferred)

    2. `releaseConnection(client: Client)`: Mark connection as idle for reuse

    3. `closeConnection(client: Client)`: End client and remove from pool

    4. `closeAll()`: End all connections and clear pool

    5. `execCommands(client: Client, commands: string[]): Promise<{stdout: string, stderr: string}[]>`:
       - Execute multiple commands sequentially on a single connection (COL-08)
       - Use `client.exec()` for each command
       - Return array of { stdout, stderr } results
       - 15s timeout per command

    6. `getPoolStats()`: Return { total, idle, active } counts

    **Security:**
    - Track inUse flag to prevent concurrent channel exhaustion
    - Clean up stale connections on every getConnection call
    - Log pool stats at debug level
  </action>

<task type="auto">
  <name>Task 3: Create ServerMetricProvider</name>
  <files>apps/db-ops-api/src/server-metric-provider.ts</files>
  <action>
    Create `server-metric-provider.ts` with metric definitions and parsers:

    **MetricDefinition interface:**
    ```typescript
    interface MetricDefinition {
      name: string;       // metric_name in server_metrics table
      command: string;    // SSH command to execute (Linux)
      parse: (stdout: string) => number | null;  // Parse output to numeric value
      osType: string;     // 'linux' (extendable)
    }
    ```

    **Linux commands and parsers:**

    1. `cpu_usage` — `top -bn1 | grep "Cpu(s)" | awk '{print $2+$4}'` → parse as float
    2. `memory_usage` — `free | grep Mem | awk '{print $3/$2 * 100.0}'` → parse as float
    3. `memory_used` — `free -b | grep Mem | awk '{print $3}'` → bytes
    4. `memory_total` — `free -b | grep Mem | awk '{print $2}'` → bytes
    5. `swap_usage` — `free | grep Swap | awk '{if($2>0) print $3/$2*100; else print 0}'` → float
    6. `disk_usage` — `df -P | awk 'NR>1 {print $6,$5}'` → per mount point, returns "mount usage%" pairs, provider returns average or full output parsed by collector
    7. `load_1min` — `cat /proc/loadavg | awk '{print $1}'` → float
    8. `load_5min` — `cat /proc/loadavg | awk '{print $2}'` → float
    9. `load_15min` — `cat /proc/loadavg | awk '{print $3}'` → float
    10. `uptime` — `cat /proc/uptime | awk '{print $1}'` → seconds as float

    **Disk detail commands (COL-02):**
    - `disk_detail` — `df -B1 | awk 'NR>1 {print $6,$2,$3,$4,int($5)}'` → per mount: mount_point, total_bytes, used_bytes, available_bytes, usage_pct
    - The collector stores each mount point as separate rows with metric_name `disk_usage_{mount}` (sanitized, e.g. `disk_usage_root`)

    **Method:**
    - `getDefinitions(osType: string): MetricDefinition[]` — returns commands for the given OS type
    - `parseMetric(name: string, stdout: string): number | null` — runs the parse function
    - `getAllCommands(osType: string): string[]` — returns commands for batch execution via SshSessionPool

    For now, only Linux commands are implemented. Other OS types return empty array.
  </action>

  <name>Task 4: Create ServerCollector</name>
  <files>apps/db-ops-api/src/server-collector.ts</files>
  <action>
    Create `server-collector.ts` as a class:

    ```typescript
    import SshSessionPool from './ssh-session-pool';
    import ServerMetricProvider from './server-metric-provider';
    import { ServerDatabaseService } from './server-database-service';
    import { dbConnection } from './db-connection';
    ```

    **Config (from environment or defaults):**
    - `collectionIntervalMs`: 300000 (5 minutes) — COL-06
    - `commandTimeoutMs`: 15000 (15 seconds) — COL-04
    - `maxFailuresBeforeUnreachable`: 3 — COL-05

    **Methods:**

    1. `start()`: Start the collection timer. On each tick:
       - Query all servers where collection_enabled=true
       - For each server: collect metrics via SSH
       - On success: insert rows into server_metrics, update status to 'online', reset failure count
       - On failure: increment failure count, if >= 3 set status to 'unreachable'
       - Track consecutive failures per server

    2. `stop()`: Clear the timer, close all SSH connections

    3. `collectServer(serverId)`: One-shot collection for a specific server. Used by the detail page refresh.

    **Collection flow (per server per tick):**
    1. Get server details (host, port, credential_type + decrypt credentials via getDecryptedCredentials)
    2. Get connection from SshSessionPool
    3. Execute all metric commands in batch via execCommands
    4. Parse each output via ServerMetricProvider
    5. INSERT each metric into server_metrics table as a separate row
    6. Handle disk_detail: store each mount point as separate rows
    7. Release connection back to pool
    8. On success: update servers.status='online'
    9. On error: increment failure_count in memory, update status to 'unreachable' when threshold reached

    **Metrics batch insert:**
    Use a single INSERT with multiple value rows for efficiency:
    `INSERT INTO server_metrics (server_id, metric_name, metric_value, recorded_at) VALUES (?, ?, ?, NOW()), ...`

    **Integration:**
    - Export singleton instance
    - Wire into monitor-collector.ts startup alongside the existing UnifiedCollector (add call in the init/start section)
