<task type="auto">
  <name>Task 2: 实现多方言 SQL 分类和只读策略</name>
  <files>apps/db-ops-api/src/sql-validator.ts, apps/db-ops-api/src/operations/sql-boundary.test.ts</files>
  <action>
    使用 node-sql-parser 的 AST 能力并为不完整支持的 Oracle/Dameng 语法采用明确 allowlist/fail-closed adapter。分类至少区分 read、write、ddl、transaction、session、procedure、unknown；处理注释、CTE、SELECT INTO/FOR UPDATE、EXPLAIN 包裹写入、多语句、delimiter 和 Unicode 空白。`/execute` 只允许单条 read，其他类型返回稳定 reason code 和 approval submission link，绝不依赖字符串前缀或正则作为最终判断。
  </action>
  <verify><automated>pnpm --filter slide-api vitest run src/operations/sql-boundary.test.ts</automated></verify>
  <done>MySQL/PostgreSQL/Oracle/Dameng fixture 的 read 与危险边界均有正反例，unknown 默认拒绝。</done>
</task>

<task type="auto">
  <name>Task 3: 将公开 SQL 路由接入 ActorContext 与 Operation</name>
  <files>apps/db-ops-api/src/sql-executor.ts, apps/db-ops-api/server.ts, apps/db-ops-api/src/operations/sql-boundary.test.ts</files>
  <action>
    所有 SQL API 先校验 ActorContext、实例 scope 和实例访问模式，再创建/复用 Operation。read 路径写 queued/running/terminal 事件；write/ddl 返回 waiting_approval 并复用 Operation 创建审批，禁止另一路径直接执行。对 statement/params/result 做大小限制与审计脱敏；HTTP 状态和前端可用 reason code 区分 denied、needs_approval、execution_failed。
  </action>
  <verify><automated>pnpm --filter slide-api vitest run src/operations/sql-boundary.test.ts -t "route"</automated></verify>
  <done>审计中的零行 UPDATE 复现改为明确拒绝/待审批，且目标数据库 spy 未收到 execute。</done>
</task>
</tasks>

<threat_model>
| Threat | Mitigation |
|---|---|
| parser bypass / stacked query | AST + 单语句 + unknown fail-closed |
| 伪造资源或审批 ID | ActorContext scope + server-side Operation relation |
| 重放提交 | actor-scoped idempotency unique key |
| 结果日志泄密 | 有界结构化审计与敏感字段过滤 |
</threat_model>
