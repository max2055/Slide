<task type="auto">
  <name>Task 2: 建立历史 baseline/repair 与运行时 invariant</name>
  <files>apps/db-ops-api/src/migrations/baseline.ts, apps/db-ops-api/src/migrations/invariants.ts, apps/db-ops-api/src/migrations/runner.ts</files>
  <action>
    为已有部署提供只读 inspect 和显式 baseline：逐 migration 检查代表性表/列/索引，只有完全匹配才写 baseline ledger；不通过 `IF EXISTS` 猜测成功。repair 只能标注经过人工确认的失败 migration 并保存操作者/理由。invariant 覆盖运行时关键表、FK、唯一约束和 Phase 132-139 新结构；错误输出缺失对象，不输出连接 secret。
  </action>
  <verify><automated>pnpm --filter slide-api vitest run tests/migration-runner.test.ts -t "baseline|repair|invariant"</automated></verify>
  <done>代表性旧 schema 可安全 baseline，不完整/漂移 schema 被拒绝并指出差异。</done>
</task>

<task type="auto">

| 固定初始账户 | 显式一次性 bootstrap，无默认 hash |
</threat_model>
