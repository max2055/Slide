<task type="auto">
  <name>Task 2: 建立真实终态、取消和失败传播</name>
  <files>packages/agent-core/src/types.ts, packages/agent-core/src/runner.ts, apps/db-ops-api/src/adapter/direct-adapter.ts, frontend/src/app/ui/app-chat.ts, frontend/src/app/ui/chat/run-lifecycle.ts</files>
  <action>
    AgentRunner 接收 AbortSignal，将 provider timeout、tool error、max iteration、用户取消映射到明确终态和 reason code。DirectAdapter 保存 `runId -> AbortController/owner/session/Operation`，abort 命令必须匹配连接 actor 和 session owner；完成后原子封存终态并清理 registry。前端 Stop 发送 runId，保持 cancelling，直到服务端 cancelled/其他终态；不再只清空输入。terminal event 使用 compare-and-set，杜绝 completed 后再 failed 或重复 toast。
  </action>
  <verify><automated>pnpm --filter agent-core vitest run src/__tests__/runner-lifecycle.test.ts &amp;&amp; pnpm --filter slide-api vitest run src/adapter/__tests__/protocol-v2.test.ts -t "terminal|cancel"</automated></verify>
  <done>五种终态都有 fixture；取消流式 provider 和工具时副作用停止或由 Operation 进入可恢复状态。</done>
</task>

<task type="auto">
  <name>Task 3: 持久幂等、附件传递与重连恢复</name>
  <files>apps/db-ops-api/src/adapter/direct-adapter.ts, frontend/src/app/ui/direct-gateway.ts, frontend/src/app/ui/app-chat.ts, apps/db-ops-api/src/adapter/__tests__/protocol-v2.test.ts, frontend/src/app/ui/direct-gateway.test.ts</files>
  <action>
